# Core Principle

### 认知原则

- 只回答是什么
- 少、准确、精要、目的明确、可验证
- 拒绝长篇大论、喋喋不休、无脑投喂，但也决不能省略关键信息


### 认知驱动开发的精髓
- 为系统 构建一个稳定一致、可扩展、可验证的结构
- DRY 原则。为设计文档，计划，原型设计，编码，bug修复提供全局统一的核心认知，作为唯一事实来源



### 为AI 构建的核心认知应当包括哪些

- 术语
  是全局术语和命名定义的唯一事实源

- 目标
  面向最终实现效果，概括性、总结性，清楚可验收

- 结构
  子系统职责划分、 模块职责划分
  可扩展性、面向接口、模块化、组件化

- 功能
  有哪些功能（带唯一编号）？

- 实体
  有哪些关键的实体（带唯一编号），含义是什么

- 属性
  实体有哪些属性（带唯一编号）：类型、唯一性、可编辑性、必填、默认值、长度/精度、判断作用等
  唯一性字段重点标注；定长字段特别关注（长度/填充/截断）

- 关系
  实体之间的关联关系（带唯一编号），写清依附、基数、唯一定位、约束方向

- 状态
  实体有哪些状态、状态是如何变化的（用 PlantUML 状态图表达）

- 界限
  约束是什么？覆盖全局可用/禁用条件、关系/属性/状态变化约束、异常边界

- 参考文档&引用
  完整无缺失

逐项检查，不能整维缺失：
术语与命名 ：完整无缺失
目标 ：是否清楚、可验证、可验收
结构 :系统、子系统、可扩展性、面向接口、模块化、组件化
功能 ：功能项完整，带唯一编号，可独立实现和验收
实体：关键实体清单，带唯一编号，含含义、存储位置/类型、角色/事实源地位
属性：属性归属到实体，带唯一编号，写清 类型、唯一性、可编辑性、必填、默认值、长度/精度、判断作用
关系 ：带唯一编号，写清依附、基数、唯一定位、约束方向
状态 ：状态集合、初始/中间/终态、迁移触发、禁止迁移、失败/拒绝/超时/终止，用 PlantUML 状态图表达
界限 ：全局可用条件、禁用条件、状态/关系/属性变化约束、异常边界
参考文档&引用：完整无缺失
