# 七维领域设计模版

## 使用方式

1. 复制「完整骨架」到新文件，放在 `_task/system-design/spec/domain/<上下文>/`，文件名带时间戳，例如 `领域设计-Content-v0.4.0-20261119-100000.md`。
2. 骨架中的相对路径按上述目标位置计算（`../../核心认知.md` 等）。文件放在别的位置时自行重数层级，交付前逐条验证能解析。
3. 先判断目的与边界，再按一→七顺序落笔。边界虽然排在第七，判断在动笔前完成。
4. 每维只写该维该回答的认知问题。定义、字段表、状态图从[核心认知](../../../../_task/system-design/spec/核心认知.md)取引用，并按骨架的「定义引用表」登记锚点。
5. 填完跑[七维要点](domain-essentials.md)的自问清单，未通过项标为待办，不隐藏。

开头的文档定位与结尾的待验证、依据是文档家具，不属于七维正文。

## 骨架之外的写作要求

每维的认知问题、判据和反模式只在 [SKILL.md](../SKILL.md) 与[七维要点](domain-essentials.md)维护，本模版不重复。

某维确实不适用时，写明理由并保留标题，不用空话填充。上游依据不足时标待确认并给拥有方。

## 编号约定

编号的含义只由核心认知定义，本模版不新增前缀。表中列出的编号一律引用，不重新定义或续编。

| 前缀 | 归属 | 出处 |
| --- | --- | --- |
| `SD-nn` | 子域类型 | 核心认知 §5.1.1 |
| `F-ID-nn` | 功能 | 核心认知 §6.1 |
| `E-ID-nn` / `V-ID-nn` | 实体、值对象 | 核心认知 §7 |
| `Q-ID-nn` | 查询结果 | 核心认知 §7.10 |
| `ID-Axx` / `PR-Axx` | 属性 | 核心认知 §7.2–7.3 |
| `REL-ID-nn` | 关系 | 核心认知 §8 |
| `EV-ID-nn` | 领域事件 | 核心认知 §7.11 |
| `ID-nn` | Identity 规则索引 | 核心认知 §10.2 |
| `SUP-nn` | 支撑域用例 | [支撑域领域设计](../../../../_task/system-design/spec/domain/supporting/领域设计-支撑域-v0.4.0-20261118-141904.md) §3；归属登记在支撑域稳定入口 |

新增其他前缀前，先在核心认知或该上下文的稳定 `README.md` 登记编号归属，再回写本表。
