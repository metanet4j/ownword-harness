# 高保真原型新增与修改

## 角色与依据

本技能负责方案确认与验收交付，设计执行继续使用 `baoyu-design`，实现检查使用 `react-spectrum`。

按[设计总指南](../../../standard/OwnWord设计与设计系统.md)加载核心认知、当前版本设计文档和绑定的 Spectrum S2；遵守目标目录的 AGENTS.md。设计规则、组件与验证范围引用现有规范，不在本技能重复定义。仅编写文档或技能、未改动原型时，不触发本流程。

两个页面的形式参考：

- [开工前方案页](http://127.0.0.1:4315/design-proposal-header-menu-20261021.html)：当前效果、拟议效果、必要备选与规格说明。
- [修改后对照页](http://127.0.0.1:4315/visual-review-v14.html)：改前与改后截图、版本依据、修改说明与审阅入口。

参考页只提供组织方式，具体页面内容与设计数值以本轮依据为准。参考服务不可用时，可读取对应 HTML 源文件；本轮交付仍须通过 HTTP 预览并验证。

## 1. 定义目标并保存基准

1. 确认本轮用户任务、受影响页面或区域、当前问题、目标效果和验收条件。已有明确结论直接沿用，缺口才询问。
2. 给验收项稳定编号，如 A1、A2；描述可观察的结果，关联页面、状态与必要操作。
3. 在修改目标原型前，通过 `agent-browser` 查看当前实现，保存受影响区域的真实截图；记录提交或版本、入口、样例数据、视口、语言、主题、操作步骤与页面状态。
4. 新功能尚无对应界面时，展示其所在页面的当前状态并注明“新增”，或明确标注“无改前界面”；不制作虚假的改前截图。

## 2. 先交付方案页，确认后实施

在当前原型项目中创建本轮独立 HTML 方案页，例如 `design-proposal-<主题>-<YYYYMMDD-HHmmss>.html`。复用项目字体、Token 和资产，以接近最终实现的布局、文案和组件状态展示效果。

方案页至少包含：

| 内容 | 要求 |
| --- | --- |
| 目标与范围 | 用户任务、当前问题、本轮涉及的页面或区域及设计依据。 |
| 当前与拟议效果 | 按区域展示真实当前截图与高保真提案，清楚标注；需要选择时给少量备选、推荐项及取舍。 |
| 交互与状态 | 展示本轮关键展开、选中、空、错误等状态及触发方式；静态示意标明交互说明。 |
| 规格与验收 | 写明影响结果的布局、字级、间距、组件与状态变化；列出编号验收项，完成设计总指南要求的自评。 |
| 审阅入口 | 当前原型、本轮方案的可访问链接；标注“待确认”及需要用户决定的内容。 |

用 `agent-browser` 打开方案页并查看截图，确认内容、字体、图片和布局正常后，再将 URL 交给用户确认。

**开工门禁：方案页可审阅且用户确认本轮目标、效果与范围后，才修改目标原型。** 确认前可完成取证、基准截图和独立方案页。已有本轮明确确认或用户明确授权直接执行既定方案时，记录授权范围并沿用；仍提供方案页，不重复索取许可。沉默、超时或代理自评不算确认。

保存已确认的方案版本、选定备选及会话中的确认依据，写入现有任务状态记录。实施中若目标、范围或关键效果需要变化，先更新方案页，说明差异，仅对新增或变化部分取得确认。

## 3. 按确认方案实施并验证

- 按验收编号实施，保持已确认方案及基准证据可追溯。
- 使用 `baoyu-design` 完成原型、预览和截图评审，使用 `react-spectrum` 检查受影响组件与交互；验证范围遵循[测试与验证](../../../standard/测试与验证-20260917-194638.md)及目标目录规则。
- 原型提交、版本递增和构建清单使用 [prototype-versioning](../prototype-versioning/SKILL.md)，按目标仓库提交。
- 采集同条件的改后真实截图；截图无法证明的行为通过实际操作验证，并记录结果。未检查项标注“未验证”或“待核实”。

## 4. 交付对照页用于验收

在当前原型项目中创建本轮 HTML 对照页，例如 `visual-review-<本轮标识>.html`。在现有审阅入口链接当前成果，保留历史方案和各轮原始截图；截图条件与原尺寸查看遵循设计总指南第 8.2 节。

对照页至少包含：

| 内容 | 要求 |
| --- | --- |
| 本轮摘要与依据 | 本轮目标、修改范围、改前及改后版本或提交、已确认方案链接。 |
| 前后对照 | 按受影响页面或区域展示同条件真实截图，标明改前、改后及差异；新增界面沿用第 1 节的标注。 |
| 目标核验 | 按 A1、A2 等逐项展示“已确认目标 → 实际结果 → 截图或操作证据 → 验证结论”。偏离方案处说明原因及确认依据。 |
| 操作验证 | 提供相关入口、状态准备与复现步骤，记录正常与相关边界场景的实际结果。 |
| 审阅入口与状态 | 当前原型、已确认方案、版本及证据链接；区分代理验证结果、未验证项和用户验收结论。 |

先通过 HTTP 打开对照页，检查截图可加载、前后标签与版本一致、链接有效、可查看原图，再向用户交付对照页 URL、原型 URL 和必要的验收步骤。

用户验收前将本轮原型标为“已实现并验证，待用户验收”，不能把代理验证写成人工通过。用户反馈对应到原验收编号；在已确认范围内修订、复核并更新对照页，涉及新目标时回到方案阶段。验收通过后，按实际结论更新现有任务状态。

## 交付检查

- [ ] 方案页已通过浏览器检查，目标、拟议效果与编号验收项可审阅。
- [ ] 修改目标原型前已有本轮明确确认或直接执行授权，依据可追溯。
- [ ] 改前证据在实施前保存，改后证据来自当前实际实现，采集条件可比较。
- [ ] 对照页逐项回应已确认目标，包含可用入口、证据与实际验证结果。
- [ ] 已交付对照页及验收步骤，用户验收状态按事实记录。
