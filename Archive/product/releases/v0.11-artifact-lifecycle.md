# v0.11 Identity Artifact 生命周期

状态：`planned`

阶段：第四阶段

依赖：[`v0.10`](./v0.10-artifact-resolve.md)。

事实依据：[`核心认知：持久化关系`](../core-cognition.md#持久化关系)、[`核心认知：持久化状态`](../core-cognition.md#持久化状态)、[`核心认知：全局约束`](../core-cognition.md#全局约束)。

展示依据：[`页面风格规范：Identity Artifact`](../visual-style.md#identity-artifact)、[`页面风格规范：交互与文案`](../visual-style.md#交互与文案)。

## 目标

完成多个 Artifact 的 Current、Historical、Not Used、Unavailable 生命周期，以及 1Sat Transfer 后的关联校验。

## 范围

- Artifact 列表与详情。
- 一个 Identity 拥有多个 Artifact。
- `Set as Current`、`Change Artifact`、`Remove Association`。
- 同一 BAP ID 同时最多一个 Current Artifact。
- Transfer 前重新调用 `getOrdinals` 获取新鲜 WalletOutput。
- 有 BEEF 时显式传入 Transfer；无可用 BEEF 时按核心认知规则失败并要求重新同步。
- Transfer 后更新 Current Outpoint，保留 Origin 和原始 Inscription ID。
- 当前所有权变化、进入大于 1 satoshi Output、Origin 变化和 Binding 失效。
- Current、Historical、Not Used、Unavailable 用户状态。
- 重新选择 Artifact、解绑、重试和异常恢复。

## 用户流程

### 更换 Current Artifact

```text
Artifacts
  -> select another Artifact
  -> Set as Current
  -> Wallet Confirmation when required
  -> Current updated
  -> previous Current Artifact becomes Historical
```

### Transfer

```text
Transfer Artifact
  -> refresh current WalletOutput
  -> include BEEF when available
  -> Wallet Confirmation
  -> broadcast
  -> resolve ownership and Origin
  -> update Outpoint or mark association unavailable
```

## 验收

- 一个 BAP ID 可展示多个 Artifact，但只能有一个 Current。
- Set as Current 不修改 Artifact 的 Inscription ID；只改变产品 Binding。
- Transfer 前不使用历史 Outpoint 作为唯一输入。
- Transfer 后 Current Outpoint 可变化；Origin 在同一有效 1Sat 链内保持定位作用。
- 进入大于 1 satoshi Output 后，旧 Artifact 显示 Unavailable，不静默沿用旧 Binding。
- 重新进入 1-satoshi Output 产生新 Origin 时，要求新的关联判断。
- owner、creator、签名者和 Binding 分开显示和校验。
- 异常页面说明发生了什么、影响什么、用户下一步怎么办。
- 交易状态、Artifact 状态、Binding 状态分开显示。

## 阻塞项

- Transfer 所需 WalletOutput、BEEF 和 ancestry 解析必须用当前 SDK 集成测试确认。
- Binding 的链上或数据库权威事实必须在生产实现前关闭。
- 所有权变化与 Origin 变化的 Indexer 事件模型待确认。

## 不在范围

- Marketplace、Collection、Royalty。
- Key Rotation、Attestation、Revocation。
- Reply、Repost、Message。
