# v0.8 Identity Lookup 与 Relationship

状态：`planned`

阶段：第二阶段

依赖：[`v0.7`](./v0.7-public-identity.md)。

事实依据：[`核心认知：功能`](../core-cognition.md#功能)、[`核心认知：持久化关系`](../core-cognition.md#持久化关系)、[`核心认知：全局约束`](../core-cognition.md#全局约束)。

协议依据：[`BitcoinSchema Social Schema`](../../../reference/schema-master/schema-master/docs/social_schema.md)。

展示依据：[`页面风格规范：组件体系`](../visual-style.md#组件体系)。

## 目标

开放用户侧精确 BAP ID 查找，并以查找结果作为建立 Identity Relationship 的入口。

## 范围

- Header 或 Relationship 页面提供 `Find an identity`。
- 只接受完整 BAP ID，精确解析已发布 Identity。
- 查找结果显示 Public Identity、BAP ID、Copy 和 Relationship 操作。
- Follow、Unfollow。
- Friend 建立；Friend 的安全通信公钥字段按协议生成，解除语义待确认。
- Relationship 列表、当前状态、交易 Proof。
- Relationship 永远持久化 `fromBapId + toBapId`。
- Inscription Number 不作为 Relationship 目标字段。

## 用户流程

```text
Find an identity
  -> enter complete BAP ID
  -> resolve published Identity
  -> inspect Public Identity
  -> Follow | Friend
  -> Wallet Confirmation
  -> Relationship result
```

取消、拒绝和失败遵循 Wallet 与全局错误规则。Lookup 解析失败不得创建 Relationship。

## 验收

- 完整 BAP ID 精确命中时，结果显示同一 BAP ID。
- 名称、缩写、Inscription Number 不能作为替代输入或持久化目标。
- 没有 Artifact 的 Identity 也能被查找并建立 Relationship。
- Follow 目标使用 `toBapId`；Unfollow 只能撤销已有同类关系。
- Friend 关系使用协议要求的 BAP ID 与公钥字段；未完成 SDK/协议验证前不得宣称安全通信已可用。
- 交易失败、取消或拒绝不产生 Active Relationship。
- Account Switch 终止待签名 Relationship 操作。

## 阻塞项

- Friend 公钥派生、签名封装和验证流程需以当前 Wallet/BAP 实现验证。
- Friend 解除关系的协议语义需确认；不能用 Unfollow 代替。
- Relationship `status` 的最终枚举和索引一致性需在详细设计中确认。

## 不在范围

- 按名称模糊搜索。
- Inscription Number Lookup；在 Artifact 标识版本处理。
- Reply、Repost、Like、Message、Attestation。
