# 单元测试全覆盖计划评审

日期：2026-09-20。结论：**修订后的计划可进入 U0，U0—U9 尚未实施。**

评审对象为 [单元测试全覆盖计划](单元测试全覆盖计划-20260920-090603.md)。本轮完成文档修订；“可进入 U0”是技术评审结论，不代替任务规则要求的代码开工批准，也不表示覆盖率目标已经验证可达。

## 1. 问题与处置

| 级别 | 发现 | 影响与证据 | 当前处置 |
| --- | --- | --- | --- |
| P1 | 原命令没有强制串联报告完整性校验 | JaCoCo 缺 `.exec` 时跳过；本地 Surefire 3.5.6 的 `failIfNoTests` 默认 false。当前 18 个 component 子模块没有本模块测试，存在“无用例、无覆盖率数据但命令成功”的现实条件 | 已将 `verify-unit.py` 定为必需验收入口；U0 必须用缺文件、零测试、漏类、跳过用例的反例证明门禁有效。源码与 CLI 配置依据见计划 §6 |
| P1 | 已有标签不足以保证基线离线 | `BitailsProviderTest` 两个未标记测试真实调用 Bitails HTTP client；component-test 基类会启动 Spring 上下文。只传 `excludedGroups=integration,external` 仍可能访问外部服务 | 已明确 U0 先完成源码/继承/调用链分类与标签修正，再执行基线；profile 自带默认分层过滤；未知分类不自动运行 |
| P2 | 基线采集与逐阶段严格检查缺少独立入口 | U0 合理允许未达标，而原文只给全量严格命令；容易过早被未处理模块阻断，或长期保留绕过检查开关 | 已区分 baseline/accept 两种入口，固定 100% 规则；基线只采集，模块验收限定当前模块及依赖，U9 强制全清单 |
| P2 | 单元和集成证据未定义保存时点与独立路径 | 后续 `clean test` 会删除 target；若共用采集文件，还可能混入集成命中。仅要求“保留报告”不足以约束执行次序 | 已规定每模块立即保存 run ID 对应证据，再允许 install/clean；单元专用采集路径，集成独立目录且不启用覆盖率 profile |

以上问题已在计划层面闭环；脚本、profile、标签和门禁反例属于 U0 的待实现内容，不是本轮完成的代码。

## 2. 已核对的执行条件

- 全部 4 个仓库、25 个 POM 和 21 个 component 子模块都在范围内。
- 解析 POM 得到 component 内 39 条直接依赖，没有模块依赖后续阶段的情况；U3—U8 的主要顺序可用。
- 本地 Surefire 插件描述符确认 `failIfNoTests=false`；JaCoCo 0.8.14 缺数据的行为核对了对应版本源码，而非根据构建成功推断。
- `./init.sh` 本轮退出 0，四仓库在 `feature/java25` 且代码工作区干净；当前执行环境中间件检查仍告警，宿主状态尚未验证。
- 本轮没有运行 Maven 测试、没有执行联网测试，也没有改子仓库代码或 POM。

## 3. U0 必须进一步验证的事项

1. **覆盖率可达性**：`StateHelper` 完整枚举 switch 的 default、生成器 `Scanner.next()` 后的空白判断、JWT 初始化异常是优先排查样本。仅凭源码不宣布它们一定不可覆盖；以字节码、JaCoCo 实际分母和合理测试路径定性。100% 目标保留。
2. **生成代码边界**：本地存在 MapStruct 的 `*MapperImpl` 产物，不能假定所有 `@Generated` 都会被 JaCoCo 过滤。逐类记录生成来源、报告去向与手写契约的测试。
3. **兼容性**：实际验证锁定 JaCoCo、JDK 25、Surefire/Jupiter、Mockito agent 共存。计划中的版本依据不等于本工程实际插桩成功。
4. **用例账目**：重新发现测试，核对继承、参数化、动态测试和非 void `@Test`；历史 26/101 等计数不能作为当前单元基线。

U0 满足计划 §4.3 后即可按既定顺序推进后续阶段。真实业务、架构或范围取舍按任务规则处理；一般测试实现细节由实施者自行解决。
