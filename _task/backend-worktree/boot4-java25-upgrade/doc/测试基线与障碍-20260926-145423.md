## 覆盖障碍及处理方向

| 位置 | 已确认或待核对的障碍 | 处理方向 |
| --- | --- | --- |
| `base/AipHelper` | `ByteArrayOutputStream` 的 `IOException` 捕获路径不可由正常字节输入触发 | 移除不可能发生的受检异常包装，并以公开签名验证 API 覆盖成功、地址不匹配和坏签名 |
| `base/BapHelper`、`api-common/JwtTokenProvider` | 固定算法名的 `NoSuchAlgorithmException` 分支通常不可达 | 先核对 JaCoCo 分母；保留真实失败语义，同时用可注入算法接口或等价简化消除不可测死分支 |
| `component-common/StateHelper` | 枚举 `switch` 默认分支可能无法由合法枚举值触发 | 依据实测字节码确认；只测试真实枚举状态，不伪造值凑分支 |
| `mybatispuls-generator` | `Scanner.next()` 后的空白检查与硬编码 MySQL、源码输出路径妨碍隔离测试 | 分离输入解析和生成参数；用测试数据库、临时目录验证，不覆盖工作区源码 |
| `component-tx/DefaultCompleteTxFactory` | 公开交易完成路径内直接创建 Bitails provider 并调用主网广播 | 引入可注入的 UTXO／广播端口，本地 HTTP 替身覆盖成功和异常；自动测试不接触主网 |
| `component-common/LocalTestUtxoProvider` | 生产类直接读取相对路径 `utxo/utxo-{}.json` | 将夹具路径改为可配置，使用临时目录检验读取和错误处理 |
| `component-file`、`component-test/BitcoinschemaTransactionTest` | 前者 8 个测试全禁用；后者 `@Test` 返回 `String`，Jupiter 没有发现它 | 用本地协议服务替换文件示例；把交易构造行为变成有效的 void 测试与结果断言 |

以上是 U1—U8 的实施障碍清单，不代表已经修复或满足 100% 覆盖率。集成清单逐项记录公开入口、资源隔离与观测方式，目前 19 项均为 `not-started`。MongoDB、Elasticsearch、MySQL、Kafka、Redis 五个宿主服务已通过 `infra/status.sh` 健康检查；执行集成测试前仍需逐项确认应用日志、容器日志、连接配置及自有资源清理。
