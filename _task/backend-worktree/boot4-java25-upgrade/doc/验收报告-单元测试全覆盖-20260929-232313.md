## 6. 保留项：SFTP 实连

**这是本次验收唯一未覆盖的可执行路径，已由胡先生决定按现状收尾。**
`SftpFileClient.doInit()` 通过 hutool `Sftp`（底层 JSch）建立 SSH 连接，其成功构造行
按精确清单登记为覆盖例外（2 行）。

手写 SSH 协议栈不可行：SFTP 需要完整的版本交换、密钥交换、主机密钥验证、通道层与
SFTP 子系统，自研实现既不现实，也不能代表真实 SSH 行为（FTP 之所以能自研，是因为按
RFC 959 实现客户端用到的命令子集即可，且由真实的 commons-net 客户端验证）。

2026-09-30 复核时确认可选的补齐路径有三条：给 `ownword/infra` 增加 sftp 服务（跨任务
共享基础设施变更）、本机安装 openssh-server（宿主环境变更）、为 `metanet4j-component-file`
加 test 作用域内嵌 `org.apache.sshd:sshd-core` + `sshd-sftp`（纯 Java 进程内 SSH/SFTP
服务端，与 FTP 的 `MiniFtpServer` 同构，不改共享 infra、不动宿主环境）。胡先生评估后
决定按现状收尾：该 2 行继续按精确清单登记，不再作为待办。

这是本次验收唯一未覆盖的可执行路径；其余 22 个模块的结论不受影响。若将来要让覆盖率
缺口归零，走第三条路径即可：补 `SftpFileClient.doInit` 成功构造路径用例 → 删除例外登记
与聚合 POM `jacoco.unit.check.excludes` 对应项 → 复跑 `verify-unit.py --mode accept --scope all`
（JSch 0.1.55 与 MINA SSHD 的算法协商需先实测确认）。
