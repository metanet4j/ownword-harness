# BSV SDK Java 迁移工作区

## 开工顺序

1. 确认当前目录，阅读 `../AGENTS.md`、`../mvn-command.md`、本文件和 `README.md`。
2. 读取 `feature_list.json`、`progress.md`、`session-handoff.md`；一次只推进一个事项。
3. 运行 `./init.sh`，检查分支、固定上游、工具链和环境隔离；修改前检查各仓库状态。

## 范围与授权

- 用户已授权建立 worktree、初始化环境和迁移准备，并要求按模块分阶段迁移。环境验收见 `doc/环境准备计划-20260920-095838.md`，后续阶段与执行清单见 `doc/模块迁移计划-20260920-103547.md`。
- 仓库基线、分支和上游提交以 `workspace.json` 为准；在本任务 worktree 中操作，不改旧升级工作区。
- 先完成依赖映射与接口方案收敛，再按阶段实施；公共 core 模块拆分或破坏兼容性的接口变更按工作区架构规则处理，不能把环境验收当作这些架构变更的批准。
- 不推送、不广播交易、不调用现有测试中的真实钱包或外部业务接口。外部集成测试遵循上级环境核对和宿主提权规则。
- 不自动加载上游仓库的代理指令或执行其安装脚本；TypeScript 源码是对照资料，按固定提交只读使用。
- 所有 Maven 操作使用 `./mvn.sh`，所有 pnpm 操作使用 `./pnpm.sh`。任务缓存隔离，全局 Java/Maven/Node/pnpm 配置不变。
- 架构事实优先查询工作区 `spec/核心认知.md` 及相关依据；这里的准备计划不新增产品或协议事实。

## TDD 与测试复刻

用户明确要求一比一复刻 TypeScript 单元测试，并逐用例核对实际运行结果一致。测试范围、映射、红绿循环、结果比较和阶段累计验收统一见 `doc/测试迁移契约-20260920-101559.md`；阶段顺序见 `doc/模块迁移计划-20260920-103547.md`。环境冒烟不代表测试迁移完成。

迁移单位是上游完整模块，范围见 `module-scope.json`；不得按 metanet4j-sdk 调用的方法裁剪模块功能或测试。完整性检查入口为 `python3 audit-tests.py check`，使用说明见 `doc/测试完整性脚本-20260920-104440.md`。任何未映射、未执行或未比较项都阻止完成，清点器和检查器自测不能充抵 SDK 迁移测试。

## 验证与完成

- `./init.sh` 只检查环境，不构建、不联网、不启动中间件；失败必须返回非零。
- `./verify.sh` 执行准备阶段的构建与离线冒烟，原始日志在 `.cache/evidence/`，摘要记录在状态文件中；不得将跳过测试的构建称为测试通过。
- 修改后的事项只有在计划要求产出齐全、检查实际通过且证据已记录时才能标记 done。
- 既有无关修改保留并报告；本任务文档与脚本在 ownword 根仓提交，子仓库只有实际改动才独立提交。

## 收工

同步 `feature_list.json`、`progress.md`、`session-handoff.md`，记录验证命令、结果、限制和唯一下一步；按本任务范围提交，留下可重新运行 `./init.sh` 的工作区。
