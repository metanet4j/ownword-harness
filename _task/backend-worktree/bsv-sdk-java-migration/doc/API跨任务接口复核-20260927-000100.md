# API 跨任务接口复核

本轮以固定 TS 提交 `f999e0c1aad9a7afd0cbadaaf23841d049af9d5a` 和 Java 基线 `975fa75` 为依据。API 映射已覆盖全部声明；本轮独立探针发现的异步返回、同步异常转换及 HTTP 平台差异已分别修复并验证。导出名称扫描仍不等于全部行为验收，整合后的总验收须结合既有批次证据与当前 Java 回归。

## 导出与跨任务引用

`api-catalog.json` 的 1016 个导出入口展开为 447 个不同声明目标和 5 个 namespace。逐入口解析 `api-map.json` 的 Java 名称后，447 个目标都能定位到 Java 源文件及对应成员名。详细记录为 `.cache/evidence/api-contract-async-20260926/export-targets.json`；该扫描仅确认名称存在，不能证明方法签名、可访问性或行为相同。

5 个 namespace 分别对应 BSM、ECDSA、Hash、Utils、ValidationHelpers。跨文件共用 Java 符号主要是三个 Node HTTP 适配接口、Certificate 及派生类继承的七个字段、MerklePath.combine 的 BEEF 合并辅助步骤，以及证据异常转换方法。本轮未发现这些共用名称产生编译冲突。Java 基线的运行依赖为 Jackson；HTTP 平台修复 `052c389` 增加 `org.apache.httpcomponents.client5:httpclient5:5.6.4`。源码无 `com.metanet4j.base`／`com.metanet4j.sdk` 引用，也未修改四个既有工程。

## 公开异步入口

固定 TS 的 `Transaction.verify` 与 `completeWithWallet` 在等待链查询、费率、钱包和模板时返回 Promise。Java 原实现于返回 Future 前调用未完成 Future 的 `join()`，可阻塞调用线程。四个延迟依赖回归在原实现上均因 2 秒内未返回 Future 而失败；原始 XML 和 Maven 输出保存在证据目录 `red/`。

Java 提交 `ada34a2` 在隔离工作树 `/tmp/bsv-api-contract-async-20260926` 使用 Future 续步保持原执行顺序；验证队列对已完成依赖继续迭代，对未完成依赖登记续步。未增加线程或依赖。

原协调器用例 `reQueuesASameTxidAlternateCandidateDisplacedByAConcurrencyLimitedAttemptInsteadOfLosingIt` 的 TS 实现连续同步提交 bad、displacer、good，随后才进入 Promise 等待。Java 原夹具允许后台线程在 good 提交前结束 bad，已用现有 Tracker.gate 重现该同步提交顺序，保留原候选与全部断言。

## 同步异常与异步拒绝

固定 TS 的 `Transaction.fee`、`Transaction.broadcast`、`getVerifiableCertificates` 在注入对象同步抛错时仍返回 Promise，并拒绝同一错误。三项实测输出在 `ts-sync-exception-probe.jsonl`。

Java 原入口缺少首个异步调用前的异常转换，三个新增 RED 回归均观察到同步逃逸。提交 `f719535` 将其转换为携带原异常的 failedFuture；直接受影响的固定原用例与新增回归合计 22／22 通过，失败／错误／跳过均为零，原始日志及 XML 在 `exception-red/`、`exception-green/`。新增异步回归共 7 例，单独计数。

## HTTP 平台差异

宿主回环服务返回 `HTTP/1.1 503 Custom Failure` 时，默认 PATCH 请求观测为：

```text
Java PATCH status=503 statusText=[]
TS fetch PATCH status=503 statusText=[Custom Failure]
```

原实现中 HttpURLConnection 不支持 PATCH 时，Java 转入 JDK HttpClient，适配代码固定返回空 statusText；该值还进入 TransportError 的文本及 details。固定 TS fetch 保留 reason phrase。提交 `052c389` 改用 Apache HttpClient 保留备用路径的原始 reason phrase；本报告已核对该提交源码与 POM。GET／PATCH 回归及传输原测试合计 54／54 通过，3 份 Surefire XML 已独立核对，位置为 `.cache/evidence/api-contract-http-status-20260927/surefire-reports/`。此差异通过实现修复收口。
