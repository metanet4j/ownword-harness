# BigNumber 位运算输入局部验收

固定上游 `src/primitives/__tests/BigNumber.binary.test.ts` 的全部 20 例已通过局部标准验收。正式 Java 证据绑定提交 `8b8907b`；完整 P0 验收尚未通过。

## 结果

| 项目 | 结果 |
| --- | --- |
| 正式 TS / Java 原测试 | 20 / 20；失败、错误、跳过均为 0 |
| 真实入口输入 | 854 / 854，逐样本一致 |
| 原断言实际值 | 521 / 521，逐站点、逐次执行一致 |
| Java 原测试主体与独立 replay | 全部 521 个原 matcher 和实际值逐项一致 |
| 共享执行器回归 | arithmetic 52 + binary 20，共 72 / 72 通过 |
| 标准 bundle / compare | PASS，`formalAcceptance=false` |

两处原循环完整保留：两个全 1 向量的 8 + 256 个 bit，以及固定十进制大整数的 204 个 bit。循环条件中额外执行的 205 次 `bitLength()` 同样进入真实输入账本。原 Java 测试主体继续按实际 `bitLength()` 执行循环，其 521 条原断言必须与独立 replay 一致，防止固定语料掩盖循环数量错误。

`BigNumberInputReplay` 复用算术批次的真实 SDK 调用、对象身份和调用前状态核对，新增位运算参数与原布尔取反表达式适配。语料不保存 TS actual 作为 Java 返回值。Java 生产代码未因本批变更。原 Java 布尔断言的记录形式已与原 Jest `toEqual` 一致；两处映射顺序已按源码修正。

## 重跑入口

复用 [算术批次命令](BigNumber算术输入验收-20260927-041245.md#重跑入口) 的标准 capture 格式，替换为以下参数：

- 输入计划使用 `bn-binary-input-plan.json`。
- catalog / mapping 使用 `.cache/evidence/bn-binary-plan-20260927/` 中对应文件。
- replay 使用 `metanet4j-bsv-sdk/src/test/resources/migration/bn-binary-inputs.jsonl`。
- 两侧 `capture-bn-arithmetic-side.py` 命令均增加 `--variant binary`。
- 使用新的输出目录，Java 保留 `java clean test`，在宿主环境执行。

标准 bundle 与 compare 参数见 `full-evidence-locals.json` 的 `bignumber-binary` 条目；重跑时全部替换为同一次运行的路径。
