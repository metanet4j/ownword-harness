## 实现与真实重放

复用现有 BigNumber 入口记录器与 Java 独立重放器，增加 utils 变体。620 个入口包含 307 次构造；每个原方法调用记录真实接收者、实参类型、对象引用和当时数值。原测试文件保持只读。资源只保存输入、结果引用与原 matcher，Java 返回值由实际 SDK 调用独立计算。

首例保留完整 128 次循环与每次增长的十六进制字符串。原 Java 测试主体也继续执行该循环，长度 matcher 恢复为 `toHaveLength`。三个异常用例按原 Error 对象校验消息；两个 `1 / cmp(...)` 表达式在 Java 中实际运算，独立验证正无穷结果。`isBN` 的空数组与普通对象均保留对应输入类型。两个 fromTwos 大整数对照表达式按原顺序先计算 actual，再计算 expected。

Java 原测试主体与独立重放的 284 条断言逐值完全一致，随后与正式 TS 的 284 条原断言核对，差异列表为空。本切片没有生产代码变更，也没有新增跨语言比较例外。

## RED、GREEN 与反例

- 基线原 Java JUnit 36／36 通过，但严格原断言门禁 RED：Java 记录 287 条，原 TS 为 284 条；134 条长度断言错误地记录为 `toEqual`，三个异常用例多出了消息断言。原门禁拒绝额外断言。
- 修正原 matcher 与 Error 期望、补齐独立入口重放后，累计 124 例 GREEN，620 输入、284 原断言双端一致；原 Java 主体的 284 条断言也与独立重放一致。
- 原循环篡改：把 128 次缩为 127 次，计划生成器返回 1 并拒绝。
- 正式输入篡改：把首轮构造实参 `1` 改为 `2`，bundle 返回 2。
- 正式断言篡改：把原首轮长度 actual `1` 改为 `2`，bundle 返回 2，独立原断言比较也拒绝。
