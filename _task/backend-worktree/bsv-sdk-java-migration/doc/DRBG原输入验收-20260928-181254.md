## 实现与真实重放

探针 `capture-drbg-inputs.cjs` 不改写原测试，通过 mock `DRBG` 与 `utils.toArray` 记录真实入口与守卫操作数：构造／`generate` 记录接收者身份与实参，NIST 向量用例（10／11 行）记录 `entropyHex`／`nonceHex` 与结果长度，派生出携带 `guardSiteId`／`taken`／`controlFlow` 的分支样本。连续两次运行的 72 条样本与 30 条断言逐字节一致。

计划由 `prepare-drbg-inputs.py` 生成（`drbg-input-plan.json` 与 `.cache/evidence/drbg-plan-20260927/`）：29 例、72 样本、30 断言；15 例无效向量登记 26:9、27:9 未执行证明（规则 `drbg-nist-invalid-input-v1`，条件站点 15:9，同例共用一份分支样本）；RFC 6979 三例登记 `intToOctets` 循环样本。计划通过 `audit-tests.validate_plan`、`validate_branch_plan` 15／15、`validate_branch_observations` 15／15，`taken` 篡改被拒。

Java 侧 `DrbgInputReplay` 按 `javaMethod` 消费固定语料：重算守卫条件（`Utils.toArray` 结果长度）、按接收者身份实例化 `DRBG`、逐条记录实际消费值；`DrbgTest` 的断言保持原 matcher，无实参 `toThrow` 用 `assertThrowsAny`、四个消息断言用 `assertThrowsContaining`，各自只记录一条观察。两端“无期望 toThrow”在采集转换中统一为类型化 undefined，未新增跨语言比较例外。

## RED、GREEN 与反例

- 首轮 Java 主体用 `assertThrowsMessage` 记录异常，四个消息断言各多出一条 `toEqual`（34 条对原 30 条），逐用例对照拒绝；改用 `assertThrowsContaining` 后 30／30 一致。
- 输入篡改：Java 侧把一个 `generate` 长度由 16 改为 17，bundle 拒绝“TS/Java 输入或前置状态不同”。
- 断言篡改：TS 侧改动 `toBe` 实际值末位，bundle 拒绝“实际结果不一致”。
- 分支篡改：两端把分支样本 `taken` 改为 false，bundle 拒绝“原条件没有证明提前返回，不能删除后续断言”。
