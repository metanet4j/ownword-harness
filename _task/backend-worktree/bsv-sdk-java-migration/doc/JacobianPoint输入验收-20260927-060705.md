## 原输入与实现修正

共享采集器保留原参数类型、Point 实际仿射坐标及 JacobianPoint 的实际 `x/y/z/zOne`。原测试里的 Point-like 普通对象按 Map 和 `BooleanSupplier` 表征；回调只有在真实 SDK 调用时执行，实际返回 `false` 单独记为输入。固定语料包含 183 次原 SDK 入口和 1 次外部回调返回，不包含 TS 断言输出。

`mixedAdd(Point)` 保留原类型签名，最小 `mixedAdd(Object)` 重载接收该原测试的普通对象，真实调用 `isInfinity` 后检查空坐标。原 Java 用例按原顺序构造接收者并传入 Map，不再额外构造一个 Point 作为错误参数。

保留真实 Jacobian 状态后，原 35 例暴露 5 处差异：3 处加法结果的 `y/z` 与 TS 同时反号，2 处取负后丢失 `curve.one` 身份、使 `zOne` 从真变假。生产实现作两项最小修正：

- `add` 使用原 `h = u1 - u2`、`r = s1 - s2` 和 `nx = r² + h³ - 2v`，其余公式保留。
- `neg` 按原实现把 `x`、`y.redNeg()`、`z` 传给构造器，保留原 `z` 对象身份。

Java 原测试恢复原 BigNumber 标量类型、预期点计算顺序、重复转换次序及 `toBe` / `toThrow(text)` matcher。原 37 条断言没有增加宽松语义规则。
