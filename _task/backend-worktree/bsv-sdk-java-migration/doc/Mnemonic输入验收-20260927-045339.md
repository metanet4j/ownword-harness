`MnemonicInputReplay` 在原 Java 测试实际调用的公开入口核对参数和调用前状态，再将固定输入传入真实 SDK 方法。内部方法委派不重复记作测试入口。原 50 个测试主体、158 次断言和 24 条 BIP39 向量均保留；语料没有把 TS actual 当作 Java 返回值。生产代码未因本批变更。

随机输入来自固定 TS 原测试的 7 次实际调用。正式 TS 再次执行全部原用例时冻结这些字节，Java 通过现有 `CompatRandom` 测试入口消费同一输入，逐次核对测试身份、调用顺序和长度。每例结束必须消费完全部输入。

## 重跑入口

从任务根目录在宿主环境执行，使用新的输出目录以保留现存证据：

```bash
python3 evidence-bundle.py capture --side ts \
  --catalog .cache/evidence/mnemonic-plan-20260927/catalog.json \
  --mapping .cache/evidence/mnemonic-plan-20260927/mapping.json \
  --input-plan mnemonic-input-plan.json \
  --inputs "$ts_output/inputs.jsonl" --assertions "$ts_output/assertions.jsonl" \
  --output "$ts_output/manifest.json" --report "$ts_output/jest.json" -- \
  python3 capture-mnemonic-side.py ts \
  --catalog .cache/evidence/mnemonic-plan-20260927/catalog.json \
  --mapping .cache/evidence/mnemonic-plan-20260927/mapping.json \
  --replay metanet4j-bsv-sdk/src/test/resources/migration/mnemonic-inputs.jsonl \
  --report "$ts_output/jest.json"
```

先将 `ts_output` 设为新的绝对路径。Java 使用同一结构，将侧别改为 `java`、报告改为 `surefire.xml`，执行器参数改为 `capture-mnemonic-side.py java clean test`，并使用独立的 `java_output`。Java 采集期间主仓源码版本必须保持稳定。

标准封装使用 `python3 evidence-bundle.py`，比较使用 `python3 audit-tests.py compare`；传入本次双方 catalog/mapping、输入计划、输入、断言、manifest 和报告，比较时额外传入封装结果 `--observations`。全量登记由主代理统一维护 `full-evidence-locals.json`；本报告只说明该 50 例切片，不能替代最终统一源码版本的完整模块验收。
