## 实际采集边界

`capture-script-vector-inputs.cjs` 按冻结文件、原用例名称和 occurrence 绑定 caseId，在实际 SDK 调用前记录参数。Script 使用静态方法的 Jest spy，保留每次 `fromHex` 与 `fromASM` 的真实字符串；Spend 使用构造器 Proxy，记录调用方传入的源交易标识、索引、金额、锁定与解锁脚本、版本、输入输出、序列号和锁定时间。固定 TS 源码保持只读。

Java 的 `VectorInputRecorder.record(String test, Object input)` 由两个共享向量 helper 调用，记录本侧实际消费的值。原 invalid 向量在每条不抛异常断言中复用一次解析对象；Java helper 已按这一顺序实现，实际输入次数为 6。valid 向量重新解析，次数为 8。两类仍各保留四条原断言。

Java 记录器读取 `MIGRATION_VECTOR_JAVA_INPUTS`；未启用时不写文件。启用后要求 `EVIDENCE_RUN_ID` 和 `EVIDENCE_SIDE=java`，输出 `{runId,side,test,input}` JSONL。该小接口可供 Transaction 等共享向量 helper 复用。TS 对应接口为 `MIGRATION_VECTOR_TS_INPUTS` 和 `MIGRATION_VECTOR_CATALOG`，输出包含 caseId 的同类原始行。

## 复核与复现

真实最终证据在 `.cache/evidence/script-vector-inputs-20260927/`：

- `ts-final/`：完整三文件 Jest 报告、日志、实际调用参数和断言原始轨迹、规范化轨迹、独立运行 manifest。

- `parity-final.json`：1940 / 8286 / 5030 对照结果，`formalAcceptance=false`。

重新采集必须使用新的输出目录。真实测试须在宿主提权运行，并与其他 Maven 任务协调资源。

```bash
python3 script-vector-evidence.py prepare --plan .cache/evidence/vector-new/plan
python3 script-vector-evidence.py ts \
  --plan .cache/evidence/vector-new/plan --output .cache/evidence/vector-new/ts \
  --java-worktree /tmp/bsv-vector-inputs-20260927
python3 script-vector-evidence.py java \
  --plan .cache/evidence/vector-new/plan --output .cache/evidence/vector-new/java \
  --java-worktree /tmp/bsv-vector-inputs-20260927
python3 script-vector-evidence.py compare \
  --plan .cache/evidence/vector-new/plan --ts .cache/evidence/vector-new/ts \
  --java .cache/evidence/vector-new/java --java-worktree /tmp/bsv-vector-inputs-20260927 \
  --output .cache/evidence/vector-new/parity.json
```

每端 manifest 固定本轮命令、独立 runId、开始与结束源码摘要、计划及采集器指纹、原始报告和轨迹摘要。对照时重新从原始轨迹推导规范化轨迹；单改规范化结果或给篡改的原始输入刷新摘要都不能绕过核验。缺用例、缺样本、调用次序变化、错误侧别、重复 Java 身份和任一原断言失败均拒绝通过。

`python3 test-script-vector-evidence.py`：9 / 9 正常及篡改反例通过，包含 valid/invalid 两种调用顺序、缺样本、错误侧别、原断言失败、Spend 前置字段缺失、旧采集器指纹、修改原始输入后刷新摘要。前置工具扩展后的 `python3 test-full-evidence-preflight.py` 为 13 / 13，通过专用计划投影的反例确认其不能充当标准 capture 的来源证据。
