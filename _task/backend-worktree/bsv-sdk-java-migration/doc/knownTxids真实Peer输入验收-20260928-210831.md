# knownTxids 真实 Peer 原例输入验收

## 范围与结果

固定 `src/auth/clients/__tests__/AuthFetch.knownTxids.test.ts` 中的 `authenticatedPeerHintSurvivesPaidRetry`（17 个原例中的真实 Peer 付款例）已完成双端同输入局部门禁。

| 检查 | 实际结果 |
| --- | --- |
| 该文件固定 TS 原测试 | 17／17（入口探针与 Peer 探针各跑一次同一固定文件） |
| Java 对应原测试 | 17／17；断言表示层回归 21／21 |
| 双端 Peer 输入 | 1／1：请求随机数、两次 fetch 入口、Peer 前置状态、交付帧、发送载荷与结果、监听器编号与停止编号逐字段一致 |
| 双端原断言 | 6／6 一致 |
| 篡改反例 | Peer 输入篡改、断言篡改均被拒绝 |

局部门禁输出 `formalAcceptance=false`，作为该切片的独立验收，不代替任务级门禁。

## 实现与真实重放

`AuthFetchKnownTxidsPeerInputReplay` 按固定 TS 语料驱动 Java 侧真实流程：请求随机数按语料顺序经 `requestNonceSupplier` 注入，两次 `fetch` 入口的 url/config 与语料比对后才放行，`toPeer` 发送载荷与身份逐字节复核，语料记录的交付帧喂给监听器回调，监听器编号、停止编号与监听次数同源核对；无 Peer 观测语料时不启用，付款门禁与全量回归不受影响。

入口探针与 Peer 探针都占用 Jest 模块工厂，无法在同一次 Jest 运行中并用：门禁改为对同一固定文件运行两次（入口探针 17 条 + Peer 探针 1 条，各自独立 runId），合并后作为 Java 侧语料，两次 Jest 报告都要求 17／17。

## RED、GREEN 与反例

- 最初两探针同跑时入口探针报“固定 knownTxids 用例缺少真实入口观察”（后注册的模块工厂覆盖前者）；改为两次运行后合并语料。
- 首次门禁运行缺 `ts-peer-network.jsonl`、`ts-entry-assertions.jsonl` 产物校验项，改为按实际产物登记摘要。
- `tamper`：篡改交付帧字节与断言实际值均被拒绝。
