# 全量联合运行来源门禁

`full-evidence-run.py` 固定当前完整清单、映射、输入计划、Java revision 和采集工具后，按 TS capture → Java capture → bundle → `audit-tests.py check` 顺序执行。两个采集子进程各自产生独立 `runId`，并记录父运行的 `fullRunId`。联合 manifest 绑定命令、子进程、时间窗、日志、原始报告和轨迹的摘要；验证时重新清点固定 TS 源码并重验逐用例实际值。

目前交付的是运行工具。完整输入计划、`full-evidence-locals.json.fullRun` 双侧适配器和范围复核尚未齐备时，入口在执行测试前失败。工具自测使用两例合成数据，不计入 5329 个 SDK 原用例。

## 完整运行前置

- `full-evidence-preflight.py` 必须达到 `readyForFullCapture=true`；结构计划合并不生成运行轨迹。
- `module-scope.json.scopeReview=reviewed`，完整重新清点不得有待归属模块或跨目录测试。
- `fullRun` 提供 `tsCommand`、`javaCommand`、`tsReports`、`javaReports`。命令中的 `{runDir}` 会替换成本轮新目录；报告名称必须为目录内的相对路径。
- 两个适配器消费现有 `EVIDENCE_RUN_ID`、`EVIDENCE_SIDE`、`EVIDENCE_INPUTS_PATH`、`EVIDENCE_ASSERTIONS_PATH` 和 `EVIDENCE_INPUT_PLAN` 接口。Java 命令必须包含无过滤的 `clean test`，同次执行后保存完整 Surefire 报告。
- 实际 `run` 按工作区要求通过宿主提权执行。运行期间停止修改 Java 源码、映射及采集工具。

## 命令

```bash
python3 test-full-evidence-run.py

python3 full-evidence-run.py run \
  --run-dir .cache/evidence/full-run-<新时间戳> \
  --timeout-minutes 90

python3 full-evidence-run.py verify \
  .cache/evidence/full-run-<新时间戳>/full-run.json
```

默认 90 分钟是四阶段共享的实际执行截止时间；超时终止整个子进程组。只有前次实际触及 90 分钟、且输入计划、命令、源码和工具版本相同，才可按用户授权重跑：

```bash
python3 full-evidence-run.py run \
  --run-dir .cache/evidence/full-run-<另一个新时间戳> \
  --timeout-minutes 180 \
  --retry-after .cache/evidence/full-run-<已超时的时间戳>/full-run.json
```

新目录必须不存在。工具不会追认既有局部报告；旧 `runId`、独立 `fullRunId`、范围裁剪、报告缺失、时间窗不符、版本变化及内容篡改均拒绝。没有签名或远程可信执行器，本地 manifest 和脚本均属于受信工作区；本门禁验证可复现运行来源与内部一致性，不提供对控制整个工作区者的密码学证明。

完整联合运行通过只证明该次 SDK 测试证据门禁；API 门禁、任务依赖状态及最终交付仍按 `feature_list.json` 验收。
