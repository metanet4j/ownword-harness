# 全量验收运行手册（单次双侧采集 → audit-tests.py check）

本手册描述最终验收的唯一路径：在**冻结的单一 Java 来源**上，用一次 TypeScript 全量运行与一次 Java 无过滤全量运行采集全部 5329 个用例，然后跑完整性检查。局部证据不能拼接成最终证据（见 `doc/全量证据采集前置-20260927-005500.md`）。

## 一、前置条件（缺一不可）

1. **结构计划完整**：`python3 full-evidence-preflight.py` 的 `missingPlanCases=0`、`planErrors=[]`、`completePlanError=null`；可用 `python3 item-readiness.py`、`python3 closure-check.py --all` 交叉核对。
2. **全量运行接口就绪**：`full-evidence-locals.json` 的 `fullRun` 段含 `tsCommand`／`javaCommand`／`tsReports`／`javaReports`，preflight 的 `missingFullRunInterfaces=[]`。
3. **Java 注册身份唯一**：preflight 的 `javaRegistrations.duplicateReferences=0`，每个原用例对应独立 Java 测试身份。
4. **源码冻结**：所有实施与采集改动已提交；`git -C metanet4j-bsv-sdk status --porcelain` 为空；采集期间任何人不得改 `metanet4j-bsv-sdk/src`（改动会推进来源摘要并使整轮作废）。
5. **范围复核**：`module-scope.json` 的 `scopeReview=reviewed`（范围复核结论见 `doc/完整模块与API映射-20260920-122800.md`）。**当前值仍为 `pending`**，note 写明“仍待 P0 联合验收”——必须在最终全量运行前完成 P0 联合复核并落成 `reviewed`，否则 `audit-tests.py check` 会以“依赖模块及跨目录测试归属尚未审查完成”拒绝。
6. **环境**：宿主提权运行（完整 TS 基线含内存内集成测试）；Maven／pnpm 走 `./mvn.sh`／`./pnpm.sh`；全部命令经 `./lock.sh` 串行执行。

## 二、执行步骤

```bash
# 0. 冻结并确认来源
git -C metanet4j-bsv-sdk status --porcelain          # 必须为空
python3 full-evidence-preflight.py --require-ready \
    --run-dir .cache/evidence/final-<日期>          # 通过后写出计划与四步命令

# 1. 按 --run-dir 生成的四步顺序执行（不手工改动参数）
#    TS capture → Java capture → evidence-bundle 汇总 → audit-tests.py check
#    每一步都在同一运行目录内落原始报告、输入/断言轨迹与 run manifest

# 2. 复核
python3 full-evidence-preflight.py --output .cache/evidence/final-preflight-<日期>.json
node audit-api.cjs check                             # 无过滤 API 门禁
```

若某一步失败：不得复用已产出的运行目录（`evidence-bundle.py` 拒绝已有产物），换新目录整轮重跑；失败原因属采集实现问题时先修工具、再从头采集，禁止手工拼接或改写轨迹。

## 三、判定与留档

- `audit-tests.py check` 通过 = 六模块 5329 个注册用例的映射、执行、输入、断言与来源全部闭合；`formalAcceptance` 由它给出，不能用局部报告的 `taskAcceptance` 替代。
- 归档：运行目录（原始 Jest/Surefire 报告、输入/断言轨迹、manifests、汇总 JSON）、API 门禁输出、本轮 preflight JSON；在 `progress.md`／`session-handoff.md` 记录命令、结果与封存路径。

## 四、已知约束

- Java 命令必须是无过滤 `clean test`（preflight 拒绝 `-Dtest=`、`skipTests` 等）；报告必须写在运行目录内。
- TS 侧靠 `capture-full-dispatch.cjs` 按原文件分派探针；没有探针的原文件会被记进 `unmapped-files.jsonl`，出现即说明计划覆盖不完整，须先补探针再重跑。
- 大数组（如 4 MiB BEEF）按摘要规则采集，语义规则站点（null 适配、耗时、随机）由 `audit-tests.py` 的固定规则比较，不能放宽。
- 运行时长：完整 TS 基线约 66 分钟（含原规模 manual），Java 全量 `clean test` 约 10 分钟；须预留窗口，期间禁止改源码。

## 五、最终窗口执行清单（所有并行开发停笔后，主代理独占执行）

前置：`./lock.sh ./mvn.sh -f metanet4j-bsv-sdk/pom.xml test-compile` 干净；`python3 validate-plans.py` 全绿；`python3 build-full-run-probes.py` 报 `unresolved=0`；**没有代理仍在改 Java**。

```bash
cd /home/haodev/ownword/_task/backend-worktree/bsv-sdk-java-migration

# 1. 冻结来源：把全部 Java 改动提交（SDK 仓），此后不得再编辑任何源文件
cd metanet4j-bsv-sdk && git add -A && git commit -m "test(migration): 并行批次测试侧重放与接线（冻结来源）" && cd ..

# 2. 逐局部重采（内部即为 TS jest + Java clean test + bundle 汇总 + 篡改门禁）
./recapture-all.sh final-$(date +%Y%m%d)

# 3. 全量前置复核：planErrors 必须为空，且 currentCaptureVerified 覆盖全部 5329 例
./lock.sh python3 full-evidence-preflight.py --output .cache/evidence/preflight-final.json

# 4. 逐事项任务级对照（用 item-locals.json 的局部清单；每个事项一条报告）
python3 local-task-parity.py --item <item-id> --output .cache/evidence/<item-id>-task-parity.json

# 5. 单次双侧全量运行（fullRun 段已写入 full-evidence-locals.json）
#    注意：全量 TS 含 AESGCM.man 的 66 分钟长跑，整体约 2 小时；full-evidence-run.py run 默认 90 分钟超时，
#    必须显式 --timeout-minutes 180，否则会在长跑结束前被超时中断。
python3 full-evidence-run.py run --run-dir .cache/evidence/full-run-<日期> --timeout-minutes 180
python3 full-evidence-run.py verify .cache/evidence/full-run-<日期>/full-run.json

# 若分步执行（不使用 full-evidence-run 的 manifest 纪律），则按下面三条：
./lock.sh python3 run-full-ts-capture.py   --run-dir .cache/evidence/full-run-final --report ts-jest.json
./lock.sh python3 run-full-java-capture.py --run-dir .cache/evidence/full-run-final --reports java-surefire.xml clean test
python3 audit-tests.py check --run .cache/evidence/full-run-final

# 6. 接口面复核
node audit-api.cjs check
```

判定：`audit-tests.py check` 通过 + `audit-api.cjs check` 退出 0 + 每个事项的 `task-parity` 达到 `cases/inputs/assertions` 全覆盖，方可把 `feature_list.json` 对应事项置 `done` 并标记目标完成。

约束：最终窗口期间**禁止任何并行 Maven/采集**；任一环节失败都要修好后**从第 1 步重来**（来源一旦前移，前面所有局部证据作废）。
