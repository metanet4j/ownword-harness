# 全量验收运行手册（单次双侧采集 → audit-tests.py check）

本手册描述最终验收的唯一路径：在**冻结的单一 Java 来源**上，用一次 TypeScript 全量运行与一次 Java 无过滤全量运行采集全部 5329 个用例，然后跑完整性检查。局部证据不能拼接成最终证据（见 `doc/全量证据采集前置-20260927-005500.md`）。

## 一、前置条件（缺一不可）

1. **结构计划完整**：`python3 full-evidence-preflight.py` 的 `missingPlanCases=0`、`planErrors=[]`、`completePlanError=null`；可用 `python3 item-readiness.py`、`python3 closure-check.py --all` 交叉核对。
2. **全量运行接口就绪**：`full-evidence-locals.json` 的 `fullRun` 段含 `tsCommand`／`javaCommand`／`tsReports`／`javaReports`，preflight 的 `missingFullRunInterfaces=[]`。
3. **Java 注册身份唯一**：preflight 的 `javaRegistrations.duplicateReferences=0`，每个原用例对应独立 Java 测试身份。
4. **源码冻结**：所有实施与采集改动已提交；`git -C metanet4j-bsv-sdk status --porcelain` 为空；采集期间任何人不得改 `metanet4j-bsv-sdk/src`（改动会推进来源摘要并使整轮作废）。
5. **范围复核**：`module-scope.json` 的 `scopeReview=reviewed`（范围复核结论见 `doc/完整模块与API映射-20260920-122800.md`）。
6. **环境**：宿主提权运行（完整 TS 基线含内存内集成测试）；Maven／pnpm 走 `./mvn.sh`／`./pnpm.sh`；全部命令经 `./lock.sh` 串行执行。

## 二、执行步骤

```bash
# 0. 冻结并确认来源
git -C metanet4j-bsv-sdk status --porcelain          # 必须为空
python3 full-evidence-preflight.py --require-ready \
    --run-dir .cache/evidence/final-<日期>          # 通过后写出计划与四步命令

# 1. 按 --run-dir 生成的四步顺序执行（不手工改动参数）
#    TS capture → Java capture → evidence-bundle 汇总 → audit-tests.py check
#    每一步都在同一运行目录内落原始报告、输入/断言轨迹与 run manifest

# 2. 复核
python3 full-evidence-preflight.py --output .cache/evidence/final-preflight-<日期>.json
node audit-api.cjs check                             # 无过滤 API 门禁
```

若某一步失败：不得复用已产出的运行目录（`evidence-bundle.py` 拒绝已有产物），换新目录整轮重跑；失败原因属采集实现问题时先修工具、再从头采集，禁止手工拼接或改写轨迹。

## 三、判定与留档

- `audit-tests.py check` 通过 = 六模块 5329 个注册用例的映射、执行、输入、断言与来源全部闭合；`formalAcceptance` 由它给出，不能用局部报告的 `taskAcceptance` 替代。
- 归档：运行目录（原始 Jest/Surefire 报告、输入/断言轨迹、manifests、汇总 JSON）、API 门禁输出、本轮 preflight JSON；在 `progress.md`／`session-handoff.md` 记录命令、结果与封存路径。

## 四、已知约束

- Java 命令必须是无过滤 `clean test`（preflight 拒绝 `-Dtest=`、`skipTests` 等）；报告必须写在运行目录内。
- TS 侧靠 `capture-full-dispatch.cjs` 按原文件分派探针；没有探针的原文件会被记进 `unmapped-files.jsonl`，出现即说明计划覆盖不完整，须先补探针再重跑。
- 大数组（如 4 MiB BEEF）按摘要规则采集，语义规则站点（null 适配、耗时、随机）由 `audit-tests.py` 的固定规则比较，不能放宽。
- 运行时长：完整 TS 基线约 66 分钟（含原规模 manual），Java 全量 `clean test` 约 10 分钟；须预留窗口，期间禁止改源码。
