# 子代理采集作业说明（标准双侧同输入局部）

本说明供并行子代理使用：把指定的原测试文件／既有旧局部升级为**标准双侧同输入局部**，与已完成的 LivePolicy、ef-cache、Transaction.additional 同一模式。只读参考：本文件、`AGENTS.md`、`doc/测试迁移契约-20260920-101559.md`。

## 一、两种既有形态与升级路径

**A. 全新文件（无旧局部）**：需要写探针、冻结计划、适配器、Java 重放入口与测试接线。参考实现（照抄结构，改目标文件）：

| 参考 | 文件 |
| --- | --- |
| mock 依赖型（fetch／外部客户端） | `capture-live-policy-inputs.cjs`、`prepare-live-policy-local.py`、`capture-live-policy-side.py`、`metanet4j-bsv-sdk/src/test/java/com/metanet4j/bsv/transaction/fee_models/LivePolicyInputReplay.java`、`LivePolicyTest.java` |
| 原型包装型（类与类互相引用） | `capture-transaction-ef-cache-inputs.cjs`、`transaction-locals.py`、`prepare-transaction-local.py`、`capture-transaction-local.py`、`.../TransactionEfCacheInputReplay.java`、`TransactionEfCacheTest.java` |
| 多入口＋异常路径型 | `capture-transaction-additional-inputs.cjs`、`TransactionAdditionalInputReplay.java`、`TransactionAdditionalTest.java` |

**B. 既有旧局部（已有 `replay.jsonl`／`replay-inputs.jsonl` 与 `*-InputReplay.java`）**：多数只差“标准适配器 + 登记”。升级步骤：

1. 读 `.cache/evidence/<旧计划目录>/` 里的 `catalog.json`／`mapping.json`／`input-plan.json`／`replay*.jsonl`。
2. 打开对应 `capture-*-side.py`，按下面“适配器要求”修好两侧共用一个运行目录的问题（旧适配器多用 `calls.raw.jsonl`／`assertions.raw.jsonl` 共享名，会互相覆盖）。
3. 登记并采集：
   ```bash
   python3 register-local.py --name <局部> --catalog <catalog.json> --mapping <mapping.json> \
       --input-plan <input-plan.json> --capture <capture-*-side.py>
   ./lock.sh python3 recapture-local.py --name <局部> --run .cache/evidence/<局部>-standard-<日期> --update
   ./lock.sh python3 local-evidence-gate.py tamper --name <局部>
   ```
   （`replay` 路径会从计划目录里的 `replay.jsonl`／`replay-inputs.jsonl` 自动识别；识别不出来时在登记里补 `replay`，即 `register-local.py ... --replay <路径>`。）

## 二、适配器要求（两种入参约定）

- `--replay <语料>`：Java 侧用 `-Dmigration.<x>.corpus=<语料>` 重放冻结语料；TS 侧用探针重采并写 `EVIDENCE_INPUTS_PATH`。旧适配器多属这类。
- `--plan <计划目录>`：两侧在同一次 bundle 内采集，Java 侧通过专用环境变量读取本轮 `ts-inputs.jsonl`（新适配器用这类）。

共同点（必须满足，否则 bundle 报错）：

1. **两侧共用同一运行目录**：原始轨迹按侧别命名，例如 `raw = evidence / f'{args.side}-calls.raw.jsonl'`、`assertions = evidence / f'{args.side}-assertions.raw.jsonl'`、网络日志同理。
2. Java 侧既要传系统属性 `-Dmigration.parity.java.output=<assertions>`，也要设同名环境变量 `MIGRATION_PARITY_JAVA_OUTPUT`。
3. TS 侧必须加载 `ts-offline-guard.cjs`、探针与 `capture-parity.cjs`，并检查网络日志为空。
4. 采集结束后调用 `emit-assertion-observations.py`，参数用计划目录里的 `catalog.json`／`mapping.json`／`input-plan.json`、`--side`、`--raw <本侧原始断言轨迹>`、`--run-id $EVIDENCE_RUN_ID`、`--output $EVIDENCE_ASSERTIONS_PATH`，并按侧别加 `--allow-ts-extra`／`--allow-java-extra`。

## 三、并行纪律（必须遵守）

- 任何会写 `metanet4j-bsv-sdk/target` 或运行 Maven／采集的命令，一律 `./lock.sh <命令>`（多代理共享同一目标工程）。
- 只改自己负责的原文件对应的工具与**测试**源码；不得改生产源码、不得删除或放宽既有断言、不得改他人登记项。`full-evidence-locals.json` 只通过 `register-local.py` 改。
- 不修改 `feature_list.json`、`progress.md`、`session-handoff.md`（主代理维护）；不执行 `git commit`／`git push`（主代理统一提交）。
- TS 测试不得真实联网；Java 测试用注入的 mock 客户端。
- 计划冻结时若报“原断言次数多于计划”，按 `prepare-transaction-local.py` 的做法把同一站点第 2 次执行起记为 `<站点>#<轮次>`，`assertionSites` 仍指回原站点。

## 四、验收与汇报

验收（缺一不可）：

1. `./lock.sh python3 recapture-local.py ... --update` 输出 `cases`／`inputsCompared`／`assertionsCompared` 且退出码 0；
2. `./lock.sh python3 local-evidence-gate.py tamper --name <局部>` 输出两个 `true`；
3. 聚焦 Java 测试 `./lock.sh ./mvn.sh -f metanet4j-bsv-sdk/pom.xml clean test -Dtest=<类名>` 通过，失败／错误／跳过为 0；
4. `./lock.sh python3 full-evidence-preflight.py --output .cache/evidence/preflight-<局部>-<日期>.json` 里该 `planValid=true`。

汇报格式：局部名与原文件；用例／输入／断言数；新增或修改的文件绝对路径；上述四条命令的原始输出（可截断但要保留 JSON 行）；未解决项与阻塞。若需要改生产代码或范围外文件，立即停止并说明。
