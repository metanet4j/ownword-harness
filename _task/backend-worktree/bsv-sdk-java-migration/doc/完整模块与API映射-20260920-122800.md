### 已确定的共同约束

1. 工程及包根保持 `metanet4j-bsv-sdk` / `com.metanet4j.bsv`，底层不依赖 base/sdk。TS 类名、公开成员名和模块归属优先保留；自由函数采用模块工具类，具体入口逐项写入 api-map.json。不能仅凭命名规则自动认定已复核。
2. bigint 使用 Java BigInteger 的精确数值能力；上游 BigNumber 仍保留自己的兼容类，不能直接用 BigInteger 替换其公开状态或返回自身的可变操作。TS number、number[]、Uint8Array 分别处理，不能全部转换为 int 或 byte[]。
3. 可省略参数的默认值按源码表达式和求值时机保留。不得把每次新建的数组、Map、对象变成共享静态默认值；缺失、undefined、null 和空值按测试契约区分。
4. Promise 返回接口采用 CompletionStage 表达异步完成，原同步接口保持同步。异常拒绝、回调先后、取消与清理仍要分别复刻，不能只在同步方法外套 completedFuture。
5. 常规 Error 对应 `com.metanet4j.bsv.errors.SdkException`，TypeError 对应其子类 SdkTypeException，RangeError 对应 SdkRangeException；原错误消息、码、字段和触发时机保留。WalletError、ScriptEvaluationError、ScriptResourceLimitError、TransactionEvidenceError 保留各自类型与字段。Java CompletionException 等调度包装只在结果采集边界按已登记规则解包，不能吞掉原始失败。
6. 原测试直接检查 BigNumber/Hash 等内部状态的断言必须保留。优先在同包测试中访问等价状态；不得为了遵从技能的常规封装建议删除这些断言。最终访问方式仍需在逐项映射中登记，不提前给生产 API 增加任意调试入口。
7. 每个 Java 预期来自固定 TS 原断言、原向量或记录的 TS 实际输入输出，不能由 Java 被测实现生成。随机、时钟和环境能力通过后续确定性重放处理；独立探针只用于确认行为，不能充抵上游用例或迁移 PASS 数。

### API-HEX

已复核 `src/primitives/hex.ts` 全文件，并以固定 TS 构建产物执行 8 组实际输入探针，原始结果见 `.cache/evidence/api-hex-observations.json`。这三项是设计映射，尚未实施 Java：

| TS 声明 | Java 对应与行为 |
| --- | --- |
| assertValidHex(msg) | `Hex.assertValidHex(Object msg)`；仅接收 String。null、数值、布尔等非字符串触发 SdkTypeException；非十六进制字符串触发 SdkException；消息均为 `Invalid hex string`。Object 参数用于保留 TS 显式类型校验分支，不先把输入 toString |

| Auth Peer 同步 send 抛错与 Promise 拒绝都会涉及等待者清理；TransactionEvidenceCoordinator 有并发、取消、缓存和上下文变化 | CompletionStage 只解决返回形式，不能替代状态机、时钟、调用次数和顺序的逐项映射 |

Reader 探针的实际值、共享视图和复制结果保存在 `.cache/evidence/api-reader-observations.json`；该探针没有改动 TS 源码，也不是新增 SDK 用例。

AES 的实现选择保留待验证：`AESGCM.ts` 注释声称非标准 padding 会导致 tag 不兼容，但对 12/32 字节 IV、0/1/16/17 字节明文的 8 组实测，纯 TS 与 Node 原生 AES-256-GCM 的密文和 tag 均相同。证据为 `.cache/evidence/api-aes-observations.json`。这只能确认这 8 组结果，不能宣称所有输入兼容，也不能仅凭注释否决 JCA。后续须保留直接 AESGCM 与 SymmetricKey 的平台分支对照；SymmetricKey 使用 32 字节 IV，nativeDecrypt 当前 catch 返回 null，其调用方报 `Decryption failed!`，不能按注释误判成失败后始终回退。
