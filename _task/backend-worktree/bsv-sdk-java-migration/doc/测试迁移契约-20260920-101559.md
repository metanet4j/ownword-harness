# TypeScript → Java 单元测试迁移契约

## 范围与事实来源

用户要求：“java 的所有单元测试一比一复刻 typescript……每一个单元测试都必须通过。无遗漏，无错误。”本契约将该要求作为迁移验收门槛，沿用“只迁移 metanet4j-sdk 需要模块”的原始范围。

上游固定提交以 `../workspace.json` 为准。先盘点 SDK 全部测试文件，再按依赖映射划定所迁移模块；这些模块及实际纳入的依赖能力对应的所有上游测试均须逐项映射。不能因测试困难、失败或实现缺失将其划到范围外。未移植模块须在清单中明确列出理由；不能把全仓测试盘点称为已完成迁移。

测试边界以用户指定的 TypeScript 测试实际调用接口为依据：密钥/签名、编码/哈希、HD/助记词、BSM/ECIES、Script、Transaction/P2PKH/费用等；最终文件与接口清单由实际依赖映射收敛。测试迁移不自行扩展生产模块范围。遇到上游内部实现断言或 Java 无对应接口，必须记录差异并解决接口映射，禁止无声删除断言。

## 一比一的含义

- 每个上游文件、完整 suite/case 名和参数化数据行具有可追踪的唯一标识，关联至少一个明确的 Java 用例；不以总测试数相同代替逐项对应。
- 保留输入、fixture、已知向量、前置条件、正常/边界/异常场景及每一条断言的语义。语言专属类型、异常名称和异步机制通过明确的映射适配。
- 参数化、动态生成、snapshot 与属性测试需单独登记；保留生成器约束、seed/replay 信息和等价断言，不能折成一个弱化的成功用例。
- Java 预期值来自固定上游向量或经执行核对的参考结果，不由被测 Java 实现生成。
- 既有 Java 业务回归用例保留，独立登记，不冒充 TypeScript 复刻用例。新增 Java 行为测试应有上游对应；确有 Java 特有适配时显式标明来源和理由。

## TDD 执行

遵循 [tdd 技能](../../../../.agents/skills/tdd/SKILL.md)：一次处理一个测试行为，先写 Java 测试并确认因目标行为缺失而失败（RED），再完成最小实现使其通过（GREEN），然后验证已完成用例仍通过。不得先批量生成全套测试再补实现。

盘点、读取上游测试、运行已有测试及建立映射不属于新增 Java 测试。当前环境阶段只执行这些准备工作；不能将其作为 Java RED/GREEN 证据。

## 必须满足的验收门禁

1. 固定上游提交与运行清单；比较静态发现、测试执行清单和 Java 映射，解释动态用例、配置排除、skip/todo、only 的每项差异。
2. 迁移范围内未映射、遗漏、重复冒充、未实现均为 0；每个参数化向量和每项断言均有对应。
3. 上游参考用例与 Java 对应测试全部通过；失败、错误、跳过、禁用、todo、未执行均为 0。上游已 skip/todo 的用例仍需记录并解决，不得从分母静默移除。
4. Java 使用 `clean test`，按模块核对 Surefire XML 实际 testcases；不得用 `skipTests`、ignoreFailure、排除失败用例或仅 BUILD SUCCESS 通过验收。
5. 保存固定版本、逐项映射、RED/GREEN 命令及结果、最终报告、fixture 校验信息。断言或测试数量变更必须说明原因；不得为绿色结果放宽预期。
6. 上游自身有错误、冲突或无法稳定复现时，保留失败证据，单列待解决事项；未关闭不得声明迁移完成。

这些门禁用于提供可核验的测试完整性证据；在实际执行与逐项审核之前，不声明“全部通过”或“无遗漏”。
