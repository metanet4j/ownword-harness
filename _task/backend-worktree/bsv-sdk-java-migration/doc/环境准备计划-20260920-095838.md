# BSV SDK Java 迁移环境准备

## 目标与范围

使用 TypeScript `ts-stack/packages/sdk` 作为 Java 按需移植的参考，准备固定版本源码、隔离工具链、构建验证和后续测试复刻所需资料。测试完整性和 TDD 规则统一见[测试迁移契约](测试迁移契约-20260920-101559.md)。本阶段不修改生产 Java/POM，不拆分 Maven 模块。

四个仓库必须以各自的 `feature/java25` 为基线建立迁移分支。本次按该分支的精确 SHA 创建并已核对；分支、路径、提交、工具链和上游版本的唯一记录为 `../workspace.json`。

## 环境组成

| 内容 | 准备方式 |
| --- | --- |
| Java/Maven | 复用既有 JDK 25 与 Maven 3.9.16，使用绝对路径和显式 JAVA_HOME |
| Maven 依赖 | 复用既有 settings，以任务 `.cache/maven` 覆盖 localRepository，避免同版本产物串用 |
| Node/pnpm | 复用本机 Node，在任务 `.cache/tools/pnpm` 安装上游锁定 pnpm，所有入口使用 `../pnpm.sh` |
| TS 源码 | 克隆完整 `reference/ts-stack`，固定 detached HEAD；保留源码、测试、fixture、许可证与 monorepo 共享构建配置 |
| TS 依赖 | 使用上游 pnpm-lock.yaml，过滤 SDK 安装，frozen-lockfile 与 ignore-scripts；缓存位于任务 `.cache` |
| 中间件 | 只读检查共享 `infra/` 的容器、端口和服务版本，不创建新实例 |

Go 不再是本任务环境依赖。已下载的参考副本不作为本轮构建输入。

## 执行顺序

1. 核对四仓起点、分支、Git worktree 路径与状态，保留既有工作区。
2. 克隆 TS 源码，读取相关构建说明，固定提交、包版本与包管理器。
3. 实现环境自检及 Maven/pnpm 入口，确认隔离路径和工具版本。
4. 安装 TS SDK 所需依赖，按原配置构建 SDK，检查上游 tracked 文件无变化。
5. 构建 Java 四仓，执行已确认离线的 SDK 回归测试及 TS 算法冒烟。
6. 盘点上游测试文件、Jest 默认发现范围及排除项，为逐用例映射提供输入；完整映射与 Java RED/GREEN 属于下一阶段。
7. 只读检查共享中间件，汇总实测结果并更新交接。

## 验证与验收

- `../init.sh` 可重复运行：检查任务文件、四仓分支/基线、固定上游、工具与缓存；缺失或不匹配返回非零，不自动安装、联网或启动服务。
- `../verify.sh java-build`：依次 parent `-N install`，base/sdk/component `clean install -DskipTests`；该步骤只证明源码和测试源码编译通过。
- `../verify.sh java-smoke`：SDK `clean test -Dtest=BapDataLockBuilderSignTypeTest`；以 Surefire XML 实际用例为准，失败、错误、跳过均为零。
- `../verify.sh ts-build`：原 SDK build 脚本完整通过，确认 TS 类型与产物能生成。
- `../verify.sh ts-smoke`：HD、Mnemonic、BSM、ECIES、PrivateKey、TransactionSignature 和 P2PKH 算法测试全部通过；本阶段范围由脚本显式列出，不代表全部上游测试通过。
- 上游全量文件清单与 Jest 默认清单分别留存，manual、skip/todo/only 不得静默丢弃。逐用例 Java 映射尚未形成时，不能声称迁移测试完整。
- 宿主只读运行 `infra/status.sh`，记录五个容器、端口与版本。实连集成测试另按上级规则准备与提权。
- 保存原始日志于 `.cache/evidence/`，摘要进入状态文件；全局工具配置及旧工作区保持不变。

## 后续事项

环境验收后进入现有调用与 TS 能力映射，按[测试迁移契约](测试迁移契约-20260920-101559.md)逐条登记。公共 core 模块位置、公开 Java 类型兼容仍须收敛方案后实施。产品/架构事实引用全局[核心认知](../../../system-design/spec/核心认知.md)，本计划只定义环境准备的执行和验收。
