# BSV SDK Java 迁移环境准备

## 目标与范围

响应用户“先建立 worktree。初始化环境，准备迁移所需”：为后续按需移植 Go SDK 建立独立、可复现的准备环境。本阶段不修改生产 Java 源码或 POM，不拆分 Maven 模块。

本次创建 `bsv-sdk-java-migration` 任务目录。四个仓库必须以各自的 `feature/java25` 为基线建立 `feature/bsv-sdk-java-migration` 分支。本次读取原 `boot4-java25-upgrade` 工作区中该分支的 HEAD，并按其精确 SHA 创建；已核对四仓起点均与 `feature/java25` 完全一致。用户本轮建立 worktree 的授权覆盖该任务分支创建；旧分支保持原状。精确提交记录于 `../workspace.json`。

## 准备清单

1. 创建 parent、base、sdk、component 四个 worktree；记录起点并排除根仓重复跟踪。
2. 在 `reference/go-sdk` 获取官方源码，固定前轮核对的提交 `aaa650f810e96349669b625ca68dac896dde8fd1`，保留许可证与 Go 测试向量。
3. 复用既有 JDK 25 和 Maven 3.9.16；根据上游 `go.mod` 选择官方 Go 工具链，下载并校验官方 SHA-256，仅安装在任务 `.cache`。
4. 复用现有 Maven settings，使用任务独立本地仓库。可复制既有第三方依赖缓存，但排除 `com/metanet4j`，由新 worktree 重新构建自身产物。Go 模块和构建缓存同样隔离。
5. 提供环境入口、自检、准备验证命令、固定基线和可续接状态文件。

## 验证与验收

- 四仓分支正确，HEAD 等于记录的基线，工作区干净；旧工作区 HEAD 和分支保持原状。
- Go 源码处于固定提交且无修改；Go 工具链满足 `go.mod`，下载包 SHA-256 校验通过。
- `./init.sh` 可重复运行，检查失败返回非零；不会自动修复环境、联网或启动服务。
- 依次完成 parent 安装、base/sdk/component 的 `clean install -DskipTests`，验证生产源码与测试源码可编译。跳过测试不计作通过测试。
- SDK 执行 `BapDataLockBuilderSignTypeTest` 的离线 `clean test`，逐项核对 Surefire 执行数、失败与跳过。
- 对固定上游的 hash、Base58、BIP32、BIP39、BSM、ECIES 和 P2PKH 包执行离线算法用例；若某包包含外部服务测试，先审查并缩小执行范围。记录逐包结果，不默认运行全仓 Go 测试。
- 记录实际日志和验收摘要；全局工具链链接与既有工作区保持不变。

## 后续事项

环境准备完成后进入现有调用与 Go 能力映射。公共 core 模块位置和公开 Java 类型兼容尚属方案事项，未在本轮落地。参考全局[核心认知](../../../system-design/spec/核心认知.md)；本计划只定义准备阶段的执行和验收。
