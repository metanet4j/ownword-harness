# 钱包契约与钱包 JSON 局部证据刷新

## 范围

把 `migration-impl-wallet-contracts`（6 个原测试文件、253 例）与 `migration-impl-wallet-json`（2 个原测试文件、58 例）的局部证据重新绑定到当前 Java 来源，使其满足“报告绑定验收时提交/工作树”的完成条件。此前这些局部登记仍指向 2026-09-27 的旧采集执行器与旧 Java 版本，被 `full-evidence-preflight.py` 以“运行来源不是当前 capture 执行器产生／运行来源版本与要求不同”拒绝。

## 本轮修正

- 采集执行器版本：旧局部由更早的 `evidence-bundle.py` 生成，`producerSha256` 与当前执行器不同；只能重采，不能用打包参数追认。
- 两侧共用运行目录：`capture-json-byte-side.py`、`capture-brc100-side.py`、`capture-wallet-error-side.py`、`capture-werr-side.py`、`capture-wallet-property-side.py`、`capture-origin-header-side.py` 的原始断言轨迹按侧别改名（`<side>-assertions.raw.jsonl` 等），避免 TS 与 Java 记录混装进同一文件。
- JS 可见错误名：`ParityRecorder.errorName` 现在优先读取异常的公共 `name` 字段。WalletError 与 WERR 系列用该字段保存原 `this.constructor.name`，因此 `toBeInstanceOf`／`toThrow` 的实际错误名与固定 Jest 轨迹一致（此前 `WERR_REVIEW_ACTIONS` 被记成 `Error`，WERR 相关局部因此被逐断言比较拒绝）。
- ValidationHelpers 从专用局部升级为标准双侧局部：新增 `capture-validation-helpers-side.py`，两侧都把原始观察转换成标准行（`runId/side/caseId/sampleId|assertionId/value`），不再依赖 `audit-tests.py` 之外的自定义比较口径。

## 工具

| 工具 | 用途 |
| --- | --- |
| `local-evidence-gate.py verify --name <局部>` | 按登记重跑标准双侧汇总，核对 Jest／Surefire 全绿、用例／样本／断言数与计划一致、两侧运行身份不同 |
| `local-evidence-gate.py tamper --name <局部>` | 在运行目录副本上篡改 Java 输入或断言并同步 manifest 摘要，要求汇总分别以“TS/Java 输入或前置状态不同”“实际结果不一致”拒绝 |
| `recapture-local.py --name <局部> --run <新目录> [--update]` | 在当前版本下重采标准双侧局部；清单、映射与重放语料按登记解析，重采成功后可原地更新登记路径 |

## 重跑入口

```bash
python3 recapture-local.py --name validation-helpers --run .cache/evidence/validation-helpers-formal-<新目录> --update
python3 local-evidence-gate.py verify --name validation-helpers
python3 local-evidence-gate.py tamper --name validation-helpers
python3 full-evidence-preflight.py --output .cache/evidence/full-preflight-<新>.json
```

一次性重采多个局部时逐个执行；每个运行目录只能使用一次，禁止复用已存在的报告。

## 限制

- 其余 41 个标准局部仍绑定旧执行器或旧 Java 版本，`currentCaptureVerified=false`；最终全量运行会统一重采，本刷新不改变这一口径。
- 结构计划仍缺 1301 例，`readyForFullCapture=false`；完整 `audit-tests.py check` 仍须单次双侧全量采集与两端全量适配器。
