# JungleBus Java 25 API 与协议契约

事实依据为固定 `js-junglebus 0.4.4`、隔离安装的 `centrifuge 3.0.1` 和 `fixtures/`。实际基线通过 `./verify.sh baseline`：77 项断言，真实本地 HTTP／WebSocket，JSON／Protobuf × 普通／Lite。原始上游未改动。

## API、模型与配置

工程为独立单模块 `com.metanet4j:metanet4j-junglebus:0.1.0`，包名 `com.metanet4j.junglebus`，分支 `feature/java25`。固定 Jackson 3.1.5、protobuf-java/protoc 4.35.1、JUnit 6.0.3、Compiler 3.15.0、Surefire 3.5.6 和 Protobuf Maven Plugin 5.1.11。版本配置在工程 POM 中维护，不依赖现有后端 parent。

| Java 入口 | 返回与完成语义 |
| --- | --- |
| `JungleBusClient(String server)`／`JungleBusClient(String server, ClientOptions options)` | 构造时不联网，解析主机、端口和 TLS |
| `login(String username, String password)` | `CompletableFuture<Void>`；Token 更新后完成 |
| `setToken(String token)` | 返回设置值；后续 HTTP 与握手使用最新值 |
| `getTokenFromSubscription(String id)` | `CompletableFuture<Void>`；匿名 Token 更新后完成 |
| `getLastError()` | `Optional<JungleBusException>`；最近失败，成功不自动清空 |
| `connect()`／`disconnect()` | `CompletableFuture<Void>`；前者握手成功，后者本地断开并停止自动重连 |
| `subscribe(String id, long fromBlock, SubscriptionOptions options)` | `CompletableFuture<JungleBusSubscription>`；全部要求通道确认后完成 |
| `getTransaction(String id)` | `CompletableFuture<Transaction>` |
| `getBlockHeader(long height)`／`getBlockHeader(String hash)` | `CompletableFuture<BlockHeader>` |
| `getBlockHeaders(long from, int limit)`／`getBlockHeaders(String from, int limit)` | `CompletableFuture<List<BlockHeader>>`；limit 1–10000 |
| `getAddressTransactions(String address)`／`getAddressTransactionDetails(String address)` | `CompletableFuture<List<Address>>`；未知字段保存在可读取的 extras 中 |
| 订阅 `subscribe()`／`unsubscribe()` | `CompletableFuture<Void>`；重启要求通道／本地旧一代失效后协议取消 |
| 订阅 `getCurrentBlock()` | 服务端 BLOCK_DONE 报告高度，初始为 fromBlock；不表示调用方提交点 |
| 订阅 `getResumeFromBlock()` | 可持久化的保守重放起点；本期固定为原始 fromBlock |
| 两个对象 `close()` | 幂等本地终止，不等待调用方业务 future；关闭后无法重启 |

`Transaction`、`BlockHeader`、`Address`、`ControlMessage`、连接上下文使用 record；所有原字段有明确 camelCase 读取入口，HTTP 和协议名称仍按原样解析。uint32 使用 long，uint64 使用 BigInteger。缺失的可选高度／整数取 0，字节正文／证明取空串，未知字段保留。订阅正文与证明是小写 hex；REST 交易正文保持服务端原值，不猜测编码。

`ClientOptions.builder()` 配置 protocol、useSSL、token、debug、超时、重连、消息与 HTTP 上限以及连接事件处理器；默认 JSON，TLS 按 scheme 推断，无 scheme 默认 TLS。连接／请求超时 5 秒，心跳余量 30 秒，重连带抖动从 500 毫秒到 20 秒。HTTP 单响应和单 WebSocket 消息最多 16 MiB，可配置；并发 HTTP 最多 4 个，配置实例的原始 HTTP 在途容量由并发数 × 响应限制限定。读取流有界，禁止 ofByteArray 无界聚合。

`SubscriptionOptions.builder()` 配置 onPublish、onMempool、onStatus、onError 和 liteMode。前三个处理器使用 `Function<T, CompletionStage<Void>>`，允许用 `CompletableFuture.completedFuture(null)` 包装同步逻辑；同步抛错、返回空 stage、异常完成均报告并停止订阅。错误处理器使用 Consumer，不进入业务队列。

公开状态通过 `getState()` 和区块／控制／Mempool 的订阅布尔查询读取，不暴露可写内部 Centrifuge 对象。客户端状态为 DISCONNECTED、CONNECTING、CONNECTED、CLOSED；订阅为 UNSUBSCRIBED、SUBSCRIBING、SUBSCRIBED、PAUSED、FAILED、CLOSED。

## 固定协议与已核实差异

外层 schema 来自隔离 npm 包的 `build/protobuf/client.proto.json`，完整定义保存在 fixtures；SHA-256 见 wire.json。字段定义转为 proto3 后必须逐字段比对，生成完整外层消息类型，运行时只实现本 SDK 实际使用的命令。

JSON 为一行一条消息；Protobuf 为 varint 长度前缀，可在一帧中批量发送。WebSocket 的 Protobuf 握手同时设置 `centrifuge-protobuf` subprotocol 和 `?format=protobuf`。application data 在 JSON 中是对象，在 Protobuf 中是内层业务 bytes。

原 SDK 的 Protobuf pause／start 直接传入 JS 对象，实际编码为零长度 bytes。最小实际编码实验已确认。本实现明确修正为 UTF-8 JSON bytes，例如 `{"cmd":"pause"}`；fixtures 同时记录差异和预期帧，不能复刻空命令。

首次连接按上游调用 GET `/v1/user/refresh-token`，读取当前 token 请求头，取得连接 Token 后握手。connect reply 的 expires／ttl 驱动 HTTP 刷新和 refresh 命令；code 109 强制刷新。并发刷新合并，setToken 与旧刷新响应竞争时旧响应不能覆盖新设置值。

连接／订阅错误 code <100、temporary=true 或 code 109 属于可重试；永久权限／参数错误停止相应操作。disconnect code 位于 [3500,4000) 或 [4500,5000) 时不重连；WebSocket close 的 JSON reason 中 reconnect 优先作为关闭建议。1009 表示消息过大，停止重连。unsubscribe push code <2500 为永久取消，其他值重新订阅。原库在无连接时延后订阅，订阅确认超时会重建连接。

recoverable subscribe reply 提供 epoch／offset；重新订阅同一通道可携带 recover、epoch、offset。Java 仅在对应业务处理成功后提交各通道 offset，避免上游在回调未完成时推进 offset 的数据风险。恢复失败时区块订阅退回原始 fromBlock；Mempool 报告历史可能缺失。本期不自行推断区块完整性，不推进持久化高度。REORG 报告给处理器并保持原始重放起点，业务数据回滚由调用方负责。

至少一个区块或状态处理器时，区块和控制通道成对建立；仅状态模式内部解析交易但不补取正文。仅 Mempool 模式只有 Mempool 通道；同一客户端不得重复使用同一订阅 ID，避免共享通道重叠。Lite Mode 不补取正文，控制通道始终是 query 前缀。

## 队列、取消与资源

区块及非错误控制事件共用串行队列，Mempool 独立串行。每队列默认条数高水位 20000、低水位 10000、硬上限 40000；估算字节高水位 64 MiB、低水位 32 MiB、硬上限 128 MiB。估算涵盖输入、解码及 hex 膨胀，单帧及 HTTP 补取另外有界；这些是数据容量限制，不承诺 JVM 总堆精确等于预算。

区块达到高水位后发送 pause；两种计量均低于低水位后按 2 秒检查发送 start。命令结果失败报告并重建连接，从未提交 offset 或原始起点恢复。硬上限停止该订阅并报告，禁止静默丢弃；Mempool 上限停止并报告无法保证补回。控制回复与心跳不等待业务队列，接收缓冲自身也有上限。

取消先使旧一代失效、释放队列和定时器，再发送协议取消；成功完成后不再为旧一代取得新的回调执行许可。已取得许可的回调属于在途调用，可以结束，但不推进新一代进度。取消不等待业务 stage；回调可以返回 unsubscribe future，控制线程不得因此阻塞。断线时取消在途等待并重新排队恢复，允许重复；旧完成不能提交 offset。超时取消使该 future 失败并重建连接，避免服务端残留通道。close 终止 SDK 自有调度器、工作线程、HTTP 与 WebSocket，不关闭调用方注入的资源。

## 验收与未验部署事实

J01 的五项本地门槛已形成可执行 API、固定帧、恢复与取消反例、资源默认值和 REST 字段保留契约；实际 JS 基线和原始样本支持进入 J02。后续 Java 测试须重放这些样本，并验证在途回调失败、异步取消、回复乱序、分片和超限。

目标部署的实际版本、地址详情额外字段、REST 字节编码、/bin 鉴权、重放包含边界及块完成保证仍待线上证据。保留上游请求行为、未知字段与保守重放可继续本地迁移；不能将本地模拟通过描述为线上兼容验收。
