# JungleBus Java 25 实现计划审查

审查对象为[实现计划](实现计划-20261013-110456.md)，依据为固定的本地 `reference/js-junglebus`、依赖锁文件及后端工程规则。

结论：可以启动 J01 契约验证；当前尚未满足 J02 编码入口。原计划的范围与阶段顺序基本合理，但一处通道方案缺少依据，协议完整性、安全游标、取消语义和验收边界还需具体化。本次已修正通道方案并将其余事项写成进入 J02 的检查条件，尚未取得实际 J01 验收证据。

## 审查发现

| 编号／级别 | 问题与影响 | 依据与当前处理 |
| --- | --- | --- |
| R01／P1 | 只传状态处理器时，原计划只建立控制通道。控制事件是否由区块查询驱动没有服务端证据，可能形成“订阅成功但没有进度”的行为 | 上游客户端始终传入交易包装函数，底层因此也创建区块通道；最小实验确认。计划已改为区块与控制通道成对建立，仅状态模式不补取交易正文；服务端是否允许进一步减少通道待 J01 验证 |
| R02／P1 | 安全游标只写“更早高度”，未定义计算和对外读取方式。若调用方持久化 getCurrentBlock，再按该高度重启，仍可能跳过未完成回调；固定回退一个块也不能覆盖积压多块 | subscription.ts 在收到 BLOCK_DONE 时立即写 currentBlock，最小实验确认前序交易可仍未处理。计划已要求定义安全重放起点、持久化读取和反例；块边界未证实时从原始 fromBlock 重放，接受明确的重复与带宽成本。J01 契约尚待完成 |
| R03／P1 | 自实现外层协议的范围不能只按四个业务文件确定。连接恢复、服务端推送、错误重试等实际委托给 centrifuge 依赖，遗漏会改变订阅行为 | index.ts 创建 Centrifuge 并调用 newSubscription，yarn.lock 固定 3.0.1。本次未安装该依赖，不能宣称已清点其全部行为。计划已要求 J01 读取固定依赖，清点自动恢复及帧编码，记录 schema 来源和依赖版本 |
| R04／P2 | 取消与 close 的完成边界不明确。等待业务回调结束再完成取消，可能在“回调返回 unsubscribe future”时互相等待；旧回调也可能推进重建后的游标 | 计划同时要求串行状态入口和等待 CompletionStage，但原先未说明两者的隔离。已补入控制入口不等业务回调、取消后不启动旧回调、旧一代完成失效及资源所有权规则；J01 定义细节，J05 验证 |
| R05／P2 | “明确容量上限”只有条数思路，没有字节限制；大交易和 hex 膨胀可在达到 20000 条前耗尽内存。控制和回复也不能随业务队列一起阻塞 | 订阅含 transaction／merkle_proof，普通模式还会补取正文。计划已要求 J01 给出计数／字节限制、默认水位、在途与补取预算及超限动作；J05 验证 |
| R06／P2 | J01 要求关键待确认全部有结论，同时又允许没有账号时继续本地验证；原文本没有区分本地开工条件与部署兼容条件 | 已分成五项本地进入 J02 条件及线上待验项。模拟服务可以证明实现对指定样本的行为，不能证明目标部署的字段、权限和顺序保证；J06 的交付标签必须反映实际证据 |

P1 表示需要明确处理的重大风险，P2 表示应在相关实现前补齐的契约。表中“已修正／已补入”仅表示计划文字已处理，不表示相关功能或测试已通过。

## 本次证据

重新读取四个本地源码文件及原计划，核对 12 个客户端方法、3 个订阅方法、三类通道、业务 Protobuf 字段、Token 请求及许可证边界。通过 `git -C reference/js-junglebus status --short`、`git rev-parse HEAD` 核对参考源码仍干净且与来源锁定一致。

运行 `node <<'JS' ... JS`，使用 Node 标准库读取原始源码，提取实际 Subscribe 方法、包装回调和控制消息处理方法；仅为控制方法去掉两处 TypeScript 类型语法，注入假的通道和队列以隔离外部服务。三项断言及输出为：

```text
状态处理器单独传入时，上游客户端仍创建通道：mempool, control, block
上游交易包装回调已完成，但调用方异步处理仍未完成。
BLOCK_DONE 已将报告高度推进到 101，前序交易仍在队列中等待处理。
3 项源代码最小实验通过；未验证真实服务跨通道顺序。
```

这些实验确认业务源码的局部行为，没有运行完整 Centrifuge、真实 WebSocket、Protobuf 编解码或 Java 实现。模拟注入不能证明服务端需要区块通道、块完成顺序或可恢复性；计划在没有这类证据时保留上游查询通道并采用保守重放规则。

文档检查包括本地引用、API 映射数量、阶段完整性和 `git diff --check`。本轮尚未进行 J01 的依赖安装、完整 JS 基线或 Java 编码。
