# 圣经（和合本）

《圣经》和合本经文的抓取结果，来源 <https://cmcbiblereading.net/>（《圣经综合解读》备份站）。旧约 39 卷 929 章、新约 27 卷 260 章，共 **1189 章 31101 节**。

经文采用香港圣经公会的新标点和合本，与《圣经综合解读》每章开头逐节列出的经文一致。本目录**只收经文**：逐节注解、祷读、朗读音频都没有抓，也没有搬运任何图片。

抓取、转换与排版流程见[上级说明](../README.md)，全书章节目录与来源 URL 见 [manifest.json](manifest.json)。

## 结构

| 文件 | 说明 |

## 与前面几本书不同之处

**一本书装 66 卷。** manifest 用 `part` 区分旧约／新约，`category` 是卷名，`title` 是「创世记 第1章」；slug 取正典序号 + 英文短名 + 章号（`01-genesis-001`），全 ASCII，`ls`、EPUB 与阅读器排序都按正典顺序。

**经文模式。** manifest 里 `"site": {"verses": true}` 让 `convert.py` 走经文模式：每节一行「节号 + 经文」，不生成小标题、分类行与音频引用。站点把整节包在「」里，转换时剥掉这一层，节内对话的『』与「」保留。

**源站有四种瑕疵，都已在解析里处理。**

| 情况 | 例子 | 处理 |
| --- | --- | --- |
| 两节并成一段 | `【创廿四29~30】「…」` | 输出一条「29–30」，全书 68 处；HTML 里两节各有一个锚点 |
| 一节排成两段 | `【路六18】… 【路六19】…` 在同一段 | 按标记切成两节 |
| 标记断字 | `【创廿四2⏎e84a⏎3】`、缺前括号、整节没有起始「 | 去掉字母与空白后重拼节号 |
| 源站缺排 | 民数记 16:26、历代志上 22:2 | 记进 `manifest.json` 的 `source_gaps`，校验时放行 |
| 分节并入下一章 | 约翰福音 7:53 的「于是各人都回家去了…」在源站并入了 8:1 | 内容不丢，第 7 章止于 52 节，8:1 是两句话合排 |

另外约翰三书在源站被分成 15 节、启示录 12 章被分成 18 节（和合本按批判文本分节，比钦定本各多一节），所以全书 31101 节：和合本参考 31104 节减去源站缺排 2 节、再减去并入 8:1 的约 7:53。

**抓取通道。** 站点挂在 WordPress.com 上，带 SNI 的握手会被中间设备直接回 403，`fetch_bible.py` 因此先走「不带 SNI、按 Host 头路由」的通道，再退回普通 HTTPS。边缘节点还会在 `Content-Length` 与 `chunked` 之间切换，不按分块解码会把长度头混进正文、个别节随机丢失，所以响应要还原分块、核对长度与 `</html>`。目录页里还有未编码的中文、`2deb9` 式断字符与坏掉的主机名，抓取前统一修补。3 并发约 21 分钟抓完，已落盘的章节自动跳过。

## 阅读与跳转

HTML 阅读版把每章、每节都做成锚点，四个入口都能跳：

| 入口 | 行为 |
| --- | --- |
| 目录 | 旧约／新约 → 66 卷折叠 → 章号网格；点卷名展开该卷章号，每格标着「第 N 章 · M 节」 |
| 搜索 | 搜经文原文（如「耶稣哭了」）、卷名（如「出埃及」）、章号（如「11」）或精确引用（如「约11:35」「创1:1」），命中列成结果，点一条直接落到该节 |
| 章首「‹ 上一章 · 目录 · 下一章 ›」 | 前后相邻章节 |
| 章首「第 [ ] 节 跳转」 | 输入节号跳到本章该节，旁边显示「共 N 节」；节号不存在时输入框闪一下提示 |
| 节链接 | 每节都有 `#v1008_35` 形式的短锚点（`v` + 全书第几章 + `_` + 节号），节号本身也是链接；直接在预览里打开也能定位 |

并节的段落（如创世记 24:29–30）显示成一条，但 29 与 30 各有锚点，跳到 30 也会落在这一段。

### 搜索为什么在预览里不能用

搜索、字号、主题、书签这些都要执行 JavaScript，而 iPhone「文件」App 的快速查看不执行脚本，所以搜索框在预览里是隐藏的、点了没反应。

预览里能用的按节跳转改用原生链接实现：静态 HTML 在每节行首写一个 `<span id="v1008_35">`，锚点不依赖脚本，`file://` 打开也生效。节号用的是短 id（`v` + 全书章序号 + `_` + 节号），31,101 个锚点只占 780 KB；早先用 `v-01-genesis-001-1` 这种长 id 时同一份内容要多出近一倍标记。

### 目录为什么不逐章平铺

66 卷 1189 章平铺成列表要滑很久才能找到目标。现在目录只有 66 行，每行是一卷，展开后是章号网格（手机上约 7 列，一屏能看完一卷 50 章）。展开用原生 `<details>`，不需要脚本；有脚本时还会自动展开当前章所在的卷并高亮当前章。

### 抽屉不需要脚本

窄屏抽屉用 CSS `:target` 打开：顶栏那个菜单是个 `href="#sidebar"` 的锚点链接，点它浏览器就把 `#sidebar` 设为当前目标，`:target` 规则让侧栏滑出；关闭链接指向 `#close`。遮罩用 `body:has(.sidebar:target)`，浏览器不支持 `:has()` 时只是没有遮罩，抽屉本身正常。有脚本时会换成那套带滚动锁、当前章定位的 `class="on"`，两者互不干扰。

### 每章节数

每章标题下静态写着「共 N 节」，不执行脚本也能看到；脚本接管后隐去这行，改在跳转框里显示同一个数字，避免重复。

### 体积

单文件 5.3 MB，其中经文文字 4.0 MB、静态节锚点 780 KB、目录 167 KB。做法是静态 HTML 里经文按「一行一节」存放，行首放一个短锚点；`<p>`、节号链接与章首跳转框由页面脚本在加载时生成（脚本会把静态锚点搬进新段落，链接因此始终有效）。

## 校验

```bash
cd _task/book-scrape
python3 lib/fetch_bible.py "圣经-和合本-bible" verify     # 章数、节号连续性、合并段
python3 lib/fetch_bible.py "圣经-和合本-bible" audit      # 与独立分节数据逐章比对（需 pythonbible）
python3 lib/verify_book.py "圣经-和合本-bible"            # 逐节核对 Markdown 与 Word
```

- 章数 1189/1189，节数 31101，合并段 68 处，`source_gaps` 2 处
- 逐节核对节号：每章从 1 起连续覆盖到末节，除上表两处缺排外无缺口
- 与独立分节数据（`pythonbible`，钦定本分节）逐章比对，只有 3 章不同：约 7 少 1 节（并入 8:1）、约三多 1 节、启 12 多 1 节，与上表说明一致，其余 1186 章完全吻合
- Word 35,871 段、1,139,139 字符，Markdown 与 Word 均无缺失节
- 总目录 1189 条链接全部有效
- HTML：1189 个章节锚点、31,101 个静态节锚点（并节末节另有锚点），id 无重复；深链接 `#v1008_35` 在浏览器与无脚本预览里都能定位到「耶稣哭了」；搜索「起初」命中 37 处、「约11:35」直达该节
- 抽查：创世记 1 章 31 节、诗篇 117 篇 2 节、诗篇 119 篇 176 节、约翰福音 11 章 57 节、启示录 22 章 21 节，与和合本分节一致
