## 问题与证据

### 01 · P1：同一身份在不同入口显示不同资料

- 操作：编辑“我的身份”，将名称从 Maya Chen 改为 Review Maya，经模拟钱包批准；从数字 ID 165 进入 Artifact，再打开关联身份。
- 实际：“我的身份”显示 Review Maya；Artifact 的关联身份摘要及其公开身份页仍显示 Maya Chen，BAP ID 完全相同。再次进入可复现。
- 影响：用户不能确定更新是否生效、资产是否关联了正确身份。违背确定性、一致性及关系可感知原则。
- 原因：`artifact-detail.jsx` 的关联摘要和 `ArtifactPublicIdentity` 直接读取 `OwnwordModel.fixtures`，没有使用更新后的 Profile。
- 建议：所有当前身份展示按 BAP ID 读取同一 Profile 数据源。历史签名和历史发布资料需要快照时单独标明。
- 验证标准：修改名称、头像和简介后，从我的身份、数字查找和 Artifact 关联入口打开同一 BAP ID，当前资料一致。
- 证据：[已更新身份](evidence/review-20260919/28-profile-updated.png)、[旧关联名称](evidence/review-20260919/29-stale-associated-name.png)、[旧公开资料](evidence/review-20260919/30-stale-public-profile.png)。
- 第二次复现：[输入新名称](evidence/review-20260919/issue01-step2.png)、[更新成功](evidence/review-20260919/issue01-step3.png)、[关联摘要未同步](evidence/review-20260919/issue01-step4.png)、[公开身份未同步](evidence/review-20260919/issue01-result.png)。数字 ID 查找结果也读取固定资料，见 `artifact-find.jsx:13`。

### 02 · P1：关联待核实时，同时宣告“当前没有关联身份”

- 操作：将 165 的 Ownership & association facts 设为 Temporarily unable to verify，应用样例后，从“我的身份”打开 Review association。
- 实际：详情顶部显示 No identity currently associated；下方又显示 Association needs verification，并明确没有确认失去所有权。页面仍提供 Remove association，说明原关联记录并未消失。
- 影响：把未知状态表达为空状态，可能促使用户误以为关联丢失而进行移除或替换。违背核心认知第 9.4 节及 PRD A08-B。
- 原因：`M.binding()` 只返回验证有效的记录，详情将没有返回值统一解释为无关联，未区分记录不存在与记录待核实。
- 建议：保留上次关联身份和观测信息，标注“关联待核实”，将重试作为主操作；确认无关联时才展示空状态。
- 验证标准：服务不可用、转移后待核实、确实无关联分别展示准确且互不矛盾的状态。
- 证据：[待核实详情](evidence/review-20260919/35-unverified-artifacts-320.png)、[重试恢复关联](evidence/review-20260919/35-unverified-retry.png)。
- 同类位置：[选择器仍显示 Not linked](evidence/review-20260919/36-selector-unverified.png)；但随后确认页仍显示替换旧编号 165，见[关联确认](evidence/review-20260919/37-binding-review.png)。重复应用待核实场景可再次复现，见[复现截图](evidence/review-20260919/issue02-repeated.png)。

### 03 · P2：发布校验错误出现在首屏之外，点击后看不到反馈

- 操作：320×780 下新建空草稿，点击 Review publication；重复点击结果一致。
- 实际：页面停在原位置，焦点仍在提交按钮，错误 Write something before publishing. 位于视口坐标 y=1019，超过 780px 屏高。未修改的修订也使用同一错误区域。
- 影响：用户看见按钮没有推进，却看不到原因。违背操作反馈与错误恢复要求。
- 建议：在提交操作附近显示校验摘要，并将相关编辑区与错误关联；必要时滚动到错误。不要只依赖屏幕阅读器能读到的 `role=alert`。
- 验证标准：空正文、超限、未修改修订、导入失败在当前视口给出可见反馈和恢复动作。
- 证据：[点击后的实际视口](evidence/review-20260919/42-empty-editor-error-viewport.png)、[含错误的完整页面](evidence/review-20260919/42-empty-editor-error-full.png)。代码：`content.jsx:116`、`content.jsx:167`。

### 04 · P2：钱包已连接，内容入口仍把连接作为主操作

- 操作：进入 `#/content`，选择 New identity 场景，连接并批准钱包。
- 实际：页脚已显示 Connected，正文仍突出 Connect Wallet；再次点击继续弹出连接授权。真正需要的身份设置藏在次级 My Identity 按钮之后。
- 影响：用户容易重复连接，不能从主操作判断下一步是完成身份设置。Wallet 与 Identity 状态在入口上被混为一谈。
- 建议：按未连接、已连接但未发布、资料待补全分别分流；后两种状态直接提供“设置身份”或“补全资料”。
- 验证标准：新身份从内容深链接进入后，完成连接即进入设置或显示唯一明确的设置主操作。
- 证据：[已连接却继续要求连接](evidence/review-20260919/56-connected-content-gate.png)、[首次同类状态](evidence/review-20260919/52-after-connect-new.png)。代码：`content.jsx:164`。

### 05 · P2：手机编辑器的辅助操作挤占正文首屏

- 实际：320×780 的英文编辑器中，正文区域从约 y=562 开始。返回、草稿标题、保存状态、导入导出、发布检查、格式、视图和说明连续占据约 490px；首屏留给正文约 218px。
- 影响：写作这一主要任务被辅助操作挤压，短文也需要频繁滚动；屏幕键盘弹出后的空间还需进一步实机验证。
- 建议：移动端将导入导出收入一个菜单，收起可视化模式说明，减少重复标题与返回区的留白；保留必要格式和发布入口。
- 验证标准：320/390px 下打开草稿能直接辨认并编辑正文，辅助操作仍可找到，不降低触控尺寸。
- 证据：[320px 编辑器全页](evidence/review-20260919/18-editor-320.png)、[首屏截图](evidence/review-20260919/42-empty-editor-error-viewport.png)。代码：`content-editor.jsx:88` 起的编辑器头部与工具区、`content.css` 的移动端布局。

### 06 · P2：多个复制按钮缺少明确的目标名称

- 实际：Artifact 凭证页的 Inscription ID、Ordinal Number、Origin、Current Outpoint、详情链接、TxID 与签名者地址，按钮大多都叫 Copy full value。键盘逐个 Tab 或通过辅助技术列出按钮时，无法仅凭名称区分目标。
- 影响：协议标识容易复制错；长行两端分别放值与按钮，也增加视觉追踪成本。
- 建议：无障碍名称包含具体字段，如“复制完整 Origin”“复制签名者地址”；让按钮与字段有明确语义关联，短值的复制入口尽量紧邻值。
- 验证标准：只听按钮名称即可判断复制对象，复制内容仍为完整原值。
- 证据：[凭证页](evidence/review-20260919/08-proof.png)。代码：`artifact-detail.jsx:6` 的统一 `copyLabel="artifactCopyFull"`、`components.jsx:185`。
- 边界：这是人工发现的可用性问题，不能表述成 axe 已检测到的违规；本轮没有使用真实屏幕阅读器。

### 07 · P2：编辑器标题选择器未继承绑定 S2 的视觉状态

- 实际：浅色编辑器的 Heading 为白底、直角、细边框的原生选择框；深色变为另一种原生灰色框。相邻格式按钮与模式切换使用 S2 外观，两套控件视觉明显混杂。
- 对照：绑定版本官方 `Picker.tsx:176` 的触发器使用 `control`、`fieldInput`、`focusRing`，默认无普通边框，背景有 gray-100/gray-200 开闭状态；`style-utils.ts:244` 定义控制尺寸对应圆角。当前 `content-editor.jsx:90` 使用原生 `select`，`s2-adapter.css:32` 附近仅补高度、字体、颜色和最大宽度，未实现同一外观状态。
- 影响：控件层级、表面、圆角和展开反馈脱离周围设计系统。
- 建议：采用绑定版本的 Picker 表达，或在可维护的适配层补齐经过核对的视觉与状态；不直接改生成 bundle。原生 HTML 本身不是缺陷，问题是可见差异与缺失状态。
- 验证标准：浅深主题下与同尺寸 S2 控件一致，键盘选择、焦点、禁用状态保留。
- 证据：[浅色编辑器](evidence/review-20260919/18-editor-320.png)、[深色编辑器](evidence/review-20260919/25-editor-dark.png)。

### 08 · P3：任务标题的字号与表达方式跨页面跳变

- 实际：我的身份、我的 Artifact、我的内容使用紧凑无衬线任务标题；创建、转移、发布检查使用更大的衬线标题；身份编辑和查找又以 A little more you.、A number. An identity. 为主标题。
- 影响：连续任务的视觉节奏变化较大，部分主标题优先表达品牌语气，需要再读辅助文字才能知道任务。
- 建议：为工作区、操作表单、确认页建立清晰的标题层级；任务名做主标题，品牌语句集中在欢迎页或独立公开展示区。保留内容正文的衬线排版。
- 证据：[身份工作区](evidence/review-20260919/02-identity.png)、[Artifact 创建](evidence/review-20260919/13-create.png)、[查找](evidence/review-20260919/31-find.png)、[资料编辑](evidence/review-20260919/26-edit-profile-dark.png)。
- 性质：视觉优化建议；不把衬线字体本身判定为违反 S2。

### 09 · P3：Artifact 筛选帮助入口与说明对象距离过远

- 实际：钱包持有、历史筛选位于左侧，About this association 帮助图标独立贴在整行最右端。选择器无 Current 时还出现第二个同名帮助入口。
- 影响：桌面上看不出图标究竟解释历史筛选、资产资格还是 Current 关联；同名入口进一步削弱对象关系。
- 建议：把帮助放到对应标签旁，按说明内容命名，如“关联历史说明”；共用内容只保留一个明确入口。
- 证据：[桌面列表](evidence/review-20260919/05-artifacts-loaded.png)、[选择器](evidence/review-20260919/36-selector-unverified.png)。代码：`artifact-components.jsx:48–49`。
- 性质：关系和信息架构优化建议，点击能力本身可用。

### 10 · P3：内容摘要将相邻列表项直接拼接

- 实际：默认草稿摘要出现 `words.Make` 和 `visible.Leave`，各列表项之间缺少空格。
- 影响：列表阅读不顺，降低内容展示精细度。
- 原因：`markdown-tools.mjs` 的文本提取在列表节点内部直接拼接子节点，外层摘要空格无法补回内部的列表项边界。
- 建议：区分块级节点和行内节点，列表项、段落之间补分隔空格；保留行内强调、链接本来的连续文本。
- 验证标准：列表、嵌套列表和多段落摘要可读，不插入破坏行内词语的空格。
- 证据：[默认内容列表](evidence/review-20260919/16-content-loaded.png)。代码：`content-model.js:6`、`markdown-tools.mjs:48` 及同文件 `plain()`。
