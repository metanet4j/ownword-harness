# ADR-002：交易执行统一由 Yours Wallet 完成

> 日期：2026-11-19。**用户已确认方向**；代码调整与验收状态仍为 needs-review。

## 背景

OwnWord 现有代码在两处构造和签名交易：

- **前端** `ownword-web` 直接依赖 `@bsv/sdk` 2.8.6、`@1sat/actions`、`@1sat/templates`，在 `lib/domain/protocol.ts`、`lib/content/protocol.ts`、`lib/domain/publish.ts` 等 16 处构造 `Script`、拼装 `B + MAP + AIP` 输出、解析 `Transaction`。
- **后端** `metanet4j-api-ownword` 依赖同级仓库 `metanet4j-bsv-sdk`，`IdentityProtocol`、`PostProtocol`、`AvatarProtocol`、`ContentApi`、`IdentityApi`、`TransactionSyncApi` 六个类 import `com.metanet4j.bsv.*` 做交易解析。

`metanet4j-bsv-sdk` 是 `@bsv/sdk` 2.7.1 的 Java 移植，8.4 万行。它与前端使用的 2.8.6 是两份独立实现，同一套 `B/MAP/AIP` 编码在两处各写一次。

用户明确：**交易部分全部由 Yours Wallet 完成，前端不应直接用 `@bsv/sdk`。**

## 决策

1. **交易执行归属于 Yours Wallet。** 构造、签名、广播、回执由钱包完成；OwnWord 不自行构造交易，也不持有签名密钥。
2. **前端不直接使用 `@bsv/sdk` 构造交易。** `@bsv/sdk` 只保留类型定义用途（如 `WalletInterface`、`Transaction` 类型）；`Script` 构造、`B/MAP/AIP` 拼装改为调用钱包 API。
3. **后端保留三项能力，不承担交易执行：**
   - 只读查询与投影（`api-ownword` 当前形态）；
   - 独立验签复核（`AipHelper.verifySign`），用于校验钱包签名归属，不信任单一来源；
   - 交易解析（从 rawTx 提取 `B/MAP/AIP`），用于建立内容索引与身份投影。
4. **后端 `metanet4j-bsv-sdk` 的职责收窄为解析与验签。** 不用于构造待签交易、不转发私钥、不代替钱包广播。

## 结果与成本

收益：交易构造与签名只有一份实现，消除前后端两份 `B/MAP/AIP` 编码漂移的风险；OwnWord 不接触密钥，符合[核心认知 §10.1](../核心认知.md#101-安全与权限)「平台禁止获取 Private Key」。

成本：前端需要把现有 `Script` 构造逻辑改为钱包 API 调用，`lib/domain/protocol.ts`、`lib/content/protocol.ts` 的编码函数需重写；`OwnWord` 自有协议扩展字段（`ownword.revision`、`ownword.rootTxid`、`ownword.previousTxid`）需要确认钱包 API 是否支持传入自定义 MAP。

## 验证与生效边界

- 前端 `@bsv/sdk` 的使用范围需按用途审计：类型引用可保留，交易构造需移除。
- 钱包 API 是否支持 `B + MAP(app=ownword,type=post) + AIP` 的完整自定义编码，需以实际调用验证；不支持时本决策需重新评估。
- 后端验签与解析能力保留，不因本决策删除 `metanet4j-bsv-sdk`。
- 与[核心认知 §5.2](../核心认知.md#52-接口边界)「业务组件 → 领域接口 → Adapter」的对应关系仍需确认：`WalletProvider` 是唯一交易入口。
