# OwnWord 限界上下文映射（v0.4.0 目标）

> 状态：needs-review。产品事实见[核心认知 §5](../核心认知.md#5-结构)；本文只明确 DDD 上下文职责和协作。前后端可以分别实现这些上下文，不要求同名目录或独立微服务。

## 1. 上下文职责

| Context | 领域责任 | 权威能力/依赖 | 对外发布的语义 |
| --- | --- | --- | --- |
| Identity | BAP 身份及签名密钥历史、公开资料读取 | Wallet 的签名结果 + BAP 公共验证 | BapId、IdentityResolution、VerifiedIdentityProof |
| Artifact | 1Sat 资产、Origin/编号、ownership、Current Binding | Indexer / Ordinal 验证器 + Identity 身份归属证明 | ArtifactSummary、CurrentBinding、OwnershipProof |
| Content | Post、Draft、发布及 Revision | Identity 的可验证作者归属 + 链上内容 | AuthorBapId、PublishedPost、RevisionGraph |
| Relationship | Follow / Friend 的公开关联及派生状态 | 双方 BAP ID 与各自签名记录 | 公开关系与 coverage |
| Explorer | ID 精确查询与公开主页读模型 | Identity、Artifact、Content、Relationship 的查询 | 只读聚合，不反向修改它们 |
| Wallet | 会话、权限、签名与交易提交 | 用户钱包，主要在客户端 | 钱包能力和操作回执 |
| Blockchain / Indexer | 原交易、签名/链序、编号与重组证据 | Bitcoin 与可重建索引 | 带来源、覆盖和时点的 Observation |

## 2. 跨上下文约束

- Content 的作者、Relationship 的端点均使用 `BapId`；Artifact 的数字 ID 要先解析资产，再核验 `IdentityNFTBinding`，不能直接替换 BAP ID。
- Identity 聚合不持有可变的 NFT Binding；Artifact 上下文负责历史/当前关联与双向唯一性，Identity 首页仅读取有效 Current 的摘要。
- Wallet Connection 不能充当 BAP 身份或已授权身份签名；所有链上操作逐笔满足[核心认知 §6.4](../核心认知.md#64-全部链上交易的身份归属)。
- 区分客户端意图、Wallet 授权回执、后端同步、已验证链上事实和 UI 展示。任何阶段失败不能推断其他阶段不存在或成功。
- 领域上下文之间通过稳定 ID、Proof、DTO/公开端口协作；UI 路由参数、来源不完整的缓存及数据库记录不能提升为权限或全局事实。

## 3. 协作方向

~~~mermaid
flowchart LR
    W["Wallet（客户端）"] -->|"授权/交易回执"| I["Identity"]
    W -->|"资产操作"| A["Artifact"]
    B["Blockchain / Indexer"] -->|"已验证观测"| I
    B -->|"Origin/Outpoint/编号"| A
    B -->|"Post 与签名"| C["Content"]
    B -->|"关系事件"| R["Relationship"]
    I -->|"身份归属和密钥历史"| C
    I -->|"身份签名证明"| A
    I --> E["Explorer 只读聚合"]
    A --> E
    C --> E
    R --> E
~~~

箭头表达业务证据/读取依赖，**不表示同步 API 的调用顺序或微服务拓扑**。具体前后端技术接口以 [Contracts](../contracts/README.md) 和相应实现设计为准。
