# OwnWord 限界上下文映射（v0.4.0 目标）

> 状态：needs-review。产品事实见[核心认知 §5](../核心认知.md#5-结构)；本表只明确前后端各自的上下文责任与协作方向，不重复核心认知的模型定义。

## 1. 上下文按执行端划分

OwnWord 的限界上下文按执行端划分。同一子域在前端与后端承担不同职责，用不同的语言与模型，各自有独立的权威来源与失败语义。下表写全名以消歧；同端内部只用名称。

| 上下文 | 执行端 | 领域责任 | 权威来源 | 对外发布的语义 |
| --- | --- | --- | --- | --- |
| Wallet | 前端 | 会话、权限、密钥派生、签名请求、交易构造与广播 | Yours Wallet | 已签原交易、回执、可恢复引用 |
| Identity | 前端 | Review、意图冻结、资料校验、执行编排与恢复 | Wallet + 后端只读 | 发布意图、操作日志、恢复状态 |
| Content | 前端 | Draft、编辑器、Preview、发布意图、Revision 编排 | 钱包签名 + 本地草稿 | 发布意图、草稿状态、修订顺序 |
| Artifact | 前端 | 创建与转移的用户流程、编号状态展示 | Wallet | Artifact 操作意图、编号展示状态 |
| Relationship | 前端 | Follow 与 Friend 的操作意图、关系视图 | Wallet | 关系操作意图、关系展示状态 |
| Reading | 前端 | 公开阅读、主页浏览、关系列表展示 | 后端只读 API | 只读视图，不产生写入 |
| Identity | 后端 | 身份投影、历史签名归属验证、操作回执查询 | Bitcoin + 公共 BAP | IdentityResolution、Proof、回执 |
| Content | 后端 | Post 解析、Revision 关系图、作者归属 | Bitcoin | PublishedPost、RevisionGraph、作者链 |
| Artifact | 后端 | Artifact 解析、编号与 Origin 追踪、Binding 验证 | Bitcoin + Indexer | ArtifactSummary、编号状态、Ownership |
| Relationship | 后端 | Follow/Friend 记录解析、关注与粉丝派生 | Bitcoin | 公开关系、人数、coverage |
| Transaction | 后端 | 接收已签原交易、独立验签、网络观测、提交记录 | 钱包回执 + 链上观测 | 验签结果、networkAccepted、confirmations |
| Chain Query | 后端 | 原交易、主链归属、确认数、Ordinal 查询 | WhatsOnChain、JungleBus、Indexer | 带来源、覆盖、链锚与时点的 Observation |

## 2. 跨上下文约束

- **交易只在钱包侧执行。** 前端 Wallet 是唯一构造、签名、广播的上下文；其他前端上下文只产生意图，后端全部上下文只读。参见 [ADR-002](../decisions/ADR-002-交易执行归属钱包-20261119-140000.md)。
- **后端不持有私钥。** 后端 Transaction 接收钱包已签原交易，独立验签后记录；不构造待签交易，不代替钱包广播。
- **同一子域两端模型不同。** 前端 Draft 是可编辑本地状态，后端无 Draft；后端 RevisionGraph 从链上重建，前端只消费读取结果。禁止把两端模型当作同一份实现。
- Content 作者、Relationship 端点均使用 `BapId`；Artifact 的数字 ID 要先解析资产，再核验 `IdentityNFTBinding`，不能直接替换 BAP ID。
- Identity 聚合不持有可变的 NFT Binding；Artifact 上下文负责历史/当前关联与双向唯一性。
- Wallet Connection 不能充当 BAP 身份或已授权身份签名；所有链上操作逐笔满足[核心认知 §6.4](../核心认知.md#64-全部链上交易的身份归属)。
- 公共索引 unknown 保留为查询未知，不单独否决钱包已有的身份操作语义。
- 区分客户端意图、Wallet 授权回执、后端验签、链上观测和 UI 展示。任何阶段失败不能推断其他阶段不存在或成功。
- 跨端只通过稳定 ID、Proof、公开端口协作；UI 路由参数、来源不完整的缓存及数据库记录不能提升为权限或全局事实。
