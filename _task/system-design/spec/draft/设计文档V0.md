# 产品七维定义

> **Own your identity. Own your words.**
> **拥有你的身份，为你的言论负责。**

本平台是一个基于 Bitcoin / BSV、BAP 与 1Sat Ordinals 构建的去中心化身份与内容平台。

平台不替用户保管身份，不替用户拥有内容，也不替用户发言。

用户通过自己的钱包控制身份，通过自己的身份对内容进行密码学签名，并将身份、内容及其证明发布到区块链，使身份归属、内容来源和历史版本可以被独立验证。

------

# 一、术语 Terminology

## 1. Wallet / 钱包

用户控制私钥和链上资产的软件。

MVP 默认支持 **Yours Wallet**。

平台不得直接接触、保存或传输用户私钥。

钱包负责：

- 用户授权
- 身份密钥提供
- 消息签名
- BAP 签名
- 交易签名
- Ordinal 创建
- 交易广播相关授权

钱包是一个外部能力提供者，而不是平台领域模型的一部分。

------

## 2. Wallet Provider

钱包向 Web 应用暴露的能力接口。

平台内部禁止业务代码直接依赖 Yours Wallet。

统一抽象为：

```text
WalletProvider
```

例如：

```text
WalletProvider
├── YoursWalletProvider
├── OneSatWalletProvider
├── FutureWalletProvider
└── ...
```

核心能力：

```text
connect()
disconnect()
getIdentity()
signMessage()
signTransaction()
inscribe()
getOrdinals()
```

Yours Wallet 当前 Provider API 已经基于 `WalletInterface` / BRC-100 暴露钱包连接，并存在 `disconnected → detecting → selecting → connecting → connected` 的连接状态，因此可以直接作为第一版 Adapter 的实现基础。

------

## 3. BAP Identity / BAP 身份

基于 Bitcoin Attestation Protocol 建立的密码学身份。

BAP Identity 的核心是：

```text
BAP ID
```

BAP ID 是稳定身份标识。

身份可以发生：

```text
创建
发布
签名
密钥轮换
撤销
恢复
```

但 BAP ID 本身不应被当成普通用户名进行修改。

BAP 当前协议把 Bitcoin keypair 作为身份基础，并通过稳定的 member/root path 定义 BAP ID；签名路径可以轮换，而 BAP ID 保持不变。

------

## 4. Identity Profile / 身份资料

与 BAP Identity 关联的可变展示资料。

例如：

```text
displayName
avatar
bio
website
location
links
```

需要特别区分：

```text
BAP Identity = 密码学身份

Identity Profile = 身份展示资料
```

Profile 可以不断发布新版本。

Profile 发生修改时：

```text
Profile V1
   ↓
Profile V2
   ↓
Profile V3
```

而：

```text
BAP ID
```

始终保持不变。

这样可以避免把 UI 资料和底层身份协议绑定。

------

## 5. BAP NFT / Identity NFT

平台定义的一种 **BAP Identity 链上身份卡**。

它基于 1Sat Ordinals 创建。

一个 NFT 可以包含：

```text
BAP ID
Avatar
Display Name
Identity Metadata
Creation Time
Application Identifier
```

平台业务规则：

```text
1 BAP Identity
      │
      └── 0..1 Identity NFT
```

未创建 NFT：

```text
BAP Identity → 0 NFT
```

创建以后：

```text
BAP Identity → 1 NFT
```

注意：

**Identity NFT 不是 BAP 身份所有权本身。**

BAP 身份所有权来自身份密钥。

NFT 是：

```text
Representation
Credential
Identity Card
Public Artifact
```

而不是：

```text
Authentication Authority
```

这是非常重要的安全边界。

1Sat Ordinal 本质上是跟随单 satoshi UTXO 转移的资产，因此 Ordinal 的持有者变化不能自动等同于 BAP 身份密钥所有者变化。

------

## 6. Content / 内容

由某个 BAP Identity 发布并负责的内容。

MVP：

```text
Markdown
```

未来可以扩展：

```text
Markdown
Image
Audio
Video
HTML
Document
Code
Dataset
```

统一领域抽象：

```text
Content
```

而不是：

```text
MarkdownPost
```

避免未来扩展时重构领域模型。

------

## 7. Content Revision / 内容版本

链上内容不可简单覆盖。

因此“修改文章”实际应表示：

```text
Content
 ├── Revision 1
 ├── Revision 2
 └── Revision 3
```

每一次修改都是一个新的版本。

旧版本仍然存在。

最新版本通过：

```text
previousTxId
contentId
revision
```

建立关系。

------

## 8. Signature Proof / 内容签名证明

证明：

> 某个 BAP Identity 对某段具体内容进行了签名。

建议签名对象不是编辑器里的原始状态，而是经过确定性处理后的：

```text
Canonical Content
       ↓
Content Hash
       ↓
Signature
```

例如领域模型：

```text
SignatureProof {
    bapId
    contentHash
    signature
    signerAddress
    algorithm
    createdAt
}
```

------

## 9. Chain Record / 链上记录

平台对某次上链行为的统一抽象。

```text
ChainRecord {
    txid
    outputIndex
    blockHeight
    blockTime
    network
    protocol
    confirmationStatus
}
```

页面不直接依赖某个 indexer 返回的数据结构。

# 二、目标 Goal

## 产品目标

建立一个：

> **身份归个人，内容归个人，言论责任归个人。**

的平台。

三个核心能力：

```text
Identity
    ↓
Signature
    ↓
Content
```

即：

```text
Who are you?
      ↓
What did you say?
      ↓
Can anyone verify it?
```

------

## 1. Own your identity

平台用户不是传统意义上的：

```text
Account
```

而是：

```text
Cryptographic Identity
```

平台不能：

```text
删除用户身份
冒充用户身份
替用户修改身份所有权
替用户进行签名
```

------

## 2. Own your words

内容来源由用户身份签名证明。

平台数据库不能成为内容真实性的唯一来源。

即使未来网站不存在，只要链上数据和协议仍然可解析，第三方仍然可以验证：

```text
内容
+
签名
+
BAP ID
+
交易
```

之间的关系。

------

## 3. Responsible speech

平台强调：

```text
Freedom
+
Ownership
+
Responsibility
```

而不是仅仅：

```text
Freedom
```

每篇正式发布内容显示：

```text
Signed by

BAP ID
Signature
Transaction
Timestamp
```

形成产品独有的“署名文化”。

------

## 4. Verifiable by anyone

验证过程原则上不依赖平台自己的数据库。

平台可以提供：

```text
Verify
```

页面。

输入：

```text
BAP ID
Content
Signature
TXID
```

即可独立验证内容来源。

------

## 5. Platform as Interface, not Authority

平台定位不是：

```text
Identity Provider
```

而应该是：

```text
Identity Interface
Content Interface
Protocol Interface
Indexer
Explorer
```

平台负责提供优秀的使用体验，而不是成为身份真实性的中心化权威。

------

# 五、关系 Relationship

## 核心领域关系

```text
Wallet
  │
  │ controls
  ▼
BAP Identity
  │
  ├────────── 0..1 ──────── Identity NFT
  │
  │
  ├────────── 1..N ──────── Content
  │                            │
  │                            └── 1..N Revision
  │                                      │
  │                                      └── SignatureProof
  │
  └────────── 1..N ──────── Profile Revision
```

------

## Wallet 与 Identity

不要定义：

```text
1 Wallet = 1 Identity
```

建议：

```text
1 Wallet
    ↓
0..N BAP Identity
```

因为 BAP 当前实现本身支持从同一个根创建多个 `bap:0`、`bap:1` 等身份。

产品第一版 UI 可以默认：

```text
一个 Active Identity
```

但领域模型保留多个身份能力。

------

## Identity 与 NFT

平台业务规则：

```text
BAP Identity
      │
      │ 1 : 0..1
      ▼
Identity NFT
```

创建 NFT 后：

```text
1 : 1
```

但是：

```text
NFT Ownership
```

绝对不能成为：

```text
BAP Authentication
```

否则 NFT 被转移以后会产生严重语义冲突。

------

## Identity 与 Content

```text
1 Identity
    ↓
N Content
```

每篇内容必须有：

```text

```

NFT：

```text
不是 BAP 身份所有权证明
```

NFT 是：

```text
Identity Artifact
```

------

## 5. 链上数据边界

链上已经确认的数据：

```text
不可修改
不可真正删除
```

因此 UI 不应使用：

```text
Delete from Blockchain
```

而应该：

```text
Publish New Version

Supersede

Revoke

Hide Locally
```

------

## 6. 数据库边界

平台数据库：

```text
不是 Source of Truth
```

数据库可以保存：

```text
索引

搜索数据

缓存

草稿

UI 设置

链上同步状态
```

但不能成为：

```text
身份真实性来源

内容签名真实性来源
```

对于已发布内容：

```text
Blockchain + Signature
```

才是最终验证依据。

------

## 7. Indexer 边界

Indexer 是：

```text
Read Model
```

而不是：

```text
Authority
```

即使 1Sat API 出现问题：

```text
Chain data still exists.
```

因此 IndexerPort 应可替换。

------

## 8. MVP 边界

第一版明确不做：

```text
算法推荐

Likes

Comments

DM

复杂 Follow Graph

Token Economy

Marketplace

DAO

多链

NFT Trading

复杂 Reputation System
```

第一版只验证一件事情：

> 用户是否愿意使用自己的区块链身份，对自己发布的内容进行签名，并公开承担其来源责任？

因此 MVP 最小闭环是：

```text
Connect Wallet
      ↓
Create / Select BAP Identity
      ↓
Create Identity NFT
      ↓
Write Markdown
      ↓
Preview
      ↓
Sign
      ↓
Publish
      ↓
Verify
```

如果这个闭环成立，再进入：

```text
Identity
   ↓
Relationship
   ↓
Reputation
   ↓
Social Graph
```

阶段。

# 最终产品模型

整个系统最终可以归纳为四个核心领域对象：

```text
IDENTITY
   │
   │ signs
   ▼
CONTENT
   │
   │ creates
   ▼
PROOF

IDENTITY
   │
   │ relates to
   ▼
IDENTITY
```

进一步简化就是：

```text
Who

Said What

To Whom

Prove It
```

这应该成为整个产品架构和 UX 的核心。
