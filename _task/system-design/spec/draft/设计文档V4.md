# 区块链身份、关系与内容平台设计

## 1. 术语

| 术语                   | 定义                                                         |
| ---------------------- | ------------------------------------------------------------ |
| Wallet                 | 用户控制私钥、签名和链上交易的钱包                           |
| Wallet Provider        | 平台接入钱包的统一接口                                       |
| BAP                    | Bitcoin Attestation Protocol，链上身份协议                   |
| BAP ID                 | BAP 身份的稳定唯一标识                                       |
| BAP Profile            | BAP 身份公开资料，如名称、头像、简介、类型                   |
| Identity NFT / BAP NFT | 平台定义的身份 NFT，基于 1Sat Ordinals 创建，并与 BAP ID 建立绑定 |
| Content                | 用户发布的链上内容，MVP 支持 Markdown                        |
| Content Revision       | 已发布内容的后续版本，链上内容不可覆盖修改                   |
| Relationship           | BAP 身份之间的关系                                           |
| Signature              | BAP 身份对内容或操作产生的密码学签名                         |
| Inscription            | 写入 1Sat Ordinal 的链上数据                                 |
| TXID                   | 链上交易唯一标识                                             |
| Origin                 | 1Sat Ordinal 初始 1 satoshi 输出标识                         |
| Protocol Adapter       | 平台领域模型到具体区块链协议的适配层                         |

------

# 2. 目标

设计一款面向个人和组织的：

> **区块链身份 + 关系 + 内容平台**

核心理念：

**Own your identity. Own your words.**

**拥有你的身份，为你的言论负责。**

用户应能够：

1. 拥有自己的区块链身份。
2. 使用自己的身份对内容签名。
3. 自己控制内容发布。
4. 验证其他内容是否由指定身份发布。
5. 建立身份之间可验证的关系。
6. 不依赖平台保存私钥。
7. 不因平台消失而失去身份和已经发布的内容。

平台本质上应是：

> **协议使用者 + 钱包协调者 + 内容展示器 + 区块链索引器**

而不是传统意义上的账号中心和内容所有者。

------

# 3. 结构

## 3.1 可扩展性

外部能力全部通过 Adapter 接入。

```text
Application
    │
    ├── WalletProvider
    │       ├── YoursWalletAdapter
    │       └── OtherWalletAdapter
    │
    ├── IdentityProtocol
    │       └── BapAdapter
    │
    ├── ContentProtocol
    │       └── BitcoinSchemaAdapter
    │
    ├── OrdinalProtocol
    │       └── OneSatAdapter
    │
    └── ChainGateway
            ├── Broadcast
            └── Indexer
```

MVP 使用：

- Wallet：Yours Wallet
- Identity：BAP
- Content：BitcoinSchema
- NFT：1Sat Ordinals

未来替换或增加实现，不影响核心业务模型。

Yours Wallet 当前 Provider API 已提供 BRC-100 钱包连接、BAP Profile、身份发布和更新、Ordinal 查询与 inscription 等能力，因此可作为第一个 Wallet Adapter。

## 3.2 面向接口

核心接口：

### WalletProvider

负责：

- 连接钱包
- 断开钱包
- 获取当前身份公钥
- 获取地址
- 请求签名
- 创建交易
- 提交交易
- 监听账户切换

领域层不得直接依赖 Yours Wallet。

------

### IdentityProtocol

负责：

- 解析 BAP ID
- 发布 BAP ID
- 查询 BAP Profile
- 更新 BAP Profile
- 验证身份
- Key Rotation

------

### ContentProtocol

负责：

- 内容编码
- Metadata 构造
- 签名数据构造
- 协议数据构造
- 协议解析
- 内容验证

MVP：

```text
BitcoinSchemaAdapter
```

优先兼容既有 BitcoinSchema / 1Sat 协议组合，不自行定义新的链上内容协议。1Sat SDK 当前也已经包含 AIP、BAP、MAP、BSocial 等模板能力。

------

### OrdinalProtocol

负责：

- 创建 inscription
- 查询 Ordinal
- 获取 NFT
- 转移 NFT
- 验证 NFT 所有权

MVP：

```text
OneSatAdapter
```

1Sat Ordinals 使用单个 1 satoshi 输出承载 inscription，并通过后续 UTXO spend 转移所有权。

# 4. 实体

## 4.1 核心实体

### WalletAccount

代表当前连接的钱包账户。

不是平台账号。

------

### BapIdentity

代表一个独立区块链身份。

```text
BapIdentity
 ├── bapId
 ├── identityKey
 ├── type
 ├── profile
 ├── publishTxId
 └── status
```

一个钱包可以管理多个 BAP Identity。

BAP 当前实现本身支持从同一根密钥派生多个身份，例如 `bap:0`、`bap:1`。

------

### IdentityNFT

平台中的「BAP NFT」。

底层：

```text
1Sat Ordinal
```

用于提供：

- 身份视觉载体
- 身份收藏品
- 身份链上资产
- Identity Avatar / Badge
- 可验证 NFT 所有权

注意：

> IdentityNFT ≠ BAP Identity

BAP ID 是身份。

NFT 是身份拥有或关联的资产。

------

### Content

用户使用 BAP Identity 发布的内容。

MVP：

```text
format = Markdown
```

Content 包含：

```text
作者
原始内容
内容 Hash
Metadata
签名
TXID
发布时间
协议
状态
```

------

### ContentRevision

表示内容的后续版本。

链上已经确认的内容：

```text
禁止覆盖
```

修改内容实际上产生：

```text
Content V1
      ↓
Content V2
      ↓
Content V3
```

形成版本链。

------

### Relationship

两个 Identity 之间的关系。

```text
Identity A
    ↓
Relationship
    ↓
Identity B
```

MVP 可以暂不实现完整社交关系，但领域模型预留。

未来支持：

```text
FOLLOW
ENDORSE
TRUST
BLOCK
MEMBER_OF
OWNED_BY
CREATED_BY
```

不将关系模型绑定死为传统 `follow`。

------

### Transaction

链上操作记录。

用于统一跟踪：

- Identity 发布
- Profile 更新
- Content 发布
- NFT 创建
- NFT 绑定
- Relationship 创建

------

# 5. 关系

核心关系：

```text
WalletAccount
    1
    │
    └──── N BapIdentity


BapIdentity
    1
    │
    ├──── N Content
    │
    ├──── N Relationship
    │
    └──── 0..1 Bound IdentityNFT


WalletAccount
    1
    │
    └──── N IdentityNFT
```

## BAP ID 与 NFT

规则：

> 一个钱包可以创建、持有多个 Identity NFT。

但：

> 一个 BAP ID 同一时间只能绑定一个 Identity NFT。

即：

```text
BAP ID
   │
   └── 0..1 ACTIVE IdentityNFT
```

建议同时约束：

```text
IdentityNFT
   │
   └── 0..1 BAP ID
```

形成真正的一对一「当前绑定关系」。

如果 NFT 被转移：

```text
原所有者
   ↓
失去 NFT
   ↓
系统重新验证 ownership
   ↓
BAP ↔ NFT Binding 失效
```

不要仅依靠数据库中的 `bound=true` 判断。

# 6. 属性

## 6.1 BapIdentity

| 属性        | 类型     | 唯一 | 不变 | 必填 |
| ----------- | -------- | ---- | ---- | ---- |
| bapId       | String   | ✓    | ✓    | ✓    |
| identityKey | String   | -    | -    | ✓    |
| type        | Enum     | -    | -    | ✓    |
| name        | String   | -    | -    | -    |
| image       | URI      | -    | -    | -    |
| description | String   | -    | -    | -    |
| publishTxId | String   | ✓    | ✓    | -    |
| status      | Enum     | -    | -    | ✓    |
| createdAt   | DateTime | -    | ✓    | ✓    |

`type`：

```text
PERSON
ORGANIZATION
```

BAP ID 应视为稳定身份标识。

密钥轮换不应该创建新的 BAP ID。BAP 当前规范明确将 `rootPath` 作为稳定身份根，将 `currentPath` 用于当前签名密钥路径。

因此：

```text
修改身份
≠
修改 bapId
```

修改身份主要指：

```text
更新 Profile
Key Rotation
```

------

## 6.2 IdentityNFT

| 属性            | 类型     | 唯一 | 不变 | 必填 |
| --------------- | -------- | ---- | ---- | ---- |
| origin          | String   | ✓    | ✓    | ✓    |
| mintTxId        | String   | ✓    | ✓    | ✓    |
| currentOutpoint | String   | ✓    | -    | ✓    |
| owner           | String   | -    | -    | ✓    |
| contentType     | String   | -    | ✓    | ✓    |
| content         | URI/Data | -    | ✓    | ✓    |
| bapId           | String   | -    | -    | -    |
| status          | Enum     | -    | -    | ✓    |

其中：

```text

```

代表 NFT 的永久身份。

而：


会随着 NFT 转移而变化。

# 7. 状态

状态需要分领域建模，而不是使用统一的 `status=0/1`。

------

## 7.1 Wallet 状态

```text
DISCONNECTED
      ↓
DETECTING
      ↓
CONNECTING
      ↓
CONNECTED
      ↓
DISCONNECTED
```

还需要处理：

```text
ACCOUNT_SWITCHED
```

Yours Wallet 当前连接 API 已暴露 disconnected、detecting、selecting、connecting、connected，并提供 signedOut 与 switchAccount 事件。

------

## 7.2 BAP Identity 状态

```text
UNPUBLISHED
      ↓
PUBLISHING
      ↓
ACTIVE
```

异常：

```text
PUBLISHING
   ↓
FAILED
```

密钥轮换：

```text
ACTIVE
  ↓
ROTATING
  ↓
ACTIVE
```

不要设计：

```text
DELETED
```

因为已经产生的链上身份记录无法真正删除。

应用层可以：

```text
HIDDEN
ARCHIVED
```

但不能表示链上数据消失。

------

## 7.3 Content 状态

```text
DRAFT
  ↓
READY
  ↓
SIGNING
  ↓
BROADCASTING
  ↓
PENDING
  ↓
CONFIRMED
```

异常：

```text
SIGNING → REJECTED

BROADCASTING → FAILED

PENDING → FAILED
```

其中：

```text
CONFIRMED
```

为链上最终业务状态。

------

## 7.4 IdentityNFT 状态

```text
DRAFT
 ↓
MINTING
 ↓
PENDING
 ↓
ACTIVE
 ↓
TRANSFERRED
```

可扩展：

```text
BURNED
```

------

## 7.5 NFT Binding 状态

单独建立状态：

```text
UNBOUND
   ↓
BINDING
   ↓
BOUND
```

NFT ownership 改变：

```text
BOUND
  ↓
INVALID
```

重新绑定：

```text
INVALID
  ↓
UNBOUND
```

```text

```

```text
WalletProvider
```
```text
     ↓
```

## 11.3 协议边界

MVP 优先使用现有标准：

```text

BitcoinSchema
AIP / BAP Signing
MAP
1Sat Ordinals
```

除非协议确实无法表达业务，否则：

> 不自行发明新的链上协议。

BitcoinSchema 项目的核心目标本身就是通过可扩展 Schema 实现可互操作的数据应用。

## 11.4 数据所有权

链上数据：

```text
Blockchain = Source of Truth
```

```text
Index
Cache
Search
UI State
Draft
```

不能把平台数据库定义为身份、NFT 或链上内容的最终事实来源。

------

## 11.5 内容不可变

链上已确认 Content：

```text
不可修改
不可删除
```

所谓：

```text
修改
```

实际为：

```text
发布新 Revision
```

所谓：

```text
删除
```

只能：

```text
隐藏 / 标记 / 撤回声明
```

不能声称链上原始内容已经消失。
