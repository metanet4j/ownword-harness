# 区块链身份、关系与内容平台产品设计

> **Own your identity. Own your words.**
> 拥有你的身份，为你的言论负责。

# 1. 术语

| 术语            | 定义                                             | 产品含义                             |
| --------------- | ------------------------------------------------ | ------------------------------------ |
| Wallet          | 用户持有密钥并管理链上资产的钱包                 | 用户进入平台及执行链上操作的能力入口 |
| Yours Wallet    | 基于 BRC-100 的非托管 BSV Wallet                 | MVP 默认支持的钱包                   |
| Wallet Provider | 平台对钱包能力的统一抽象                         | 用于未来接入其他钱包                 |
| BAP             | Bitcoin Attestation Protocol                     | 平台身份体系的核心协议               |
| BAP ID          | BAP 中确定性派生的身份标识                       | 个人或组织的区块链身份 ID            |
| BAP Profile     | BAP 身份对应的公开资料                           | 名称、头像、简介、类型等             |
| Key Rotation    | 保持 BAP ID 不变，更换当前签名路径               | 身份安全机制                         |
| Attestation     | 对身份或属性建立密码学证明                       | 后续信任体系基础                     |
| BitcoinSchema   | 一组可组合的 Bitcoin 数据 Schema                 | 平台内容、关系协议的主要标准         |
| B Protocol      | 保存内容主体的数据协议                           | 用于 Markdown、文本、图片等内容      |
| MAP             | 描述数据语义及上下文                             | 如 `type=post`、`app=xxx`            |
| AIP             | Author Identity Protocol                         | 对链上数据建立作者签名               |
| Post            | 新发布的一条内容                                 | MVP 的核心内容类型                   |
| Reply           | 以交易为上下文的 Post                            | 后续回复能力                         |
| Repost          | 引用已有 Post 的链上行为                         | 后续转发能力                         |
| Follow          | 两个身份之间的单向关系                           | 后续身份关系                         |
| Friend          | 两个身份之间的双向关系                           | 后续更强关系及安全通信               |
| 1Sat Ordinal    | 1Sat Ordinals 协议中的可追踪链上资产             | BAP NFT 的底层资产模型               |
| Inscription     | 写入 Ordinal 的内容                              | NFT 图片、JSON 或其他文件            |
| Outpoint        | 某个交易输出的位置                               | Ordinal 当前所在位置                 |
| BEEF            | 包含交易 ancestry 的数据                         | Ordinal 转移等操作需要的交易上下文   |
| BAP NFT         | **本产品定义的、与 BAP 身份关联的 Ordinal 资产** | 身份的视觉化、资产化表达             |
| Binding         | BAP ID 与某个 BAP NFT 建立的绑定关系             | 一个 BAP ID 同时最多一个有效绑定     |
| Transaction     | Bitcoin 链上交易                                 | 身份、内容、NFT 等行为的最终链上记录 |

**依据：**

BAP 将 Bitcoin keypair 作为数字身份基础，并定义身份创建、Attestation、Rotation、Revocation 等生命周期；BAP ID 由稳定 identity root 派生。

Yours Wallet 是基于 BRC-100 的非托管钱包，并直接提供 BAP Identity、Ordinal、签名及交易相关能力。

BitcoinSchema Social Schema 已定义 Post、Reply、Repost、Follow、Friend 等社交语义。

# 2. 目标

设计一款以 **区块链身份为中心** 的个人或组织身份、关系、内容平台。

用户通过自己的 Wallet：

1. 拥有自己的区块链身份；
2. 使用自己的 BAP Identity 发布和签名内容；
3. 对自己发布的内容负责；
4. 建立属于 Identity 而不是平台账号的关系；
5. 创建并持有代表自身 Identity 的 BAP NFT；
6. 即使离开本平台，其身份、内容和链上资产仍然存在。

核心理念：

> **Identity belongs to the user.**
> **Words are signed by the identity.**
> **Blockchain is the source of truth.**

平台不是传统模式：

```text
用户
 ↓
平台账号
 ↓
平台数据库
 ↓
平台内容
```

而是：

```text
Wallet
   ↓
BAP Identity
   ↓
Content / Relationship / BAP NFT
   ↓
Bitcoin
```

平台主要负责：

- 创建和展示良好的用户体验；
- 组织和索引链上数据；
- 提供内容编辑与预览；
- 提供协议解析；
- 提供身份和内容验证；
- 提供搜索、缓存等 Web 能力。

平台不拥有：

- 用户私钥；
- 用户 BAP ID；
- 用户已发布内容；
- 用户 Ordinal 资产。

**依据：**

BAP 的设计目标本身就是解决集中式身份控制、平台身份割裂以及不可验证身份的问题，并强调身份所有权和数据主权。

Yours Wallet 为 non-custodial Wallet，密钥保存在用户设备中。

# 4.1.4 创建 BAP NFT

这里需要区分：

```text
BAP Identity
```

和：

```text
BAP NFT
```

二者不是同一实体。

本产品定义：

> **BAP NFT 是与 BAP Identity 建立关联关系的 1Sat Ordinal，用于身份的视觉化和资产化表达。**

可以表现为：

- Identity Badge；
- Identity Card；
- Digital Seal；
- Identity Artifact。

------

### 创建

```text
Identity
   ↓
Create BAP NFT
   ↓
Upload / Generate Content
   ↓
Preview
   ↓
Inscribe
   ↓
Wallet Sign
   ↓
Broadcast
   ↓
Created
```

1Sat Ordinals 使用一个值为 **1 satoshi** 的 output 承载 inscription，并可以通过消费该 output 将 Ordinal 转移给其他地址。

Yours Wallet 当前提供：

```text
inscribe
getOrdinals
transferOrdinals
```

并允许 inscription 添加 MAP Metadata 及可选 BAP signing。

1Sat SDK 同样提供：

```text
inscribe()
sendOrdinals()
getOrdinals()
```

等接口。

------

### BAP NFT Binding

这是**本产品规则，而不是 BAP/1Sat 协议规则**：

> 一个 BAP Identity 可以创建或拥有多个 BAP NFT，但同一时间只能有一个处于“绑定中”的 BAP NFT。

即：

```text
BAP Identity

├── NFT A    Historical
├── NFT B    Bound
└── NFT C    Unbound
```

约束：

```text
BAP ID → Active BAP NFT = 0..1
```

这样既允许创建多个 NFT，也允许以后更换当前 Identity NFT。

------

### NFT 转移

由于 Ordinal 可以被转移，NFT 所有者可能发生变化。

因此平台必须考虑：

```text
Bound NFT
    ↓
NFT transferred
    ↓
Current ownership changes
    ↓
Binding becomes invalid
```

不能因为数据库中还存在 Binding，就继续显示正常绑定。

------

### Ordinal 操作约束

Yours Wallet 明确要求：消费已有 Ordinal 的操作需要先执行：

```text
getOrdinals
```

获得：

```text
output
+
BEEF
```

再进行 transfer/list/cancel 等操作。

这属于实现边界，原型中不需要直接展示 BEEF，但产品状态要允许出现：

```text
Loading asset
Asset unavailable
Transfer failed
```

等情况。

# 5. 实体

MVP 核心实体：

## 5.1 WalletConnection

表示当前 Web 应用与 Wallet 的连接上下文。

它不是 Identity。

------

## 5.2 BAPIdentity

平台最核心的业务实体。

表示：

> 一个个人或组织的主权区块链身份。

------

## 5.3 BAPProfile

BAP Identity 的公开展示资料。

与 BAP ID 分开建模：

```text
BAP Identity
   │
   └── Profile
```

这样：

```text
BAP ID
```

保持稳定，而：

```text
name

```

可以更新。

Yours Wallet 将 `getProfile/updateProfile` 与 Identity Publish 分开提供，也支持这种产品建模。

------

## 5.4 Content

身份发布的内容。

MVP：

```text

Content.mediaType = Markdown
```

------

## 5.5 Relationship

两个 Identity 之间的关系。

```text
Identity
   ↓
Relationship
   ↓
Identity
```

不是：

```text
Platform User
   ↓
Platform User
```

------

## 5.6 BapNFT

与 BAP Identity 相关的 1Sat Ordinal Asset。

NFT 自身存在，不依赖 Binding。

------

## 5.7 IdentityNFTBinding

连接：

```text
BAPIdentity
     ↕
BapNFT
```

的独立关系实体。

独立建模的目的是：

- 支持更换 NFT；
- 保留历史 Binding；
- 检测 NFT 转移；
- 支持解绑；
- 避免把 NFT 直接写死在 Identity 上。

------

## 5.8 BlockchainTransaction

用于记录各类业务操作对应的链上交易：

```text

Profile Update
Content Publish
NFT Inscription
NFT Binding
```

业务实体不应完全依赖 Transaction Entity，但 UI 可以通过它统一展示：

```text
TxID
Network Status
Block
Created Time
```

# 6. 关系

核心关系：

```text
Wallet
   │
   │ controls / signs
   ▼
BAP Identity
BAP Identity
   │
   │ publishes
   ▼
Content
BAP Identity
   │
   │ relationship
   ▼
BAP Identity
BAP Identity
   │
   │ binding
   ▼
BAP NFT
```

完整模型：

```text
                     Wallet
                        │
                        ▼
                  BAP Identity
                        │
          ┌─────────────┼──────────────┐
          │             │              │
          ▼             ▼              ▼
       Content     Relationship      BAP NFT
                         │
                         ▼
                    BAP Identity
```

关系数量：

| A            | 关系           | B            | 数量     |
| ------------ | -------------- | ------------ | -------- |
| BAP Identity | Profile        | BAP Profile  | 1 : 0..1 |
| BAP Identity | Publish        | Content      | 1 : N    |
| BAP Identity | Relation       | BAP Identity | N : N    |
| BAP Identity | Own/Create     | BAP NFT      | 1 : N    |
| BAP Identity | Active Binding | BAP NFT      | 1 : 0..1 |

其中：

> **一个 BAP ID 同一时间最多绑定一个 BAP NFT。**

这是本产品业务约束。

BitcoinSchema 则为 Identity → Identity 的 Follow/Friend 等关系提供协议语义，例如 Follow 被明确描述为两个 Identity 之间的单向关系。

```text

      ↓
PUBLISHING
      ↓
ACTIVE
```

```text
ACTIVE
  ↓
ROTATING
  ↓
ACTIVE
```

```text
ACTIVE
  ↓
REVOKED
```

BAP 定义的 Identity Lifecycle 包括 Genesis、Attestation、Rotation 和 Revocation。

```text

Active

```

# 7.3 Content 状态

```text
DRAFT
   ↓
READY
   ↓
AWAITING_SIGNATURE
   ↓
BROADCASTING
   ↓
PUBLISHED
```

```text

        ↓
USER_REJECTED
BROADCASTING
     ↓

```

```text

Mined

```

# 10. 界限

## 10.1 Wallet 边界

MVP 默认：

```text
Yours Wallet
```

但业务层必须使用：

```text
WalletProvider
```

抽象。

依据：Yours Wallet 自身基于 BRC-100 Wallet Interface，WalletProvider 也支持检测 compatible wallet。

------

## 10.2 私钥边界

平台：

```text
Never access private key
Never store seed phrase
Never ask user for WIF
```

用户签名由 Wallet 完成。

Yours Wallet 明确是 non-custodial，keys stay on device。

------

## 10.3 Wallet Permission 边界

```text
Wallet Connected
```

不意味着：

```text
Application can sign automatically
```

Yours Wallet 中执行签名或广播的 Action 可能要求用户批准；用户拒绝时应正常处理 `user-rejected`。

------

## 10.4 BAP Identity 边界

不能提供：

```text
Edit BAP ID
```

可以提供：

```text
Edit Profile
Rotate Identity Key
Attestation
```

BAP ID 是稳定 Identity，Rotation 改变的是当前 Signing Root。

------

## 10.5 Content 边界

MVP：

```text
Post
Markdown
UTF-8
BitcoinSchema
```

优先使用 BitcoinSchema Social Schema。

不重新设计：

```text
Custom Post Protocol
Custom Follow Protocol
Custom Reply Protocol
```

因为 BitcoinSchema 已定义这些语义。

------

## 10.6 区块链与数据库边界

Bitcoin：

```text
Identity
Published Content
Signature
NFT
Transaction
```

是链上事实。

平台数据库主要负责：

```text
Draft
Index
Cache
Search
UI State
Transaction Tracking
```

数据库不能成为：

```text
BAP ID ownership
NFT ownership
Published content
```

的唯一事实来源。

------

## 10.7 BAP NFT 边界

必须坚持：

```text
BAP Identity ≠ BAP NFT
```

Identity 可以没有 NFT：

```text
Identity → 0 NFT
```

也可以拥有多个：

```text
Identity → N NFT
```

但本产品规定：

```text
Identity → 0..1 Active Binding
```

NFT 被转移后，需要重新验证 Binding。

# 13. 设计结论

整个产品应围绕一个中心设计：

```text
                  BAP Identity
                       │
          ┌────────────┼────────────┐
          │            │            │
          ▼            ▼            ▼
       Content     Relationship    BAP NFT
          │            │            │
          └────────────┼────────────┘
                       │
                       ▼
                    Bitcoin
```

Wallet 位于 Identity 之前：

```text
Wallet
  ↓
Identity
```

但 Wallet 不是产品核心。

产品核心是：

> **一个由用户自己掌控、可以签署自己的内容、建立自己的关系，并持有自己的身份资产的区块链 Identity。**

因此原型设计时所有关键页面都应该不断强化三个对象：

```text
Identity

Words

Proof
```

最终落回品牌：

> **Own your identity. Own your words.**
