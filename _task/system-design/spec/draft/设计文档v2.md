# 区块链身份、关系与内容平台设计文档

> **Own your identity. Own your words.**
> 拥有你的身份，为你的言论负责。

------

# 1. 术语

## 1.1 Wallet

用户控制私钥、资产和签名能力的钱包。

MVP：

- Yours Wallet

原则：

- 平台不保存私钥
- 平台不保存助记词
- 平台不代替用户签名
- 钱包通过统一接口接入

------

## 1.2 BAP Identity

基于 BAP 协议建立的区块链身份。

核心标识：

```text
BAP ID
```

BAP ID：

- 唯一
- 稳定
- 不可修改
- 作为个人或组织的身份标识

------

## 1.3 Profile

BAP Identity 的展示资料。

例如：

- 名称
- 头像
- 简介
- 网站
- 社交链接

Profile 可以修改，但不改变 BAP ID。

------

## 1.4 BAP NFT

基于 1Sat Ordinals 创建的身份 NFT。

规则：

```text
一个 BAP Identity
可以创建多个 BAP NFT

一个 BAP ID
同时最多绑定一个 BAP NFT
```

BAP NFT 是身份展示资产，不是身份本身。

------

## 1.5 Content

由 BAP Identity 发布的链上内容。

MVP：

```text
Markdown Post
```

内容协议以：

```text
BitcoinSchema/schema
```

为主。

主要使用：

```text
B
MAP
AIP
Social Schema
```

------

## 1.6 Relationship

BAP Identity 之间的关系。

优先使用 BitcoinSchema 已定义的关系，例如：

```text
Follow
Unfollow
Friend
Reply
Repost
```

后续可扩展：

```text
Trust
MemberOf
WorksFor
Endorse
Attest
```

------

## 1.7 Signature

证明某个身份对具体数据进行了签名。

主要使用：

```text
AIP
```

签名必须由用户钱包完成。

------

## 1.8 Chain Record

实体在 Bitcoin 链上的交易记录。

主要包括：

```text
TXID
Output Index
Block Height
Block Time
Confirmation Status
```

------

# 2. 目标

构建一个基于 Bitcoin 的：

```text
身份
+
关系
+
内容
```

平台。

核心目标：

## 2.1 身份属于用户

用户通过钱包和私钥控制自己的身份。

平台不是身份所有者。

------

## 2.2 内容属于用户

用户决定：

- 发布什么
- 什么时候发布
- 使用哪个身份发布
- 是否更新内容

平台不能替用户修改已经发布的链上内容。

------

## 2.3 用户为自己的内容负责

每条正式发布的内容都能够验证：

```text
谁发布
↓
发布了什么
↓
是否被修改
↓
使用什么身份签名
↓
对应哪笔链上交易
```

------

## 2.4 数据可独立验证

真实性不依赖平台数据库。

核心验证链：

```text
BAP Identity
      ↓
Signature
      ↓
Content
      ↓
Transaction
```

------

## 2.5 平台定位

平台是：

```text
Identity Interface
Content Interface
Relationship Interface
Protocol Adapter
Indexer
Explorer
```

而不是中心化身份权威。

------

# 3. 分类

核心实体如下。

## 3.1 Wallet

职责：

- 钱包连接
- 用户授权
- 获取身份信息
- 消息签名
- 交易签名

------

## 3.2 Identity

协议：

```text
BAP
```

职责：

- 表示个人或组织
- 作为内容作者
- 作为关系主体
- 关联 Profile
- 关联 BAP NFT

------

## 3.3 Profile

职责：

- 保存身份可读资料
- 与底层 BAP Identity 解耦

------

## 3.4 BapNft

协议：

```text
1Sat Ordinals
```

职责：

- 身份链上展示
- 身份数字资产
- 与 BAP ID 建立绑定关系

------

## 3.5 Content

职责：

- 表示一篇逻辑内容
- 保存作者
- 管理当前版本

------

## 3.6 ContentRevision

职责：

- 表示一次具体内容版本
- 保存 Markdown 内容
- 对应一次签名和链上发布

------

## 3.7 Relationship

职责：

描述两个 Identity 之间的关系。

例如：

```text
A FOLLOW B
```

------

## 3.8 SignatureProof

职责：

证明某个 Identity 对具体数据进行了签名。

------

## 3.9 ChainRecord

职责：

统一保存链上交易状态和定位信息。

------

# 4. 关系

## 4.1 总体关系

```text
Wallet
  │
  └── controls
        │
        ▼
     Identity
        │
        ├── Profile
        │
        ├── BapNft 0..N
        │
        ├── Content 0..N
        │
        └── Relationship 0..N

Content
  │
  └── ContentRevision 1..N
            │
            ├── SignatureProof
            └── ChainRecord
```

------

## 4.2 Wallet 与 Identity

```text
1 Wallet : 0..N Identity
```

领域模型允许一个钱包管理多个身份。

MVP 可以只突出当前 Active Identity。

------

## 4.3 Identity 与 Profile

```text
1 : 1
```

Profile 可更新。

BAP ID 不变化。

------

## 4.4 Identity 与 BapNft

创建关系：

```text
1 Identity : 0..N BapNft
```

绑定关系：

```text
1 Identity : 0..1 Bound BapNft
```

即：

```text
BAP NFT 可以多个
BAP ID 同时只能绑定一个
```

------

## 4.5 Identity 与 Content

```text
1 Identity : 0..N Content
```

一个 Content 必须只有一个作者。

------

## 4.6 Content 与 ContentRevision

```text
1 Content : 1..N ContentRevision
```

例如：

```text
Article A
 ├── Revision 1
 ├── Revision 2
 └── Revision 3
```

更新内容不是修改旧交易，而是创建新版本。

------

## 4.7 ContentRevision 与 SignatureProof

正式发布后：

```text
1 : 1
```

每个已发布版本必须存在签名证明。

------

## 4.8 ContentRevision 与 ChainRecord

```text
1 : 0..1
```

草稿：

```text
0
```

上链后：

```text
1
```

------

## 4.9 Identity 与 Identity

通过 Relationship 建立：

```text
Identity A
     │
Relationship
     │
     ▼
Identity B
```

Relationship 至少包含：

```text
source
target
type
```

# 5. 属性

## 5.1 Identity

| 属性      | 类型     | 唯一 | 不变 | 必填 | 说明     |
| --------- | -------- | ---- | ---- | ---- | -------- |
| id        | UUID     | 是   | 是   | 是   | 内部ID   |
| bapId     | String   | 是   | 是   | 是   | BAP ID   |
| status    | Enum     | 否   | 否   | 是   | 身份状态 |
| createdAt | DateTime | 否   | 是   | 是   | 创建时间 |
| updatedAt | DateTime | 否   | 否   | 是   | 更新时间 |

核心约束：

```text
bapId UNIQUE
bapId IMMUTABLE
```

------

## 5.2 Profile

| 属性        | 类型    | 唯一 | 不变 | 必填 | 长度 |
| ----------- | ------- | ---- | ---- | ---- | ---- |
| identityId  | UUID    | 是   | 是   | 是   | 36   |
| displayName | String  | 否   | 否   | 否   | 64   |
| avatar      | String  | 否   | 否   | 否   | 2048 |
| bio         | String  | 否   | 否   | 否   | 500  |
| website     | String  | 否   | 否   | 否   | 2048 |
| version     | Integer | 否   | 否   | 是   | -    |

------

## 5.3 BapNft

| 属性              | 类型   | 唯一     | 不变 | 必填 | 说明           |
| ----------------- | ------ | -------- | ---- | ---- | -------------- |
| id                | UUID   | 是       | 是   | 是   | 内部ID         |
| origin            | String | 是       | 是   | 是   | Ordinal Origin |
| creatorIdentityId | UUID   | 否       | 是   | 是   | 创建身份       |
| ownerAddress      | String | 否       | 否   | 是   | 当前持有地址   |
| boundIdentityId   | UUID   | 条件唯一 | 否   | 否   | 绑定身份       |
| txid              | String | 是       | 是   | 是   | 创建交易       |
| status            | Enum   | 否       | 否   | 是   | 状态           |


```text
一个 BAP ID
同时只能绑定一个 BAP NFT
```

# 6. 状态

所有关键实体采用显式状态机管理。

------

## 6.1 Wallet

```text
DISCONNECTED
     ↓
CONNECTING
     ↓
CONNECTED
```

异常：

```text
CONNECTING
   ↓
ERROR
```

------

## 6.2 Identity

```text
NONE
 ↓
CREATING
 ↓
ACTIVE
 ↓
REVOKED
```

异常：

```text
CREATING
 ↓
FAILED
```

最终状态：

```text
REVOKED
```

------

## 6.3 BapNft

```text
CREATING
 ↓
PENDING
 ↓
CONFIRMED
 ↓
BOUND
```

解绑：

```text
BOUND
 ↓
CONFIRMED
```

失败：

```text
CREATING / PENDING
        ↓
      FAILED
```

------

## 6.4 Content

```text
DRAFT
 ↓
PUBLISHED
```

可增加展示状态：

```text
PUBLISHED
 ↓
HIDDEN
```

`HIDDEN` 仅代表平台隐藏，不代表删除链上内容。

------

## 6.5 ContentRevision

```text
DRAFT
 ↓
PREVIEW
 ↓
SIGNING
 ↓
SIGNED
 ↓
BROADCASTING
 ↓
PENDING
 ↓
CONFIRMED
```

失败：

```text
SIGNING
 ↓
FAILED
```

或：

```text
BROADCASTING
 ↓
FAILED
```

`CONFIRMED` 后内容不可修改。

修改必须创建：

```text
Revision N + 1
```

------

## 6.6 Relationship

采用事件模型。

Follow：

```text
NONE
 ↓ Follow
ACTIVE
 ↓ Unfollow
INACTIVE
```

后续再次 Follow：

```text
INACTIVE
 ↓ Follow
ACTIVE
```

------

## 6.7 ChainRecord

```text
CREATED
 ↓
BROADCASTED
 ↓
PENDING
 ↓
CONFIRMED
```

异常：

```text
BROADCASTED
 ↓
FAILED
```

# 7. 功能

## 7.1 Wallet

### Connect Wallet

目的：

建立用户与平台之间的授权和签名通道。

功能：

- 检测钱包
- 连接钱包
- 断开
- 获取钱包信息
- 监听变化
- 处理授权异常

------

# 7.2 Identity

### Create Identity

目的：

创建 BAP Identity。

### Load Identity

目的：

发现并加载已有身份。

### View Identity

目的：

查看：

- BAP ID
- Profile
- BAP NFT
- Content
- Relationship

### Update Profile

目的：

修改身份展示信息。

不改变：

```text
BAP ID
```

### Revoke Identity

目的：

按照 BAP 协议撤销身份。

------

# 7.3 BAP NFT

### Create NFT

目的：

创建身份相关的链上 NFT。

允许：

```text
Identity
 ├── NFT 1
 ├── NFT 2
 └── NFT N
```

### Bind NFT

目的：

指定当前 Identity 使用的身份 NFT。

约束：

```text
一个 BAP ID
只能存在一个 Active Binding
```

### Unbind NFT

目的：

解除绑定关系。

NFT 本身继续存在。

### Change Bound NFT

逻辑：

```text
Unbind Old
+
Bind New
```

业务上作为一个原子操作。

------

# 7.4 Content

### Create

创建逻辑内容。

### Import Markdown

导入标准 Markdown。

### Edit Draft

编辑尚未正式发布的内容。

### Preview

发布前确认最终内容。

必须保证：

```text
Preview Data
=
Signed Data
```

### Publish

目的：

将内容按照 BitcoinSchema 发布。

基本流程：

```text
Markdown
 ↓
BitcoinSchema
 ↓
B + MAP
 ↓
AIP Signature
 ↓
Bitcoin Transaction
```

### Update

目的：

发布内容新版本。

```text
Revision 1
 ↓
Revision 2
 ↓
Revision 3
```

旧版本继续存在。

### View

展示：

- 内容
- 作者
- BAP ID
- TXID
- 发布时间
- 签名
- 验证状态

------

# 7.5 Relationship

### Follow

建立 Identity A → Identity B 的关注关系。

### Unfollow

结束 Follow 关系。

### View Relationships

查看某个 Identity 的链上关系。

MVP 优先使用 BitcoinSchema 已有协议。

------

# 7.6 Verify

### Verify Identity

验证 BAP Identity。

### Verify Signature

验证内容签名。

### Verify Content

验证页面内容和链上内容一致。

### Verify Transaction

验证交易存在和确认状态。

验证链：

```text
Identity
   │
   │ signs
   ▼
ContentRevision
   │
   │ published
   ▼
Transaction
```

全部成立后：

```text
VERIFIED
```

# 10. 界限

## 10.1 Wallet Boundary

业务代码只依赖：

```text
WalletPort
```

例如：

```text
WalletPort
 ├── YoursWalletAdapter
 └── FutureWalletAdapter
```

Yours Wallet 不是系统核心依赖。

------

## 10.2 Private Key Boundary

平台永远不：

```text
保存 Private Key
保存 Mnemonic
上传私钥
服务端替用户签名
```

------

## 10.3 Identity Boundary

BAP 是身份标准。

平台不重新定义身份协议。

平台主要负责：

- UI
- Profile
- 索引
- 内容
- 关系
- 验证

------

## 10.4 Content Boundary

内容协议以：

```text
BitcoinSchema/schema
```

为主。

优先复用：

```text
B
MAP
AIP
Social Schema
```

只有现有协议无法表达核心业务时才扩展 Schema。

------

## 10.5 NFT Boundary

1Sat Ordinals 用于：

```text
BAP NFT
Digital Asset
```

必须区分：

```text
BAP Identity
≠
BAP NFT
```

NFT 的转移不自动等于 BAP Identity 的转移。

------

## 10.6 Blockchain Boundary

已经确认的数据：

```text
不可修改
不可真正删除
```

因此平台只能：

```text
发布新版本
撤销
解除关系
隐藏展示
```

不能：

```text
Delete From Blockchain
```

------

## 10.7 Database Boundary

平台数据库用于：

- 草稿
- 缓存
- 索引
- 搜索
- 状态同步
- UI 数据

数据库不是：

```text
Identity Source of Truth

Content Source of Truth
```

真实性最终由：

```text
Blockchain
+
Protocol
+
Signature
```

决定。

------

## 10.8 Indexer Boundary

Indexer 是：

```text
Read Model
```

不是：

```text
Authority
```

Indexer 必须通过接口隔离，支持后续替换。

# 12. 核心约束

系统必须遵守：

```text
1. BAP ID 唯一且不可修改

2. 一个 Identity 可以创建多个 BAP NFT

3. 一个 BAP ID 同时最多绑定一个 BAP NFT

4. BAP NFT 不等于 BAP Identity

5. 一个 Content 只能属于一个 Identity

6. 一个 Content 可以存在多个 Revision

7. 已确认 Revision 不可修改

8. 修改内容必须发布新 Revision

9. 正式发布必须由用户钱包签名

10. 身份协议使用 BAP

11. 内容和关系协议优先使用 BitcoinSchema

12. 签名优先使用 AIP

13. NFT 使用 1Sat Ordinals

14. 平台不得接触用户私钥

15. 平台数据库不是真实性来源
```

# 13. 核心模型

```text
             Identity

           /          \
      creates        relates
         │              │
         ▼              ▼
      Content ◄──── Relationship
         │
         │ signed by
```

协议对应：

> **What did you say?**
> **What is your relationship with others?**
