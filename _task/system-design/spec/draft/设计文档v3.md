# 区块链个人身份、关系与内容平台——产品设计文档

> **Own your identity. Own your words.**
> 拥有你的身份，为你的言论负责。

------

# 1. 术语

## 1.1 Wallet / 钱包

用户持有私钥并对区块链交易进行授权的软件。

MVP 使用 **Yours Wallet**。

Yours Wallet 当前基于 BRC-100 Wallet Interface，支持连接、身份、签名、Ordinals、交易等能力，并通过 `@1sat/react`、`@1sat/actions` 等接口供 Web 应用调用。

平台原则：

- 钱包是密钥和交易授权入口。
- 平台不托管私钥。
- 平台不保存助记词、WIF 或钱包密码。
- 钱包实现必须可替换。

------

## 1.2 Wallet Identity Key

钱包提供的公开身份 Key。

Yours Wallet 连接后可以取得 `identityKey`。

注意：

**Wallet Identity Key ≠ BAP ID。**

它属于钱包/BRC-100 层，不应作为平台内部的 BAP ID 使用。

------

## 1.3 BAP

**Bitcoin Attestation Protocol**。

用于在 Bitcoin 上建立、管理和验证自主数字身份。

BAP 的核心思想是：

> 身份来源于密钥，而不是来源于某个中心化账户。

BAP ID 可以由身份根密钥确定性生成，并支持身份签名密钥轮换而保持 BAP ID 不变。

------

## 1.4 BAP ID

一个稳定的链上身份标识。

例如：

```text
BAP ID
    ├── Profile
    ├── Signing Keys
    ├── Attestations
    ├── Content
    ├── Relationships
    └── BAP NFT
```

核心约束：

- BAP ID 唯一。
- BAP ID 创建后不可修改。
- Profile 可以修改。
- Signing Key 可以轮换。
- Key Rotation 不改变 BAP ID。

因此产品界面应使用：

```text
Edit Profile
```

而不是：

```text
Edit BAP ID
```

等 BAP 操作。

------

# 3. BAP NFT

本平台定义的：

> **与 BAP 身份建立可验证关联的 1Sat Ordinal。**

它用于提供一个：

- 可视化身份载体
- 链上身份凭证
- 收藏型身份对象
- BAP Identity Card

需要特别区分：

```text
BAP ID = 身份本身
BAP NFT = 身份对应的链上资产/凭证
```

**NFT 不拥有 BAP 身份。**

真正控制 BAP 身份的是密钥。

1Sat Ordinals 协议本身定义的是单 satoshi inscription、ownership chain 和 origin，并没有定义一个独立的标准实体叫做“BAP NFT”。因此本平台的 BAP NFT 是建立在 **1Sat Ordinals + MAP + BAP Signature** 之上的应用组合，而不是重新定义 Ordinals 协议。

------

# 4. Active BAP NFT

一个 BAP ID 可以创建多个 BAP NFT。

例如：

```text
BAP ID
 │
 ├── NFT #1
 ├── NFT #2
 └── NFT #3   ← ACTIVE
```

但：

> **同一个 BAP ID 同一时间只能绑定一个 Active BAP NFT。**

因此：

```text
BAP ID : BAP NFT

1 : N   历史创建关系
1 : 0..1 当前有效绑定关系
```

NFT 可以重新创建或重新绑定，但不能同时存在两个 Active NFT。

------

# 5. 1Sat Ordinal

运行在 BSV 上的 Ordinals 实现。

一个有效的 1Sat Ordinal inscription 位于一个 **1 satoshi output** 中，并通过 origin 追踪其所有权历史。

Ordinal ID 可表示为：

```text
txid_vout
```

Ordinal 可：

- 创建
- 持有
- 转移
- 再 inscription
- Burn

因此 BAP NFT 的资产层采用 1Sat Ordinals。

------

# 6. Bitcoin Schema

平台内容和关系的主要链上数据标准。

原则：

> 平台不重新设计自己的内容协议。

优先采用 Bitcoin Schema 已定义的语义模型。

Bitcoin Schema 当前提供 Post、Reply、Repost、Like、Follow、Friend、Ordinal 等标准结构，其目标就是让不同应用共享可互操作的链上数据。

------

# 7. B Protocol

负责存放实际内容。

例如 Markdown：

```text
# Own your words

Everything I write is signed by me.
```

Bitcoin Schema Post 支持：

- text
- Markdown
- image
- binary

等内容。

------

# 8. MAP

Magic Attribute Protocol。

负责表达内容语义。

例如：

```text
app  ownword
type post
context tx
```

用于告诉索引器：

> 这笔链上数据是什么。

------

# 9. AIP

Author Identity Protocol。

负责：

> 对链上数据进行作者签名。

Bitcoin Schema Post 的标准组合形式为：

```text
B
+
MAP
+
AIP
```

例如：

```text
B <content> <mediaType> <encoding>
|
MAP SET app <app> type post
|
AIP <signature>
```

------

# 10. 平台目标

设计一个：

> **由用户控制身份、关系和内容的开放式区块链内容平台。**

用户拥有：

```text
Identity
Relationships
Content
NFT
```

平台只负责：

```text
创建工具
展示工具
索引工具
验证工具
```

而不是成为数据所有者。

------

# 11. 核心理念

平台围绕四个原则设计。

## 11.1 Own Your Identity

身份由用户密钥控制。

不是：

```text
User → Platform Account
```

而是：

```text
User
 ↓
Wallet
 ↓
BAP Identity
 ↓
Platform
```

平台只是 BAP Identity 的客户端。

------

## 11.2 Own Your Words

文章最终发布到 Bitcoin。

平台数据库不是最终数据源。

```text
Blockchain
    ↓
Indexer
    ↓
Platform
```

Blockchain 是事实来源。

Indexer 和数据库只是：

```text
Cache
Search Index
Projection
```

------

# 12. Responsible for Your Words

内容发布之前由 BAP 身份授权签名。

形成：

```text
BAP Identity
      ↓
Signature
      ↓
Content
      ↓
Transaction
```

任何人可以验证：

```text
是谁发布
内容是否被修改
交易是否存在
```

------

# 13. 不可篡改的真实含义

“完全控制内容”不等于：

> 用户能够删除已经写进 Blockchain 的历史交易。

链上内容发布后具有不可变性。

因此平台定义：

### 发布之前

用户可以：

```text
Create
Edit
Delete
Preview
```

### 发布之后

原始记录：

```text
Immutable
```

后续如果需要修改，应创建：

```text
New Version
Amendment
Correction
```

而不是修改原始交易。

MVP 暂不实现链上文章版本管理。

# 21. BAP Key Rotation

身份安全功能。

```text

   │
Old Key
   ↓
Rotate
   ↓
New Key
```

```text

```

产品 UI：

```text

 └── Rotate Identity Key
```

# 34. NFT 转移规则

1Sat Ordinals 原生支持 transfer。

但：

> NFT 转移不等于 BAP Identity 转移。

因此：

```text
Transfer NFT
     ≠
Transfer BAP ID
```

BAP Identity 仍由 BAP Key 控制。

如果当前 Active BAP NFT 被转移：

```text
BOUND
 ↓
TRANSFERRED
 ↓
INVALID_BINDING
```

平台自动取消：

```text
Active Binding
```

防止出现：

> NFT 持有人被错误认为拥有对应 BAP 身份。

# 87. 产品设计核心原则

整个项目后续无论做产品、架构还是代码，都建议坚持以下七条规则：

**1. BAP ID 是身份，NFT 不是身份。**

**2. 钱包控制密钥，平台不控制身份。**

**3. Blockchain 是事实来源，数据库只是索引。**

**4. 内容优先采用 Bitcoin Schema，不重新定义内容协议。**

**5. 所有公开内容必须能够追溯到签名和 Transaction。**

**6. 所有 Wallet、Protocol、Indexer 都必须通过 Adapter 解耦。**

**7. 所有关键操作都必须让用户明确知道自己正在签什么。**

这样产品的核心思想才真正对应：

> **Own your identity. Own your words.**
>
> 身份属于你。
> 言论属于你。
> 签名来自你。
> 责任也属于你。
