## 4. 状态与数据一致性

应用分别维护 WalletSession、IdentityResolution、ProfileDraft 和 Operation。后端资料、表单草稿、交易确认状态不共用一个对象。

1. 钱包连接后取得钱包身份公钥，由身份 Action 派生 BAP ID，再查询后端身份契约。钱包公钥与 BAP ID 使用不同类型，不能互相代用。
2. 解析明确返回已发布、未发布、资料不完整或读取失败。超时、离线和未知不能落入“身份不存在”。
3. 每次连接、账户变化或断开递增 `sessionEpoch`。解析、图片解码、上传和交易结果都绑定 epoch 与 operationId；旧结果不得写入新账户。
4. Review 冻结待确认资料。取消创建或保存保留草稿；确认成功前不覆盖已发布资料。重复点击只启动一个操作。
5. 名称必填、最多 100 个字素簇；简介最多 1000 个字素簇；类型限定 Person/Organization，使用 `Intl.Segmenter` 统一计数与校验，回退行为有测试。
6. 未改动资料不能保存；未保存离开覆盖站内跳转、浏览器后退和刷新。刷新使用浏览器原生离开提示，不能假装可定制其文案。
7. 断开清除当前应用的身份、草稿和监听器，不触发钱包整体 sign out。尚未能取消的真实外部请求只能丢弃返回结果；Mock 同样覆盖迟到回调。
8. 交易请求超时不等于未广播。已返回 txid 时继续查验；未返回时显示结果待核实并重新解析，不自动再签一次。
9. Mock 数据按 BAP ID 隔离并提供确定性重置。开发环境可跨刷新保留模拟发布结果；草稿默认仅当前会话保存，偏好独立保存。

## 5. 后端契约草案

本节定义应用层 HTTP 契约，不声称现有 metanet4j 已实现。DTO 与映射在前端仓库集中定义，后续后端实现按相同样例做契约测试。核心协议含义仍引用核心认知，不由 Mock 重新定义。

### 5.1 公共数据结构

```ts
type Profile = {
  name: string;
  type: 'Person' | 'Organization';
  bio: string;
  imageUrl: string | null;
};
type ProfileSnapshot = Omit<Profile, 'name' | 'type'> & {
  name: string | null;
  type: Profile['type'] | null;
};
type Meta = {
  requestId: string;
  source: 'mock' | 'indexer';
  observedAt: string; // ISO 8601，表示实际观测时间
};
type ApiError = {
  error: {
    code: string;
    retryable: boolean;
    field?: 'name' | 'type' | 'bio' | 'image';
  };
  meta: Meta;
};
type IdentityResolution =
  | { kind: 'not-found'; bapId: string }
  | { kind: 'published'; bapId: string; profile: ProfileSnapshot;
      idTxid: string; profileTxid: string | null;
      missingFields: Array<'name' | 'type'> };
```

所有成功响应为 `{data, meta}`。未知字段可忽略，契约要求的字段缺失、标识不匹配、时间格式错误按协议错误处理，不能展示成功。ProfileSnapshot 用 null 明确表达旧资料缺失的姓名或类型，`missingFields` 与之保持一致；可选简介和图片分别归一为空字符串和 null。缺失必填资料进入补全，不存在与不完整不可混为一类。提交使用经校验的 Profile，不能因 DTO 默认值掩盖缺失。

时间、TxID、BAP ID、用户资料不随语言切换改写。HTTP 错误通过稳定 code 映射本地文案，不向用户直接显示 Java 异常、钱包内部堆栈或英文系统字符串。

### 5.2 HTTP 端点

| 方法与路径 | 输入 | 成功响应 data | 错误与边界 |
| --- | --- | --- | --- |
| `GET /api/v1/identities/{bapId}` | 完整且正确编码的 BAP ID | `IdentityResolution`；200 + `not-found` 表示本次成功检索未发现发布记录 | 400 无效标识；502 上游错误；503 读取不可用；超时进入解析失败，不返回 not-found |
| `GET /api/v1/transactions/{txid}` | 完整 TxID | `{txid, visibility:'unknown'\|'observed', networkAccepted:boolean\|null, confirmations:number\|null, identitySignature:'unverified'\|'valid'\|'invalid'}` | 未观测到返回 unknown，接受状态为 null；确认数仅在可核实主链归属时返回；不以 txid 存在推导成功 |
| `POST /api/v1/avatar-uploads` | `multipart/form-data`，字段 file | 201：`{assetId, url, contentType, byteLength}` | 413 体积超限；415 类型不支持；422 解码失败；503 存储不可用 |
| `GET /api/v1/assets/{assetId}` | 上传响应返回的资源标识 | 图片字节及正确 Content-Type | 404 资源不存在；不支持任意外部 URL 代理 |

头像格式与原型一致：PNG/JPEG/WebP。初始上传限额设为可配置的 5 MiB，这是实现默认值，不是协议事实；前后端共用验证参数。Mock 将文件保存至 gitignore 的本地目录并返回稳定 HTTP 地址，使刷新后仍可显示。表单选择后先本地预览，提交时上传；blob URL 不写入发布 Profile。图片替换和取消时释放本地 object URL；头像读取失败回退至字母图案。

实际链上交易仍由钱包 Action 负责。以上后端 API 不接收私钥，不代替钱包签名；没有“POST 一个 Profile 即宣布已上链”的生产接口。

### 5.3 Profile 映射和后续收口

界面字段 `name/type/bio/imageUrl` 在适配边界映射为 SDK 的 Schema.org `name/@type/description/image`。本地 metanet4j 的 Identity 模型具有 `alternateName`、`@type`、`description`、`image`，未见 `name` 字段；这是已发现的接入差异，不能直接把 Java 对象当 DTO。

Mock 先遵守上述应用 DTO，保留 `name` 和 `alternateName` 的后端样例用于后续适配测试。真实阶段由后端实施者根据 Schema 与既有数据确认读取兼容和写入规则；不在前端给两个不同字段静默赋同一含义。签名封装及区块状态映射亦在真实阶段以核心认知第 12 节要求和真实样例收口。

## 6. 钱包 Mock 与真实 API 的对应

### 6.1 已知接口形状

以本地锁定的 1Sat SDK 源码为依据，应用只依赖连接、会话和 Identity Actions 的窄接口，不构建一个完整钱包。

| 真实 API 边界 | Mock 需保持的行为 |
| --- | --- |
| `connectWallet(config): Promise<ConnectWalletResult \| null>` | 返回 `{wallet, provider, identityKey, disconnect}` 的相同形状；支持未发现、连接中、批准、拒绝、异常 |
| `WalletInterface.getPublicKey(...)` | 区分 `{identityKey:true}` 与 BAP `protocolID/keyID/counterparty` 派生参数；按账户返回固定公钥样例 |
| `createWalletSession` 的身份变化、断开事件 | 触发 `identityChange` / `disconnected` 等适配后事件，清理订阅并使旧操作失效 |
| `computeBapId(ctx)` | 固定公钥样例经已核实算法得到稳定 BAP ID；改资料不改身份标识 |
| `updateProfile.execute(ctx, {profile})` | 返回已读 `IdentityResponse` 形状；支持确认、取消、失败、超时及成功后索引延迟 |
| `resolveBapId/getProfile` 的钱包记录 | 仅表示钱包本地记录；不代替 HTTP 的公开发布判定 |

Mock 与真实实现共享 TypeScript 输入输出类型和契约样例。在 SDK 边界模拟连接及高层 Identity Action，底层以 `Pick<WalletInterface, …>` 明确声明实际使用的子集；如果接入点要求完整 WalletInterface，则其余方法提供类型正确的 unsupported 拒绝实现，不用 `as any` 伪装完整钱包。页面不得通过硬编码延时直接把 published 改为 true。

外部错误在钱包适配层归一化为 `cancelled`、`unavailable`、`timeout`、`failed` 或 `outcome-unknown`；SDK 返回 `{error}` 也必须处理，不能只捕获 Promise rejection。取消码和超时形式以锁定 SDK 的实际实现为准，未核实的错误不能按字符串猜成“用户取消”。

### 6.2 应用内部端口

```ts
type WalletSessionResult =
  | { kind: 'connected'; identityKey: string; provider: string }
  | { kind: 'cancelled' | 'unavailable' }
  | { kind: 'failed'; retryable: boolean };
type WalletOperationResult =
  | { kind: 'submitted'; operationId: string; txid: string; bapId: string }
  | { kind: 'cancelled'; operationId: string }
  | { kind: 'failed'; operationId: string; code: string; retryable: boolean }
  | { kind: 'outcome-unknown'; operationId: string; txid?: string };
type WalletEvent =
  | { type: 'identityChange'; previous: string; next: string }
  | { type: 'disconnected'; reason: 'unauthenticated' | 'unavailable' | 'manual' };
interface IdentityWalletPort {
  connect(): Promise<WalletSessionResult>;
  disconnect(): void;
  deriveBapId(): Promise<string>;
  publishProfile(input: {
    operationId: string;
    bapId: string;
    profile: Profile;
    sessionEpoch: number;
  }): Promise<WalletOperationResult>;
  subscribe(listener: (event: WalletEvent) => void): () => void;
}
```

该端口是 OwnWord 内部接口，不冒充 SDK 原生方法。`WalletOperationResult` 使用 submitted（含 txid）、cancelled、failed、outcome-unknown 的联合类型；提交结果与链上观测分别维护。端口将 Profile 映射到真实 Action 输入，Mock 也经过同一映射和输入校验。`operationId/sessionEpoch` 是应用关联字段，不擅自加入 SDK 不接受的协议参数。

本地 `updateProfile` 在首次发布时会合并 ID + ALIAS，已有身份时仅更新 ALIAS。因此不预先写死 `publishIdentity` 后再 `updateProfile` 的双交易流程。真实接入时核对已发布记录与钱包 basket 的一致性；不以钱包 basket 缺失决定重复发布 ID。

### 6.3 模拟账本与场景

Next 的 Mock 服务维护一个可重置、按 BAP ID 隔离的模拟账本。Mock 钱包批准操作后通过仅 Mock 环境可用的 `/api/__mock__/…` 写入账本；正常 UI 仍经 `/api/v1` 查询结果。模拟写入口校验 operationId，同一请求重复到达只产生一条记录。账本与头像存在 gitignore 目录中，使用原子文件更新；它是本地演示存储，不冒充生产数据库。

最少提供：已有完整身份、新身份、资料不完整、钱包不可用、拒绝连接、拒绝创建/保存、解析失败后恢复、上传失败、广播结果未知、索引延迟、交易失败、切换账户以及断开后的迟到结果。两套固定账户能复现隔离问题；测试通过固定场景和可控时间驱动，不依赖随机故障或易抖动的固定 sleep。

Mock 确认面板允许批准和取消，视觉沿用原型确认流程，并标识“模拟钱包”；全局只需低干扰的 Mock 环境标识，错误注入放开发入口或测试夹具，不进入普通使用步骤。Mock 返回的签名验证维持 unverified，不伪造密码学验证。模拟成功可以用于流程验收，报告必须明确其模拟来源。

环境以 `OWNWORD_INTEGRATION_MODE=mock|live` 统一选择配对的钱包和后端实现，默认 mock；服务端只将这一非敏感模式传给客户端 Provider。live 配置缺失时报告配置错误，不静默退回 Mock。Mock 模式能在没有钱包扩展、后端地址和真实资金时完成全部流程；live 模式的模拟写入和场景管理端点返回 404，不执行模拟逻辑。

本地参考包为 `@1sat/connect 0.0.95`、`@1sat/actions 0.0.221`，而 Yours Wallet 源码依赖较早版本。它们是审计来源，并非已验证的生产依赖组合。实施时按实际可安装版本锁定类型和样例；若包兼容阻塞，以版本化的最小契约类型继续 Mock，并记录精确差异，不能趁机升级 Next/React 或改变业务契约。
