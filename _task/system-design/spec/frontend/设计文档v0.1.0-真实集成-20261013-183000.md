## 3. 数据流

### 3.1 连接与读取

1. 连接适配取得实际 walletIdentityPublicKey，检测 network=main。通过真实 computeBapId 取得 BAP ID。
2. 请求身份 HTTP。后端从已验证投影读取；缺失时尝试配置的实际公共 BAP 查询和原始交易核验。不能用空 MongoDB 表直接判定身份未发布。
3. DTO 区分 published、incomplete、not-published、unknown。not-published 同时要求成功公共查询、明确无有效记录及充分覆盖；判断细则见第 4.1 节。索引 404 或覆盖不足返回 unknown，上游不可用返回可重试错误。
4. 钱包 basket 用于签名序列和钱包输出管理，不作为公开发布事实。若 public 已发布但 basket 缺失，先恢复实际记录；恢复不能完成则提示能力缺失，不重复发布 ID。
5. 账户事件和断开递增 epoch，终止未提交 Review，取消本地 fetch 并丢弃迟到结果。

### 3.2 创建、补全与更新

1. 表单校验产品属性。选图本地预览，真正发布前上传到真实头像服务，使用可持久读取的 URI。
2. Review 冻结 profile、bapId、walletIdentityPublicKey、epoch、operationId 和当前 profileTxid。先 POST 意图，确认真实存储成功后才进入 Actions；不要求此时已有 TxID。切换账户或改变输入后重新 Review。
3. 真实 Identity Actions 编码 Schema.org、派生密钥、构造 ID/ALIAS 和 AIP。WalletProvider 在转交 createAction 前截取实际请求，追加链下标签 `ownword-operation:<operationId>`，冻结请求字节并请求真实后端 preflight。首次 ID 由根声明建立归属，ALIAS 按新声明的签名者验证；逐输出验签、冻结内容和资料版本核对均先于可能的广播。
4. preflight 通过后再次核对会话 epoch、公钥和本地请求摘要，登记唯一提交尝试；仅首次明确取得执行许可的调用可以转交钱包。实际钱包可能在 createAction 内完成广播，因此不能只拦截 signAction。若返回 signableTransaction，先保存 reference 和实际交易模板，追加 signable preflight，通过后才转交 signAction；不修改或替代真实 Actions。
5. 钱包回执经适配层保留原始证据并归一化。AtomicBEEF 先解码为交易，再取原始 hex 和实际 TxID，不能把整个 BEEF 当作 rawTx。后端再次核验回执与已批准请求一致；此校验保护投影，不能替代第 3 步的发布前校验。
6. live 分支查询网络、写入真实事件、更新投影并回读；simulated 分支只写隔离操作记录并给出模拟结果，不更新生产公开身份投影。没有回执或 TxID 的不明结果也写入原操作。
7. 刷新、进程重启、回执丢失或网络超时均查询同一操作，通过原钱包 reference、操作标签及真实网络证据恢复；不自动再次执行 Actions 或授权。HTTP 重试只重放登记和查询，不承诺替钱包实现广播幂等。页面草稿保留，提交完成前不覆盖旧资料。

## 4. HTTP 契约

以下为本次需要新增的接口设计，不声称当前已存在。业务 DTO 与 Java 实体分离；成功为 {data,meta}，失败为 {error,meta}。

成功和错误响应均使用以下 meta；时间为 UTC ISO 8601。

```ts
type ResponseMeta = {
  requestId: string;
  network: 'main';
  respondedAt: string;
  source: 'chain' | 'indexer' | 'storage' | 'validator' | 'wallet-simulation' | null;
  observedAt: string | null;
};
```

respondedAt 必填，表示服务生成本次响应的时间。source 和 observedAt 必填但允许 null：没有取得实际依据时两者均为 null，不用 respondedAt 补齐。缓存返回原事实的来源和观测时间；真实存储读写、验签或钱包模拟分别使用对应来源，不标成主网观测。多个依据各自保留时间，顶层 meta 对应本次返回的主要依据。

错误包含 code、retryable 和可选 field；固定本地文案映射，不向页面输出 Java 堆栈。常用 code：INVALID_IDENTIFIER、UPSTREAM_UNAVAILABLE、SIGNATURE_INVALID、IDENTITY_MISMATCH、PROFILE_CHANGED、OPERATION_CONFLICT、ASSET_INVALID、STORAGE_UNAVAILABLE。

### 4.1 Identity

GET /api/v1/identities/{bapId}

```ts
type IdentityResolution = {
  kind: 'published' | 'incomplete' | 'not-published' | 'unknown';
  bapId: string;
  profile: {name: string | null; type: 'Person' | 'Organization' | null;
    bio: string; imageUrl: string | null} | null;
  idTxid: string | null;
  profileTxid: string | null;
  missingFields: Array<'name' | 'type'>;
  signatureStatus: 'valid' | 'invalid' | 'unverified';
  simulationPreview: IdentityOperation | null;
  indexCoverage: {
    status: 'sufficient' | 'unknown';
    provider: string | null;
    checkpoint: {height: number; blockHash: string} | null;
    historyComplete: boolean;
    recentWindowComplete: boolean;
    observedAt: string | null;
    lastResponse: {status: number; observedAt: string} | null;
  };
};
```

200 可表示实际查询后的明确分流；未知来源不返回 not-published。400 标识非法；502 上游失败；503 存储/索引不可用。客户端必须检查 bapId 与请求一致，不能默默采用不同身份。profile 字段映射 name/@type/description/image；alternateName 仅作为明确的旧格式回退，不能掩盖没有资料。

仅 simulated 服务从隔离集合读取最近一次完成的真实模拟操作，放入 simulationPreview；live 始终为 null。该预览不改变 kind、profile、签名及公共覆盖结论。进行中的更新、取消和失败不能覆盖上一版预览；刷新后仍从服务回读。当前操作与上一版资料分别维护，结果未知只允许核实原操作，明确取消或未提交才开放重新 Review。

操作登记只接受 DTO 中声明的意图字段，内部锁、验证结果和状态不能由请求注入。已保存原始交易的操作收到迟到取消、未提交或传输错误时返回当前记录，不将已验证回执降级。

否定结果只有在成功读取且没有有效 ID，同时覆盖证据充分时才返回 not-published。充分覆盖要求：实际数据源覆盖该 BAP ID 的历史 ID/ALIAS 及签名历史；主链 checkpoint 已核实、回填和订阅没有缺口；近期未确认与新增交易窗口已同步到本次观测时点。服务依据数据源契约和真实同步状态计算 status，不接收客户端覆盖声明，不用配置中的 true 代替证据。

参考公共 BAP 接口从自身索引存储返回 404，未提供上述覆盖证据；本期默认将这种结果归为 unknown。空数据库、分页列表无结果、单笔交易暂不可见及过期 checkpoint 均不开放新建。找到可验证 ID 时可以确认已发布；最新 Profile 顺序尚不充分则保持待核实，不将旧缓存当作当前资料。A00 必须核实所选真实数据源的 endpoint、否定语义和 checkpoint，证据未满足时不关闭未发布分流验收。

lastResponse 仅记录实际公共 HTTP 状态与取得响应的时间，不能替代 observedAt、checkpoint 或充分覆盖。权限拒绝与无覆盖证明保持 unknown；超时、连接错误和 5xx 返回可重试 502。原始交易已取得但缺少对应身份签名历史时，签名归属为 unverified，不能仅凭缺少历史记为 invalid。

### 4.2 原始交易与操作

操作按意图、校验、提交尝试和回执分别登记，API 自身不调用钱包或代为广播。

POST /api/v1/identity-operations：钱包提交前持久化冻结意图。

```ts
type OperationIntent = {
  operationId: string;
  bapId: string;
  kind: 'create' | 'profile-update';
  walletIdentityPublicKey: string;
  sessionEpoch: number;
  expectedProfileTxid: string | null;
  profile: {name: string; type: 'Person' | 'Organization'; bio: string; imageUrl: string | null};
};
type OperationResult = {
  operationId: string;
  bapId: string;
  status: 'reviewed' | 'validating' | 'prepared' | 'awaiting-wallet' | 'cancelled'
    | 'submitted' | 'indexing' | 'published' | 'simulated' | 'outcome-unknown' | 'failed' | 'abandoned';
  broadcastMode: 'live' | 'simulated';
  txid: string | null;
  walletReference: string | null;
  profileDigest: string;
  preflight: {validationId: string; requestDigest: string} | null;
  submissionAttempt: {attemptId: string; validationId: string} | null;
  networkAccepted: boolean | null;
  identitySignature: 'valid' | 'invalid' | 'unverified';
};
```

Idempotency-Key 必须等于 operationId。首次意图写入返回 201/reviewed；相同键、相同冻结内容返回 200 和既有记录，不重新执行 Actions；不同内容返回 409。字段 400、旧版本 409、数据库失败 503。登记失败或结果不明时先查同一操作，取得明确登记结果前不调用可能广播的钱包方法。

profileDigest 固定为 SHA-256(UTF-8(JSON.stringify([name,type,bio,imageUrl])))，数组顺序固定，字符串不做隐式 trim、Unicode 归一化或翻译，imageUrl 无值用 null。Java 按相同 JSON 字符串转义及 UTF-8 规则计算，不能使用属性顺序可变的对象序列化。编码后的 ALIAS 解析为同四字段精确比较；Schema.org 字段映射与 Review 一致。

名称与简介的字符计数沿用固定原型的扩展字素簇规则。前端使用 Intl.Segmenter，Java 25 使用正则 \X；校验和计数不改变原始字符串、摘要或签名字节。

POST /api/v1/identity-operations/{operationId}/preflight：真实广播前校验。

```ts
type PreflightRequest =
  | {phase: 'request'; createActionArgsJson: string}
  | {phase: 'signable'; validationId: string; walletReference: string; unsignedRawTx: string};
```

request 阶段接收真实 Actions 交给 WalletProvider 的实际请求 JSON。后端计算原始 UTF-8 请求摘要、解析实际 lockingScript、逐输出验证 AIP/BAP 归属及冻结资料，重新核对 expectedProfileTxid；通过后保存请求字节及 validationId，返回 200/prepared。拒绝缺签、内容变化、错误身份、无关业务输出或未批准的 sendWith；失败为 422，资料版本变化为 409。相同请求幂等返回既有校验结果；新请求不能覆盖尚未核实结果的提交。cancelled/failed 只有明确未提交证据、用户再次 Review 且冻结意图未变时可重新预检，旧校验和尝试保留；内容变化建立新 operationId。

signable 阶段保存真实 reference 和已解码交易模板，验证钱包保留已核验的业务输出；模板含资金输入和找零，尚无完整花费签名，因此 unsignedRawTx 的哈希不作为最终 TxID。通过后维持 awaiting-wallet 并记录对应模板；验证失败阻止 signAction，明确未提交时 abortAction。两阶段都不生成公开身份投影。

POST /api/v1/identity-operations/{operationId}/submission-attempts：登记一次钱包执行许可。请求为 {attemptId,validationId,requestDigest}，三个值绑定已批准的同一请求。后端重新核对资料版本和校验有效性，再原子地将 prepared 改为 awaiting-wallet 并记录尝试；同一 network+bapId 还有待核实提交时拒绝另一 operationId。仅首次响应返回 201 和 executionGranted=true，重复请求返回 200 和 executionGranted=false。状态或资料版本冲突为 409，存储失败为 503。适配层核对 epoch、公钥和请求摘要后才能申请，明确取得首次许可后只转交一次该请求；许可响应丢失时不依据 GET 或重复 POST 的结果补发钱包调用，先恢复原操作。

prepared 只是预检就绪，awaiting-wallet 表示请求可能进入钱包处理，均不代表网络接受。HTTP 无法与插件调用组成原子事务；提交尝试保留以防刷新后重复调用，超时不自动释放。只有明确取消或证实未提交后，用户重新 Review 才能建立下一次尝试，旧尝试不能删除。

POST /api/v1/identity-operations/{operationId}/wallet-results：记录实际钱包回执或不明结果。

```ts
type WalletResultRequest =
  | {kind: 'receipt'; attemptId: string; txid: string; rawTx: string}
  | {kind: 'outcome-unknown'; attemptId: string; txid: string | null;
      rawTx: string | null; walletReference: string | null; code: string}
  | {kind: 'cancelled' | 'unsubmitted'; attemptId: string; walletReference: string | null; code: string};
```

receipt 仅接收原始交易 hex，后端计算实际 TxID、验签并与已批准业务输出及 signable 模板核对；相同回执幂等，不同交易不能替换同一次尝试。非法签名、错误归属或内容变化返回 422 并保留实际执行证据；如果可能已广播，操作保持 outcome-unknown，不显示“未提交”，不自动重发。缺少 TxID 的未知结果可返回 202/outcome-unknown 并持久化，页面按 operationId 查询。

cancelled/unsubmitted 只能由适配层保留的明确钱包拒绝、调用尚未转交或其他确定未提交证据归类；不得用 SDK 的通用 error、空 listActions 或网络 404 推断。提交可能性无法排除时统一 outcome-unknown。

broadcastMode 由部署和测试钱包传输来源决定；普通请求不能把模拟 TxID 标成真实。live 必须从主网取得与 rawTx 相同的交易才能进入生产投影。接入阶段限制接受协议输出集合，拒绝无关交易及缺失 identityKey 证明。

GET /api/v1/identity-operations/{operationId}：从真实存储查询同一意图、尝试及当前状态，reviewed/awaiting-wallet/outcome-unknown 均允许 txid=null；404 只表示未登记，不表示钱包或链上没有交易。适配层用操作标签分页查询实际 listActions，结合原 reference 找回实际 TxID，再从真实网络取得 rawTx 并核验归属后记录原操作。钱包无记录或网络不可用保持未知，查询路径不调用 updateProfile/createAction/signAction。模拟入口绑定 loopback 与隔离数据库，生产部署关闭。

首次登记前保存 operationId，并在当前调用内保留冻结意图。只有尚未收到登记成功、从未进入 Actions 且原账户/epoch 未变时，才允许重放同一 UUID 的首次登记；它不调用钱包。刷新后缺少这份当前调用证据，或许可/回执响应丢失时，必须先查询原操作，不能凭较早的 reviewed 状态或 404 重新发布。

GET /api/v1/transactions/{txid}：实际网络读取与验签。返回 txid、rawTx（原始 hex/null）、visibility（unknown/observed）、networkAccepted（boolean/null）、confirmations（integer/null）、identitySignature 及每个 BAP 输出的验证结果。未观测时保留 unknown，rawTx=null；不把 simulated 操作回执混入该接口的主网结果。

### 4.3 头像

POST /api/v1/avatar-uploads：multipart file，PNG/JPEG/WebP，初始最大 5 MiB；检查字节、MIME 与可解码性。解码前检查单边不超过 8192 px、总像素不超过 1600 万，防止小压缩文件触发过量内存分配。WebP 复用 Java ImageIO SPI，通过 [TwelveMonkeys imageio-webp 3.12.0](https://github.com/haraldk/TwelveMonkeys/tree/master/imageio/imageio-webp) 解码。201 返回 assetId、url、contentType、byteLength；413 超限，415 不支持，422 无效图片，503 存储不可用。

GET /api/v1/assets/{assetId}：返回真实图片字节、Content-Type、ETag 和缓存头；assetId 仅 SHA-256，不接收文件路径或任意 URL。404 不存在。上传真实写入隔离存储，重启后可读；取消编辑不删除已发布图片。生产配置 PUBLIC_ASSET_BASE_URL 必须是可公开读取的 HTTPS 地址；本地 loopback 结果仅作为本地集成证据。

写接口限制 Origin、大小、并发与上传配额，图片始终当作图片响应且不执行脚本。测试数据库及本地资产使用独立命名空间。

### 4.4 运行入口

GET /health：只有真实 MongoDB 和必需配置就绪才 ready；链查询依赖不可用单独列出，不假装 healthy。Next 同源 /api 仅转发明确 allowlist 到配置的 OWNWORD_API_URL，不接受任意代理目的地。缺配置返回可恢复错误，不返回样例成功。

### 5.1 广播前适配与恢复

WalletProvider 对真实 CWI 做最小边界适配：登记请求、调用第 4.2 节真实校验接口、核对账户、保留原始结果，其他方法继续委托实际钱包。真实 updateProfile 始终使用该 provider；未接入预检的原始 CWI、自动广播的外部 fundingProvider 路径不得用于 live 发布。

请求预检必须先于 createAction。signAndProcess=false、noSend 或 SDK 函数名都不能单独证明不会广播；本地权限模块的 createAction 响应处理可能完成交易流水线。获准的请求使用冻结字节重建参数，禁止预检后变更业务输出、目标及提交选项。返回可签交易时再做模板预检；完整回执按 Transaction.fromAtomicBEEF 解码，取得 toHex 和 id，保留 BEEF 作为钱包证据，不将其整体 hex 传给 rawTx。

W00/I06 必须核实锁定 Yours/CWI 路径是否保持已批准业务输出及授权账户，是否能终止未提交的旧账户授权。账户变化在转交前使许可失效；转交后先取消可终止的原请求，无法排除已提交时记录 outcome-unknown 并归原身份核实。若插件内部自动处理无法满足上述契约，阻塞该 live 路径，不绕过预检，也不声称发布后的 422 能撤回交易。

隔离测试钱包在公开解析 unknown 时提供明确标记的“准备模拟资料”，仅创建模拟操作意图；结果和会话内预览读取真实 simulated_operations，更新关联上一笔模拟回执。它不改变公开解析结果、不开放真实创建，也不写 identity_projection。生产钱包在 unknown 时继续核实，不开放创建。

操作标签和钱包 reference 仅用于找回原交易。查询恢复执行真实 listActions 的标签过滤与分页，核对实际输出、资料摘要和 BAP 签名；多候选或证据不足继续待核实，不按最新本地时间猜测。钱包错误在 adapter 边界记录原始结构，再映射产品状态；SDK 折叠后的 error 不能单独证明未提交。

connectWallet 将多次失败折叠为 null，本地源码不能直接提供可靠取消原因。适配层采用受控 Yours 连接及原始错误证据区分 unavailable/cancelled/failed；不能凭字符串猜用户取消。Account Switch 同时监听事件及认证/公钥变化，避免扩展事件漏送。

测试钱包钥匙不进入 Next 客户端或 Java 服务。测试接口 loopback-only，令牌及钥匙通过隔离配置读取且不输出。模拟输入/花费能力仅发生在钱包边界；原始交易的身份内容签名真实校验，资金有效性和网络确认仍为未验收。

## 6. 后端存储、解析与索引

1. MongoDB 分开保存 chain_events、identity_projection、identity_operations、simulated_operations、avatar_assets。操作以 operationId 唯一，保存冻结意图、预检请求、钱包 reference、尝试和回执；提交许可通过单文档条件更新原子取得。awaiting-wallet/submitted/indexing/outcome-unknown 通过 network+bapId 的部分唯一索引限制为一个活动操作，结果未知时不释放；重复键返回 409。模拟操作同样真实持久化，但不能进入前两者。
2. 真实事件唯一键 network+txid+vout，保留原始字节/来源摘要、块位置、签名和观测时间。重复摄入、重启重放及失败重试不重复写资料版本。
3. 每笔交易逐输出识别 BAP 与 AIP。首先验证根 ID 的派生关系和声明，再验证同交易 ALIAS。历史签名按当时有效地址判断，不只查当前 rootAddress。
4. 旧 MongoBapService 的 Optional.get 缺失处理、Identity.name 映射、首次双输出解析需定向修复并有真实输入验证。旧 Planaria JSON 不作为新钱包原始交易的已验证兼容入口。
5. 公共索引路径先核实真实 endpoint、响应与覆盖范围。可复用已验收 JungleBus 客户端接入原始交易，业务仍负责解析、持久化、排序和重建。既有匿名订阅样本不能证明包含本次测试交易；发布测试须确认本次 txid 被实际索引。
6. 资料排序以验证过的链关系与区块位置为依据；无链序证据的冲突返回 unknown，不按客户端 Date.now 选择最新。重组先回滚受影响主链投影，再重放；无法取得必要信息时显示待核实。
7. 不要求启动本期不需要的全部中间件；最小应用需要真实 MongoDB、真实文件持久化、主网查询。需要其它设施时沿用共享 infra。
