## 3. 数据流

### 3.1 连接与读取

1. 身份控制器依赖 WalletProvider 公共接口，连接后取得 accountPublicKey、BAP ID 与 network；这些是钱包会话与密钥上下文。
2. 请求 GET identities/{bapId}。后端根据服务 scope 读取原交易派生的真实投影，返回同一 profile 字段。页面不从钱包 basket、SDK 的 getProfile 或 simulationPreview 读取业务资料。
3. scope=mainnet 保持已验证公共数据、历史与覆盖要求。scope=broadcast-mock 读取隔离测试记录：stored 表示已验签存储且资料可读，empty 表示此测试空间尚无身份记录；两者不声明主网发布或未发布。Mock 服务的空记录可进入测试创建流程。
4. 身份签名者与是否已有 ID 从后端交易记录取得；签名所需公钥仍向 WalletProvider 获取并与后端上下文核对。隐藏于 SDK Actions 的 listOutputs/basket 业务读取必须迁出，不通过代理返回固定伪记录来继续旧流程。
5. 账户变化递增 epoch，未提交 Review 失效；已签名或已广播交易保留原账户归属。钱包会话监测通过 WalletProvider，页面不接触 CWI 事件或具体实现。

### 3.2 创建、补全与更新

1. 本地校验、Review 冻结资料、图片摘要、BAP ID、账户及流程 UUID，尚不业务 POST。
2. 真实 BAP/B/MAP/AIP 模板在身份业务模块编码输出，通过 WalletProvider 获得授权内容签名；实际 SDK 交易流水线在具体钱包适配器内部完成资金输入、找零与交易签名。
3. WalletProvider.prepareTransaction 保证此步骤不广播，返回已签名 rawTx 与其 TxID。业务层验证原交易保留冻结输出并先写 IndexedDB；本地持久化失败时不进入广播。
4. 调用 WalletProvider.broadcastTransaction 广播同一已签名原交易。第一阶段本地适配器 Mock 广播结果，交易字节和 TxID 保持原值；明确拒绝/失败不业务 POST，未知结果保留状态。
5. 广播 accepted 后保存 BroadcastReceipt，再 POST transactions/sync。后端重新计算 TxID、解析并验签，只从原交易生成身份、资料、图片和历史，不接收另一份 Profile。
6. 同步失败只重放同一原交易；成功后重新 GET 身份与图片，页面展示后端结果，操作回执不能代替资料查询。Mock 广播的真实后端投影写入隔离命名空间，不写生产公开投影。
7. 准备回执丢失由 WalletProvider.recoverPreparation 封装钱包内部未广播过程恢复。已广播业务查询通过后端；有 rawTx 的广播未知先查后端，Mock 模式允许用户明确重试同一已签名交易的广播，不执行再次构造或签名。旧无 rawTx 操作保持未知。
8. 首次无头像可将 ID+ALIAS 放同一交易；首次带头像依次 ID、图片、ALIAS，最多三笔，每笔都应用上述持久化、广播与同步要求。公开/费用、部分成功与取消边界在 Review 说明。

## 4. HTTP 契约

以下为本次接口契约；实际实现与验收状态见统一任务清单。业务 DTO 与 Java 实体分离；成功为 {data,meta}，失败为 {error,meta}。

成功和错误响应均使用以下 meta；时间为 UTC ISO 8601。

```ts
type ResponseMeta = {
  requestId: string;
  network: 'main';
  respondedAt: string;
  source: 'chain' | 'indexer' | 'storage' | 'validator' | 'wallet-simulation' | null;
  observedAt: string | null;
};
```

respondedAt 必填，表示服务生成本次响应的时间。source 和 observedAt 必填但允许 null：没有取得实际依据时两者均为 null，不用 respondedAt 补齐。缓存返回原事实的来源和观测时间；真实存储读写、验签或钱包模拟分别使用对应来源，不标成主网观测。多个依据各自保留时间，顶层 meta 对应本次返回的主要依据。

错误包含 code、retryable 和可选 field；固定本地文案映射，不向页面输出 Java 堆栈。常用 code：INVALID_IDENTIFIER、UPSTREAM_UNAVAILABLE、SIGNATURE_INVALID、IDENTITY_MISMATCH、PROFILE_CHANGED、OPERATION_CONFLICT、ASSET_INVALID、STORAGE_UNAVAILABLE。

### 4.1 Identity

GET /api/v1/identities/{bapId}

```ts
type IdentityResolution = {
  scope: 'mainnet' | 'broadcast-mock';
  kind: 'published' | 'incomplete' | 'not-published' | 'unknown' | 'stored' | 'empty';
  bapId: string;
  profile: {name: string | null; type: 'Person' | 'Organization' | null;
    bio: string; imageUrl: string | null} | null;
  idTxid: string | null;
  profileTxid: string | null;
  missingFields: Array<'name' | 'type'>;
  signatureStatus: 'valid' | 'invalid' | 'unverified';
  currentAddress: string | null; // 已验证 ID 声明的当前签名地址
  indexCoverage: {
    status: 'sufficient' | 'unknown';
    provider: string | null;
    checkpoint: {height: number; blockHash: string} | null;
    historyComplete: boolean;
    recentWindowComplete: boolean;
    observedAt: string | null;
    lastResponse: {status: number; observedAt: string} | null;
  };
};
```

200 可表示实际查询后的明确分流；未知来源不返回 not-published。400 标识非法；502 上游失败；503 存储/索引不可用。客户端必须检查 bapId 与请求一致，不能默默采用不同身份。profile 字段映射 name/@type/description/image；alternateName 仅作为明确的旧格式回退，不能掩盖没有资料。

scope 由服务部署决定，普通请求不能指定。broadcast-mock 的 profile 来自后端已验签原交易及实际存储，使用同一 GET 查询字段；不提供 simulationPreview，也不由前端读取操作日志拼接资料。测试投影按服务首次接收的固定顺序重建，重复同步不重新排序；该顺序不用于主网。取消、失败和未同步交易不覆盖上一版资料。生产公开存在性和覆盖证明仍按下述主网规则。

交易同步只接受第 4.2 节回执字段，资料、验证结果和网络状态不能由请求注入。已保存的原交易不会被本地迟到取消降级。

否定结果只有在成功读取且没有有效 ID，同时覆盖证据充分时才返回 not-published。充分覆盖要求：实际数据源覆盖该 BAP ID 的历史 ID/ALIAS 及签名历史；主链 checkpoint 已核实、回填和订阅没有缺口；近期未确认与新增交易窗口已同步到本次观测时点。服务依据数据源契约和真实同步状态计算 status，不接收客户端覆盖声明，不用配置中的 true 代替证据。

参考公共 BAP 接口从自身索引存储返回 404，未提供上述覆盖证据；本期默认将这种结果归为 unknown。空数据库、分页列表无结果、单笔交易暂不可见及过期 checkpoint 均不开放新建。找到可验证 ID 时可以确认已发布；最新 Profile 顺序尚不充分则保持待核实，不将旧缓存当作当前资料。A00 必须核实所选真实数据源的 endpoint、否定语义和 checkpoint，证据未满足时不关闭未发布分流验收。

lastResponse 仅记录实际公共 HTTP 状态与取得响应的时间，不能替代 observedAt、checkpoint 或充分覆盖。权限拒绝与无覆盖证明保持 unknown；超时、连接错误和 5xx 返回可重试 502。原始交易已取得但缺少对应身份签名历史时，签名归属为 unverified，不能仅凭缺少历史记为 invalid。

### 4.2 原交易同步与操作

POST /api/v1/transactions/sync：只同步钱包已返回的同一笔交易；后端不调用钱包、不代为广播。

```ts
type TransactionSync = {
  operationId: string; // 本地为本笔交易生成的 UUID
  bapId: string;       // 待核对归属，不能当作已验证证明
  txid: string;
  rawTx: string;      // 原始交易 hex，不是整个 BEEF
};
```

Idempotency-Key 必须等于 txid。后端计算实际 TxID，检查 BAP 标识、逐输出协议和 AIP，再从交易解析 ID、ALIAS 或 B 图片。资料摘要为 SHA-256(UTF-8(JSON.stringify([name,type,bio,imageUrl])))；名称/简介继续使用字素簇计数，解析不改变原始字符串。拒绝额外的 Profile、状态、网络接受或验证字段，不能让客户端覆盖链上字段。

首次同步返回 201；相同 TxID 和相同原交易幂等返回 200，不增加事件、资料版本或图片副本。operationId 不能绑定另一 TxID，同 TxID 不能替换原始字节。记录保留 network+txid+vout、bapId、原始字节、协议类型、签名证据及来源时间。后端同步响应丢失后可以安全重放原请求。

live 从实际主网读取相同 rawTx 并按有效 BAP 密钥历史验证，核实后才能写 chain_events/公开投影；网络未观测、签名历史缺失或链序不明返回 202/pending，不产生假公开资料。业务接受不等于已经挖矿；confirmations 单独显示。simulated 真实验签并写隔离交易/图片及可重建测试投影，GET 身份直接返回此来源的正常 profile，networkAccepted=null，不能修改 live 公开投影。broadcastMode 由部署决定，普通请求不能升格。

响应沿用 data/meta，返回 operationId、txid、bapId、kind（identity-init/create/profile-update/avatar）、由交易取得的 profile 或 asset、原始交易/验证证据、broadcastMode、identitySignature、networkAccepted 和状态。仅 ID 声明没有 Profile，返回 profile=null；图片返回 asset，不能伪造用户资料。资料交易返回确切 Profile，客户端与冻结值比较。

400：格式或额外字段；409：同操作或 TxID 绑定冲突；422：交易、签名、身份或图片无效；503：实际存储不可用。交易可能已经广播，422/503 均不授权再次广播。

GET /api/v1/identity-operations/{operationId}：仅在旧无 TxID 操作的迁移恢复仍有实际调用时保留，只读兼容；新流程优先使用本地日志及 TxID 重放同步，前端迁移后核查并移除无调用接口。新流程无 TxID 的草稿及未知操作只在浏览器日志中，404 不表示钱包未提交。

GET /api/v1/transactions/{txid} 用于已签名/广播未知交易的业务核实：先读原交易同步记录；主网模式必要时实际查询网络。测试模式查无记录不推断从未广播。此接口因新增恢复消费者而恢复，不能返回伪造接受状态。

旧 POST identity-operations、preflight、submission-attempts、wallet-results 和 avatar-uploads 直接删除；不保留返回 410 的空接口。取消/明确未提交不写后端假交易，记录在本地；有回执的重试全部走 transactions/sync。

### 4.3 头像链上发布与读取

图片 B 输出使用真实原字节、实际 MIME 和 binary 编码，附 MAP(type=post,app=ownword) 及当前 BAP 密钥的 AIP。应用允许 PNG/JPEG/WebP，最大 5 MiB；本地校验图片尺寸，后端从交易再次解码检查单边 8192px、总像素 1600 万及字节/MIME 一致性。WebP 沿用 TwelveMonkeys ImageIO SPI，不增加另一套服务。

POST transactions/sync 接收图片交易回执，返回 assetId=txid、vout、uri=b://txid、contentType、byteLength 和内容 SHA-256。本期每笔图片交易只有一个 B 图片输出且固定为输出 0；客户端核对输出，后端拒绝歧义与无关协议。先发布 ID 再发布头像的依赖见第 3.2 节，取消 Profile 不删除图片交易。

GET /api/v1/assets/{txid}：按交易定位并返回已验证图片的真实字节、Content-Type、ETag、immutable 缓存和 nosniff。后端文件是链上图片缓存，元数据保留原交易与输出位置；丢缓存后按原交易重建，不能接受任意文件路径/URL。模拟缓存与主网数据隔离。

Profile.image 保存 b://TxID；前端 Portrait 通过同源只读接口显示。既有 HTTPS 图片引用只读兼容，新发布头像统一引用链上图片。链上图片不可撤回，Review 必须说明公开、付费和取消后的保留行为。发布费用与实际钱包限制由钱包报告，不能承诺 5 MiB 在任何钱包均可广播。

原交易 hex 会扩大图片请求体，Next 同源代理与后端共同限制同步请求为 12 MiB，图片原字节仍限 5 MiB。限制 Origin、并发与磁盘缓存配额，缓存始终按图片响应，不执行脚本。

### 4.4 运行入口

GET /health：只有真实 MongoDB 和必需配置就绪才 ready；链查询依赖不可用单独列出，不假装 healthy。Next 同源 /api 仅转发明确 allowlist 到配置的 OWNWORD_API_URL，不接受任意代理目的地。缺配置返回可恢复错误，不返回样例成功。

## 5. 独立钱包模块与稳定隔离接口

### 5.1 对外契约

WalletProvider 是业务层唯一钱包依赖，公开类型使用 OwnWord DTO、hex、数字和普通对象，不引用 WalletInterface、CreateActionArgs、SDK Transaction、window.CWI 或具体钱包私有错误。每个适配器实现相同接口，业务层不按钱包类型判断。钱包模块不导入 Profile、IdentityResolution、业务 HTTP 或同步状态。

```ts
type WalletSession = {
  providerId: string;
  accountPublicKey: string;
  bapId: string;
  network: 'main';
  capabilities: { prepareWithoutBroadcast: boolean };
};
type TransactionDraft = {
  operationId: string;
  accountPublicKey: string;
  description: string;
  outputs: Array<{satoshis: number; lockingScript: string; description: string}>;
};
type PreparedTransaction = {
  txid: string;
  rawTx: string;
  accountPublicKey: string;
  preparationId: string | null; // 钱包模块的不透明标识
};
type BroadcastReceipt = {
  txid: string;
  mode: 'live' | 'simulated';
  status: 'accepted' | 'rejected' | 'unknown';
};
interface WalletProvider {
  connect(options: {silent: boolean}): Promise<WalletSession>;
  getSession(): Promise<WalletSession | null>;
  disconnect(): Promise<void>;
  getPublicKey(input: {purpose: 'bap'; sequence: number}): Promise<string>;
  signHash(input: {sequence: number; hashHex: string; accountPublicKey: string}): Promise<string>;
  prepareTransaction(draft: TransactionDraft,
    onPreparation?: (id: string) => Promise<void>): Promise<PreparedTransaction>;
  recoverPreparation(input: {operationId: string; preparationId: string | null;
    accountPublicKey: string}): Promise<PreparedTransaction | null>;
  abortPreparation(id: string): Promise<'aborted' | 'unknown'>;
  broadcastTransaction(transaction: PreparedTransaction): Promise<BroadcastReceipt>;
}
```

公开签名返回真实 DER 签名 hex；身份业务模块用真实模板生成 AIP 并验证。sequence 是产品使用的 BAP 签名序列语义，具体派生路径封在适配器内；没有当前签名能力时明确失败。network 及账户核对贯穿准备和广播；授权、拒绝、账户变化、能力不足和结果未知通过统一错误码表达。

### 5.2 模块与依赖

```text
lib/wallet/contracts.ts  ← 稳定公共接口和 DTO
lib/wallet/index.ts      ← 唯一创建/注册入口
lib/wallet/adapters/*    ← Yours、本地钱包及后续具体适配器
lib/domain/*            ← BAP/头像编码、Review、本地日志、HTTP 同步与业务恢复
app/*                   ← 只调用 WalletProvider 和身份业务接口
```

CWI/BRC-100 的 28 个方法是具体适配器内部技术接口，不能整体暴露给页面作为模块公共接口。已有 client/test-wallet 可复用其传输与真实密码学；交易流水线复用锁定 @1sat/actions/@bsv/sdk，不新增第二套交易协议。SDK 身份 Actions 的 basket 查询依赖与后端查询边界冲突，应使用已安装的协议模板及通用交易流水线拆开编码和执行。

Yours 扩展适配器使用真实 window.CWI。第一阶段本地复用 Yours 所用的官方钱包核心：用 @1sat/utils 的 getKeysFromMnemonicAndPaths 和 YOURS_ID_PATH 得到 identityPk，交给 @1sat/wallet-node 的 createNodeWallet；它与扩展 createWebWallet 共享 @1sat/wallet 的 createWalletCore。Node 工厂与真实 SQLite 仅运行于隔离钱包进程，不在页面模拟 IndexedDB 来运行浏览器工厂。createAction、signAction、createSignature 及准备记录由官方 Wallet 处理；应用不再自己组装资金输入和找零交易。复用核心不等于已验证扩展桥接、解锁或权限弹窗。

助记词默认首次生成有效的隔离测试值并保存到忽略的私有文件，后续连接和进程重启复用。每条助记词对应一个测试钱包；同一固定 Yours 派生配置保持根公钥和 BAP ID，一条助记词不注册为两套钱包。不同助记词使用各自的钱包数据库和持久存储标识。测试允许显式导入公开测试向量用于确定性验证，但不在页面展示助记词/WIF，不通过业务 API 接收或传递，也不请求用户真实钱包种子。

测试资金入口只给官方钱包提供隔离可签名 UTXO，不代替 createAction/signAction，不声明其主网可花费。独立钱包进程使用官方工具箱 MockServices 的本地测试链保存资金与广播状态，经官方 internalizeAction 接收测试资金；业务交易的输入、找零和签名仍由官方 Wallet 生成。broadcastTransaction 内部调用官方 createAction(sendWith)，将已签名原 TxID 交给 MockServices，并由官方 Wallet 更新真实存储状态。测试链只属于钱包资金/广播环境，不替代业务后端、主网读取或公开索引。关闭官方钱包自动后台广播，以准备不广播及未外发测试交易的实际证据验收。未广播准备及原交易由官方钱包持久保存，重开同一助记词和存储后能够恢复；钱包存储丢失时，仅恢复助记词不能宣称恢复所有历史。旧自建测试钱包进程及记录保留只读迁移用途，新钱包使用独立端口和数据库。

业务侧 WalletProvider、OwnWord DTO 与 HTTP 契约保持不变。替换钱包只改变适配器与注册入口；钱包私钥、助记词和测试资金不进入业务模块、页面或 Java。

### 5.3 准备、广播与恢复

适配器内部可以使用 CWI noSend、createAction/signAction 两阶段及 opaque reference，但必须实证准备步骤未广播交易。Mock 广播限定在 broadcastTransaction 的钱包广播服务边界，不能伪造 rawTx、TxID、签名、后端响应或投影。真实 Yours 扩展能力尚未验证时不得标记通过或暗中使用会广播的准备路径。

准备过程恢复是钱包内部事务管理，封装于 recoverPreparation；不得提供按 BAP ID 查询资料或已广播业务历史的接口。业务数据查询均走真实后端。本地日志只用于保存草稿、冻结输出、签名交易及广播/同步恢复，不作为已完成资料的展示来源。

### 5.4 验收

用同一组公共接口检查本地官方核心及 Yours 扩展适配器的账户归属、签名、输出保真、准备不广播、广播原 TxID、拒绝、故障和同交易恢复。增加同助记词重新打开、不同助记词隔离、无效助记词拒绝与钱包持久记录恢复。未安装/实际验证 Chrome 扩展时明确 not-run。检查 app 与身份业务代码不引用 CWI 或具体实现类；钱包模块不引用业务资料、同步 API。广播 Mock 下依然通过真实 Java、MongoDB、文件、解析和验签完成创建、更新、图片及刷新回读。

## 6. 后端存储、解析与索引

1. MongoDB 分开保存 chain_events、identity_projection、已同步 identity_operations、simulated_operations，以及分模式的图片缓存元数据。交易以 network+txid 唯一，操作 UUID 不得绑定另一交易；后端不保存广播前许可。浏览器 IndexedDB 保存未提交/未知流程。模拟记录真实持久化但不进入公开事件和投影。
2. 真实事件唯一键 network+txid+vout，保留原始字节/来源摘要、块位置、签名和观测时间。重复摄入、重启重放及失败重试不重复写资料版本。
3. 每笔交易逐输出识别 BAP 与 AIP。首先验证根 ID 的派生关系和声明，再验证同交易 ALIAS。历史签名按当时有效地址判断，不只查当前 rootAddress。
4. 旧 MongoBapService 的 Optional.get 缺失处理、Identity.name 映射、首次双输出解析需定向修复并有真实输入验证。旧 Planaria JSON 不作为新钱包原始交易的已验证兼容入口。
5. 公共索引路径先核实真实 endpoint、响应与覆盖范围。可复用已验收 JungleBus 客户端接入原始交易，业务仍负责解析、持久化、排序和重建。既有匿名订阅样本不能证明包含本次测试交易；发布测试须确认本次 txid 被实际索引。
6. 资料排序以验证过的链关系与区块位置为依据；无链序证据的冲突返回 unknown，不按客户端 Date.now 选择最新。重组先回滚受影响主链投影，再重放；无法取得必要信息时显示待核实。
7. 不要求启动本期不需要的全部中间件；最小应用需要真实 MongoDB、可重建链上图片缓存、主网查询。需要其它设施时沿用共享 infra。
