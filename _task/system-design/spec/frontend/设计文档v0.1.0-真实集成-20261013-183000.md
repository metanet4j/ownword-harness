## 3. 数据流

### 3.1 连接与读取

1. 连接适配取得实际 walletIdentityPublicKey，检测 network=main。通过真实 computeBapId 取得 BAP ID。
2. 请求身份 HTTP。后端从已验证投影读取；缺失时尝试配置的实际公共 BAP 查询和原始交易核验。不能用空 MongoDB 表直接判定身份未发布。
3. DTO 区分 published、incomplete、not-published、unknown。not-published 同时要求成功公共查询、明确无有效记录及充分覆盖；判断细则见第 4.1 节。索引 404 或覆盖不足返回 unknown，上游不可用返回可重试错误。
4. 钱包 basket 用于签名序列和钱包输出管理，不作为公开发布事实。若 public 已发布但 basket 缺失，先恢复实际记录；恢复不能完成则提示能力缺失，不重复发布 ID。
5. 账户事件和断开递增 epoch，终止未提交 Review，取消本地 fetch 并丢弃迟到结果。

### 3.2 创建、补全与更新

1. 表单和图片只做本地校验、预览。Review 冻结资料、文件字节摘要、BAP ID、钱包公钥、账户代数和流程 UUID；此时不调用业务 POST，不发布图片。
2. 浏览器 IndexedDB 保存流程和每笔交易的操作 UUID、转交标记、冻结内容及回执。原子登记转交后再调用钱包；本地存储失败则阻止调用。GET 身份与交易读取可以在广播前执行，但不以修改 HTTP 方法保留旧后端预检。
3. 无头像的首次资料沿用真实 updateProfile 的 ID+ALIAS 同交易。带头像且钱包尚无身份声明时，先调用真实 publishIdentity 创建 ID，再经后端同步；图片须使用该身份的有效当前密钥签名，不能先发没有身份归属的图片。
4. 头像采用现有 B + MAP(type=post) + AIP 图片协议，复用锁定 SDK 的 B/MAP 模板和 applyBapAip，binary 编码，不创建私有 avatar 协议。钱包取得图片交易回执后才 POST 同步；ALIAS 的 image 写入 b://TxID，页面通过只读解析展示。此路径只提供身份头像，不增加内容管理页面。
5. 使用真实 Actions/CWI 发布 Profile。适配层在最早可能广播的 createAction 前验证实际 BAP/AIP 脚本、冻结资料、签名者、账户和提交选项；返回 signableTransaction 时再次核对业务输出，之后才调用 signAction。校验在客户端完成，不向后端申请许可。校验不通过且明确未广播时 abortAction。
6. 回执按 Transaction.fromAtomicBEEF 解码，计算实际 TxID，与钱包返回值核对，先写入本地日志再 POST 后端同步。backend 请求不携带另一份 name/type/bio/imageUrl；字段只从原交易解析。模拟只写隔离记录，不写公开投影。
7. 同步失败显示“已广播，待同步”，只重放同一 TxID/原始交易。回执丢失时只读原 wallet reference 或操作标签的 listActions，找回原交易再同步；恢复入口不执行 Actions/createAction/signAction。
8. 带头像的首次身份最多包含 ID、图片、ALIAS 三笔交易和多次钱包授权，Review 明确说明。已成功的步骤不重发；中途取消不会撤回已发布图片或 ID。失败后先恢复原交易同步，未执行的下一笔必须由用户明确继续并获得钱包授权。

## 4. HTTP 契约

以下为本次需要新增的接口设计，不声称当前已存在。业务 DTO 与 Java 实体分离；成功为 {data,meta}，失败为 {error,meta}。

成功和错误响应均使用以下 meta；时间为 UTC ISO 8601。

```ts
type ResponseMeta = {
  requestId: string;
  network: 'main';
  respondedAt: string;
  source: 'chain' | 'indexer' | 'storage' | 'validator' | 'wallet-simulation' | null;
  observedAt: string | null;
};
```

respondedAt 必填，表示服务生成本次响应的时间。source 和 observedAt 必填但允许 null：没有取得实际依据时两者均为 null，不用 respondedAt 补齐。缓存返回原事实的来源和观测时间；真实存储读写、验签或钱包模拟分别使用对应来源，不标成主网观测。多个依据各自保留时间，顶层 meta 对应本次返回的主要依据。

错误包含 code、retryable 和可选 field；固定本地文案映射，不向页面输出 Java 堆栈。常用 code：INVALID_IDENTIFIER、UPSTREAM_UNAVAILABLE、SIGNATURE_INVALID、IDENTITY_MISMATCH、PROFILE_CHANGED、OPERATION_CONFLICT、ASSET_INVALID、STORAGE_UNAVAILABLE。

### 4.1 Identity

GET /api/v1/identities/{bapId}

```ts
type IdentityResolution = {
  kind: 'published' | 'incomplete' | 'not-published' | 'unknown';
  bapId: string;
  profile: {name: string | null; type: 'Person' | 'Organization' | null;
    bio: string; imageUrl: string | null} | null;
  idTxid: string | null;
  profileTxid: string | null;
  missingFields: Array<'name' | 'type'>;
  signatureStatus: 'valid' | 'invalid' | 'unverified';
  simulationPreview: IdentityOperation | null;
  indexCoverage: {
    status: 'sufficient' | 'unknown';
    provider: string | null;
    checkpoint: {height: number; blockHash: string} | null;
    historyComplete: boolean;
    recentWindowComplete: boolean;
    observedAt: string | null;
    lastResponse: {status: number; observedAt: string} | null;
  };
};
```

200 可表示实际查询后的明确分流；未知来源不返回 not-published。400 标识非法；502 上游失败；503 存储/索引不可用。客户端必须检查 bapId 与请求一致，不能默默采用不同身份。profile 字段映射 name/@type/description/image；alternateName 仅作为明确的旧格式回退，不能掩盖没有资料。

仅 simulated 服务从隔离集合读取最近一次完成的真实模拟操作，放入 simulationPreview；live 始终为 null。该预览不改变 kind、profile、签名及公共覆盖结论。进行中的更新、取消和失败不能覆盖上一版预览；刷新后仍从服务回读。当前操作与上一版资料分别维护，结果未知只允许核实原操作，明确取消或未提交才开放重新 Review。

交易同步只接受第 4.2 节回执字段，资料、验证结果和网络状态不能由请求注入。已保存的原交易不会被本地迟到取消降级。

否定结果只有在成功读取且没有有效 ID，同时覆盖证据充分时才返回 not-published。充分覆盖要求：实际数据源覆盖该 BAP ID 的历史 ID/ALIAS 及签名历史；主链 checkpoint 已核实、回填和订阅没有缺口；近期未确认与新增交易窗口已同步到本次观测时点。服务依据数据源契约和真实同步状态计算 status，不接收客户端覆盖声明，不用配置中的 true 代替证据。

参考公共 BAP 接口从自身索引存储返回 404，未提供上述覆盖证据；本期默认将这种结果归为 unknown。空数据库、分页列表无结果、单笔交易暂不可见及过期 checkpoint 均不开放新建。找到可验证 ID 时可以确认已发布；最新 Profile 顺序尚不充分则保持待核实，不将旧缓存当作当前资料。A00 必须核实所选真实数据源的 endpoint、否定语义和 checkpoint，证据未满足时不关闭未发布分流验收。

lastResponse 仅记录实际公共 HTTP 状态与取得响应的时间，不能替代 observedAt、checkpoint 或充分覆盖。权限拒绝与无覆盖证明保持 unknown；超时、连接错误和 5xx 返回可重试 502。原始交易已取得但缺少对应身份签名历史时，签名归属为 unverified，不能仅凭缺少历史记为 invalid。

### 4.2 原交易同步与操作

POST /api/v1/transactions/sync：只同步钱包已返回的同一笔交易；后端不调用钱包、不代为广播。

```ts
type TransactionSync = {
  operationId: string; // 本地为本笔交易生成的 UUID
  bapId: string;       // 待核对归属，不能当作已验证证明
  txid: string;
  rawTx: string;      // 原始交易 hex，不是整个 BEEF
};
```

Idempotency-Key 必须等于 txid。后端计算实际 TxID，检查 BAP 标识、逐输出协议和 AIP，再从交易解析 ID、ALIAS 或 B 图片。资料摘要为 SHA-256(UTF-8(JSON.stringify([name,type,bio,imageUrl])))；名称/简介继续使用字素簇计数，解析不改变原始字符串。拒绝额外的 Profile、状态、网络接受或验证字段，不能让客户端覆盖链上字段。

首次同步返回 201；相同 TxID 和相同原交易幂等返回 200，不增加事件、资料版本或图片副本。operationId 不能绑定另一 TxID，同 TxID 不能替换原始字节。记录保留 network+txid+vout、bapId、原始字节、协议类型、签名证据及来源时间。后端同步响应丢失后可以安全重放原请求。

live 从实际主网读取相同 rawTx 并按有效 BAP 密钥历史验证，核实后才能写 chain_events/公开投影；网络未观测、签名历史缺失或链序不明返回 202/pending，不产生假公开资料。业务接受不等于已经挖矿；confirmations 单独显示。simulated 仅真实验签并写隔离交易/图片记录，networkAccepted=null，不能修改 live 投影。broadcastMode 由部署决定，普通请求不能升格。

响应沿用 data/meta，返回 operationId、txid、bapId、kind（identity-init/create/profile-update/avatar）、由交易取得的 profile 或 asset、原始交易/验证证据、broadcastMode、identitySignature、networkAccepted 和状态。仅 ID 声明没有 Profile，返回 profile=null；图片返回 asset，不能伪造用户资料。资料交易返回确切 Profile，客户端与冻结值比较。

400：格式或额外字段；409：同操作或 TxID 绑定冲突；422：交易、签名、身份或图片无效；503：实际存储不可用。交易可能已经广播，422/503 均不授权再次广播。

GET /api/v1/identity-operations/{operationId}：查询已同步交易；保留旧记录的只读兼容。新流程无 TxID 的草稿及未知操作只在浏览器日志中，404 不表示钱包未提交。

GET /api/v1/transactions/{txid}：真实网络读取、TxID、rawTx、观测状态、网络接受、确认和逐输出验签；模拟回执不混入主网查询。

旧 POST identity-operations、preflight、submission-attempts、wallet-results 和 avatar-uploads 退出写入路径，返回 410/WRITE_REQUIRES_TRANSACTION。取消/明确未提交不写后端假交易，记录在本地；有回执的重试全部走 transactions/sync。

### 4.3 头像链上发布与读取

图片 B 输出使用真实原字节、实际 MIME 和 binary 编码，附 MAP(type=post,app=ownword) 及当前 BAP 密钥的 AIP。应用允许 PNG/JPEG/WebP，最大 5 MiB；本地校验图片尺寸，后端从交易再次解码检查单边 8192px、总像素 1600 万及字节/MIME 一致性。WebP 沿用 TwelveMonkeys ImageIO SPI，不增加另一套服务。

POST transactions/sync 接收图片交易回执，返回 assetId=txid、vout、uri=b://txid、contentType、byteLength 和内容 SHA-256。本期每笔图片交易只有一个 B 图片输出且固定为输出 0；客户端核对输出，后端拒绝歧义与无关协议。先发布 ID 再发布头像的依赖见第 3.2 节，取消 Profile 不删除图片交易。

GET /api/v1/assets/{txid}：按交易定位并返回已验证图片的真实字节、Content-Type、ETag、immutable 缓存和 nosniff。后端文件是链上图片缓存，元数据保留原交易与输出位置；丢缓存后按原交易重建，不能接受任意文件路径/URL。模拟缓存与主网数据隔离。

Profile.image 保存 b://TxID；前端 Portrait 通过同源只读接口显示。既有 HTTPS 图片引用只读兼容，新发布头像统一引用链上图片。链上图片不可撤回，Review 必须说明公开、付费和取消后的保留行为。发布费用与实际钱包限制由钱包报告，不能承诺 5 MiB 在任何钱包均可广播。

原交易 hex 会扩大图片请求体，Next 同源代理与后端共同限制同步请求为 12 MiB，图片原字节仍限 5 MiB。限制 Origin、并发与磁盘缓存配额，缓存始终按图片响应，不执行脚本。

### 4.4 运行入口

GET /health：只有真实 MongoDB 和必需配置就绪才 ready；链查询依赖不可用单独列出，不假装 healthy。Next 同源 /api 仅转发明确 allowlist 到配置的 OWNWORD_API_URL，不接受任意代理目的地。缺配置返回可恢复错误，不返回样例成功。

## 5. 钱包完整 API 与模拟边界

生产接入从 CWI 或锁定的 connectWallet/createWalletSession 建立真实会话。测试方案使用独立的钱包测试服务持有测试钥匙；浏览器 CWI 调用完整映射到它。真实 Actions 与页面不认识模拟场景。

完整方法表以 reference/1sat-sdk/packages/wallet/src/cwi/factory.ts 为准，覆盖 28 个方法：

| 类别 | 方法 | 实现与验证要求 |
| --- | --- | --- |
| 输出 | listOutputs、relinquishOutput | 按账户/basket/tags 隔离，真实类型与分页；测试钱包状态可控 |
| 交易 | createAction、signAction、abortAction、listActions、internalizeAction | 支持 signableTransaction/reference、取消与幂等；模拟广播只返回有来源的回执，不宣称主网接受 |
| 公钥 | getPublicKey、revealCounterpartyKeyLinkage、revealSpecificKeyLinkage | v0.1 的公钥派生真实；非本期权限能力可明确 unsupported，不能伪造证明 |
| 密码学 | encrypt、decrypt、createHmac、verifyHmac、createSignature、verifySignature | 优先委托真实 SDK 钱包实现；需要调用的路径必须实际验签，不返回固定 true |
| 证书 | acquireCertificate、listCertificates、proveCertificate、relinquishCertificate、discoverByIdentityKey、discoverByAttributes | 全部存在、类型正确；未实施能力统一明确 unsupported，不将其计为证书功能完成 |
| 状态 | isAuthenticated、waitForAuthentication、getHeight、getHeaderForHeight、getNetwork、getVersion | 授权可批准/拒绝/取消，网络固定 main；高度和区块头如提供必须真实读取 |

### 5.1 钱包先行适配与恢复

WalletProvider 仅在钱包边界完成本地持久化、实际输出/AIP 检查、账户核对及原始回执保存，其他方法委托 CWI。真实 updateProfile/publishIdentity 和头像 B/MAP/AIP 模板使用该边界；广播前不调用任何业务 POST。

signAndProcess=false、noSend 或 SDK 函数名不能单独证明不广播；请求校验必须先于 createAction。返回可签交易后核对相同业务输出和账户，再进入 signAction。钱包不能保证输出与账户时阻塞 live，不宣称广播后的拒绝能撤回交易。

恢复以 IndexedDB 日志、钱包操作标签和 reference 找回同一交易，真实 listActions 分页；多候选、空记录或网络 404 保持未知。取得回执后才同步后端。账户变化使未转交操作失效，已转交结果继续归原 BAP ID，旧结果不能进入新账户 UI。

测试钱包只模拟授权、资金和广播；BAP/AIP、图片字节、后端 HTTP、存储和主网只读真实。初始身份未知时保留明确的模拟准备入口，模拟资料及图片不进入公开事实。钥匙、私有配置和令牌不进入页面或 Java。

## 6. 后端存储、解析与索引

1. MongoDB 分开保存 chain_events、identity_projection、已同步 identity_operations、simulated_operations，以及分模式的图片缓存元数据。交易以 network+txid 唯一，操作 UUID 不得绑定另一交易；后端不保存广播前许可。浏览器 IndexedDB 保存未提交/未知流程。模拟记录真实持久化但不进入公开事件和投影。
2. 真实事件唯一键 network+txid+vout，保留原始字节/来源摘要、块位置、签名和观测时间。重复摄入、重启重放及失败重试不重复写资料版本。
3. 每笔交易逐输出识别 BAP 与 AIP。首先验证根 ID 的派生关系和声明，再验证同交易 ALIAS。历史签名按当时有效地址判断，不只查当前 rootAddress。
4. 旧 MongoBapService 的 Optional.get 缺失处理、Identity.name 映射、首次双输出解析需定向修复并有真实输入验证。旧 Planaria JSON 不作为新钱包原始交易的已验证兼容入口。
5. 公共索引路径先核实真实 endpoint、响应与覆盖范围。可复用已验收 JungleBus 客户端接入原始交易，业务仍负责解析、持久化、排序和重建。既有匿名订阅样本不能证明包含本次测试交易；发布测试须确认本次 txid 被实际索引。
6. 资料排序以验证过的链关系与区块位置为依据；无链序证据的冲突返回 unknown，不按客户端 Date.now 选择最新。重组先回滚受影响主链投影，再重放；无法取得必要信息时显示待核实。
7. 不要求启动本期不需要的全部中间件；最小应用需要真实 MongoDB、可重建链上图片缓存、主网查询。需要其它设施时沿用共享 infra。
