## 1. 页面方案与原型对应

### 1.1 页面与路由

沿用 v0.1 Next App Router，给内容提供可刷新路径；hash 只是原型导航手段。公开路径固定 TxID，草稿路径固定本地 UUID。具体路由如下，身份页维持已有路径。

| 页面 | 原型入口 | 拟实现路由 | 主要对象、操作与状态 |
| --- | --- | --- | --- |
| 我的内容 | `#/content` | `/content` | 当前作者摘要，草稿/已发布 Tabs，新建与整行打开；空、加载、失败、只读占用 |
| 编辑 | `#/write/:id` | `/content/drafts/:draftId` | 保存提示与工具栏在前，正文居主位，Review 为主操作；未保存、超限、恢复和修订基线提示 |
| 发布确认 | `#/review/:id` | `/content/drafts/:draftId/review` | 作者及完整 BAP ID → 正文 → 公开影响 → 返回/签名并发布；无有效内存快照则重建 Review |
| 发布进度/结果 | `#/publish/:id` | `/content/operations/:operationId` | 授权、签名、发布和同步分阶段；取消、明确失败、未知、已接收及读取入口 |
| 固定版本阅读 | `#/read/:id` | `/read/:txid` | 作者、版本提示、正文、目录及折叠 Proof；访客只读，链接不跳到新版本 |
| 版本历史 | `#/history/:id` | `/read/:txid/history` | 固定版本及可验证历史；提供最新已知版本、缺失或分支说明 |

未知路由、非法 UUID/TxID 有明确错误；服务故障显示重试。登录前只保留待进入的本地路径，连接同一身份并读库后再解析草稿，不能通过路径猜测展示其他身份标题。刷新结果页只恢复记录，不自动弹钱包授权。公开页在新浏览器直接读取后端。

最新原型公开阅读含作者按钮和目录；保留正文布局、目录与作者信息。作者按钮只承接 v0.1 已有身份查看能力，不把 v0.4 公开主页、Find、关系和媒体功能纳入本次。未知作者使用完整 BAP 标识及未核实提示，不用示例头像或 Maya Chen 填充真实数据。

使用 baoyu-design 的任务、层级、关系和操作顺序方法。方向由指定原型固定，不另做品牌探索。页面主标题与说明沿原型左对齐；工作台宽度、编辑器比例、阅读中轴、侧目录、首屏密度、字体和间距按源 CSS 与截图逐项迁移。阅读正文最大约 72ch；工具栏在 960px 以下取消双栏，320px 收起次级格式工具。真实错误和来源提示复用原型状态区，不能挤掉主操作。

四项自评：秩序由工作台横向对齐与阅读中轴表达；关系由作者与版本成组、正文与 Proof 分级表达；密度按写作/阅读任务调整；表达准确通过真实状态与可复制标识保证。品牌装饰仅保留现有壳层，动效服从 reduced-motion。原型参考截图已人工查看：工作台、编辑、Review、桌面阅读及 320px 阅读；320px 当前阅读页 `scrollWidth=320`。这些截图只证明取证对象，不是生产 UI 验收结果。

## 3. 草稿、编辑与浏览器恢复

### 3.1 草稿存储

新增 IndexedDB `ownword-content-drafts` v1，drafts 主键为 UUID；存储本期认知 E01 字段，并建立 authorBapId、[authorBapId, updatedAt, id] 索引。普通草稿不设置 revisionKey；修订草稿设置 `authorBapId:baseTxid` 唯一稀疏索引，保证单 origin 内复用。初始化绝不塞入原型示例草稿。

保存使用同一事务读取 savedRevision、比较后写入；完成事件后才更新“已保存”。停止输入 800ms 保存，编辑中新增变化不能被前一批成功回执覆盖。内存的当前正文、持久化基线、正在写入的快照分别维护。读取失败不返回空库；保留内存各身份副本，重试成功后对不同内容分配新恢复草稿 ID，磁盘原稿保留；恢复副本真正写入前一直 dirty。

仅当前已连接且身份合格的 BAP 可进入对应草稿集合；数据按身份隔离，不承诺抵御拥有同一浏览器配置文件/开发者工具的人。本期无云草稿、分享草稿或服务端草稿鉴权接口。

### 3.2 页面互斥与离开保护

使用 Web Locks 的 origin 级 `ownword-content-writer` 长持有锁。其他标签只读，提供关闭占用页后重试；获得锁后先重载草稿和未终结发布日志。无 secure context 或无 Web Locks 时保持只读，不使用 localStorage 心跳冒充原子锁。

身份、头像和内容发布还受共用操作日志的账户互斥约束；WriterLease 不能替代该互斥。草稿编辑可以继续，发布按钮必须提示待处理操作的恢复入口。

内部链接、返回、账户切换和导入替换经过同一个离开守卫：继续编辑/保存并离开/明确放弃。保存失败停留原页；硬刷新与关闭使用 beforeunload。浏览器后退需沿用并扩展 v0.1 已修复的 Navigation API 路径；不支持该 API 的浏览器采用经过真实测试的 history 守卫。若该回退实现尚未验证，兼容性验收保持开放，不能把 Chromium 结果扩写为全浏览器通过。

外部账户变化立即取消旧会话未提交授权，保留原身份未保存内存，当前 UI 不展示旧正文；原身份重新连接可恢复。持久化升级被旧标签阻塞时提示关闭旧页，原数据保持，禁止删库重建。

### 3.3 编辑与 Markdown

原文是单一状态。仅打开或切换 Milkdown 不写回序列化结果；明确编辑事件才更新正文。源码用 CodeMirror transaction 更新，同一操作进入撤销栈。模式切换保存各自 selection 和 scroll；组合输入期间不触发格式快捷键或破坏 composition。桌面分栏按段落映射同步，用户主动滚预览时不抢位置。

渲染顺序为 parse → GFM → 不支持节点转原始文本 → remark-rehype → sanitize → HTML。编辑预览、Review 和公开阅读使用同一入口；预览约 500ms 更新，Review 直接读取最新原文。脚注、媒体、原始 HTML、公式/图表保留原文并说明转源码编辑；任务框在阅读中只读。HTTP/HTTPS/mailto 白名单链接新标签打开并带 noopener/noreferrer；javascript/data 等不可激活；粘贴只接收文字。

导入先检查 `.md` 与文件字节数，再以 fatal UTF-8 解码，移除单个开头 BOM，保留 CRLF。当前非空或 dirty 时经过替换确认和离开守卫；失败不触碰现稿。发布上限 102400 UTF-8 字节；手动超限仍保存/导出，不能 Review。导出使用原文 UTF-8，不使用 HTML 或编辑器二次序列化。标题和摘要由首个 H1 与正文派生，缺 H1 不阻止非空内容发布。

## 4. 首次 Post 的协议与发布

### 4.1 原交易契约

本期首版采用已存在的 BitcoinSchema Post：

```text
OP_FALSE OP_RETURN
B <原文UTF-8字节> text/markdown utf-8
| MAP SET app ownword type post
| AIP BITCOIN_ECDSA <签名地址> <签名>
```

此处 B/MAP/AIP 表示官方协议前缀，线上值由绑定基础模板产生；管道表示 BitCom 分隔。AIP 的消息编码、分隔和哈希严格按现有实现及官方测试向量，不自行拼出另一种签名算法。一个内容数据输出为 0 satoshi，钱包的支付/找零输出按既有安全规则校验。BAP ID 不由任意 MAP 字段自报，而由签名地址在相应历史时点的 BAP 归属解析。

最小实验已确认 templates 0.0.37 的 `BSocial.createPost({app:'ownword',mediaType:'text/markdown',...})` 输出实际包含 `app=bsocial` 和 `text/plain`。采用官方 B.lock、MAP、AIP 基础能力组合标准载荷，输出后再解码比较媒体类型、编码、应用、正文摘要和完整 AIP 覆盖；不修改 node_modules、不直接升级依赖规避取证。AIP 尾部追加前后的实际输出须由独立后端验证。

不能直接从页面调用 `createSocialPost.execute`：当前 Action 最终调用 `executeTrackedAction` 并设置 `acceptDelayedBroadcast:false`，无法满足本项目的广播前原交易持久化与校验顺序。复用协议能力，通过现有 WalletProvider 执行准备和广播。

### 4.2 授权、广播与同步顺序

1. 核对当前会话、网络、BAP 公开状态与签名者、写锁、共用日志和正文。修订另核对第 5 节基线。生成 ReviewSnapshot；公开影响说明与原型一致，费用只展示钱包实际给出的信息。
2. 共用日志原子登记 `reviewed` 操作及冻结快照，失败即停止授权。签名时再次比对 sessionEpoch、作者、原文及修订引用；钱包签名后做本地 AIP 验证。
3. `prepareTransaction` 返回仅准备未广播的 rawTx；及时保存 preparationId。核对实际输出、金额、签名覆盖、TxID 与原文，再将完整原交易写入日志。钱包不具备 prepareWithoutBroadcast 时提示不支持，不能退回自动广播 Action。
4. 广播前记录 submissionAttempt，随后 `broadcastTransaction`。超时或断线进入结果未知；取消、准备失败与网络拒绝分开。准备引用不明先 recoverPreparation，同一原交易不得重新签名替代。
5. 钱包 accepted 回执先持久化，再同步原交易；后端独立查询及验证网络结果。同步失败显示已接收/待同步的实际来源，保留草稿；不能假装交易已撤销。
6. 后端内容回读的 TxID、作者与正文摘要一致后，先把日志标为同步完成，再删除对应 draftId 的**同一冻结版本**。若草稿已被继续编辑，保留新正文；跨库清理可重试且幂等，不依赖跨库事务。

模拟模式使用真实密钥派生、签名、原交易、解析、数据库及 HTTP，仅钱包交互/隔离资金/广播回执按已授权边界模拟。结果为“模拟完成，未广播主网”，读取隔离投影，确认数为空。

### 4.3 日志兼容与恢复

沿用 `ownword-wallet-receipts` 的 operations/accounts；给新记录增加 schemaVersion 和 kind 为 content-post/content-revision 的判别载荷。已有身份/头像记录按 v1 读取，不能因缺少内容字段被丢弃。若无需新 objectStore/index，保持数据库版本 1；需要升级时采用保留原记录的显式迁移并验证中断场景。共用 pending 判定必须识别新旧所有非终态。

每次恢复核对日志 broadcastMode、网络与当前配置；来源不一致时保留原记录并要求回到对应环境处理，不能把模拟原交易直接同步为生产成功。开发验收继续使用隔离浏览器配置/端口，不能用切换环境清空未处理日志来绕过互斥。

| 恢复时证据 | 恢复动作 | 禁止动作 |
| --- | --- | --- |
| 仅 Review/待授权，无钱包准备或提交证据 | 原作者重新连接后回草稿并重新 Review | 自动恢复用户授权 |
| prepare 已发起、引用或响应不明 | 恢复同一准备；明确中止才释放账户互斥 | 清日志后新建交易 |
| rawTx 已保存、尚未广播 | 查明准备仍有效，重新核对会话和基线后由用户继续或中止 | 无动作自动广播 |
| submissionAttempt 已登记，无明确结果 | 以同一 TxID 查询网络/后端与钱包恢复记录 | 因 404、超时或等待时长直接另发交易 |
| 已接收但同步失败 | 重试同步同一 rawTx；回读成功后幂等清理 | 再签一笔相同正文 |
| 明确未提交且已中止，或有依据的明确拒绝 | 保留草稿，允许重新 Review 及新操作 | 把旧授权移交新账户 |

普通索引 404 不能证明未接受。钱包或服务无法给出足够结论时保持未知并给出导出/查询入口。重发同一原交易是否安全也须核实钱包能力；本版不对未知结果做自动广播重试。

## 5. R01：已批准的修订链上关系

### 5.1 问题与证据

总认知 §7.5 要求根版本、前版、序号和新交易，§10.3 禁止 Custom Post。原型的 rootContentId/previousContentId/revisionNo 来自 `content-model.js` 的本地记录；已查 BitcoinSchema 内容规范、MAP 规范、Actions 和模板源码，未发现能直接实现这组 Revision 语义的绑定契约。此结论限于已核对来源，不宣称所有生态均无相关标准。

`context tx tx <txid>` 已用于 Reply。用它冒充 Revision 会改变标准语义；仅在 Mongo 保存链接又不能由链上重建。两种做法都不作为可接受实现。

### 5.2 已批准方案 B

保持标准 Post 主类型、B 载荷和 AIP，通过 OwnWord 命名空间的签名 MAP 元数据关联根/前版。用户在了解此方案用途及限定例外后回复“可以”，总认知第 7.5、10.3 节已更新。本方案属于 OwnWord 应用扩展；其他客户端可读取普通 Post，但未必识别修订关系，不宣称为已有通用 Revision 标准。

### 5.3 修订编码契约

首版使用第 4.1 节标准 Post，不包含修订字段；根引用在读取时取首版自身 TxID，避免交易自引用。修订仍是完整新正文的 Post，MAP 依次追加：

```text
ownword.revision 1
ownword.rootTxid <首版TxID>
ownword.previousTxid <直接前版TxID>
```

`1` 为扩展契约版本，不是内容版本号；三个键须同时出现且唯一，TxID 为 64 位小写十六进制。AIP 覆盖 B 与全部 MAP 字段。revisionNo 由已验证路径深度派生，不在链上相信客户端自报数值。本契约不使用 context=tx，不新增 type=revision。

服务验证前版和根均为可验证 Post、作者为同一 BAP、根一致、前版不是本交易、路径无环；同一 BAP 的历史不同密钥可经已验证轮换链归属，不以地址变化否定作者。无效引用不能进入版本历史；缺少前版或归属资料时保留 unverified/incomplete，并补查来源，不编造 revisionNo。

客户端只对当前查询覆盖内唯一叶子开放修订，并在 Review 与准备广播前再次读取基线。链上允许两个设备竞争产生两个后继；后端不对 previousTxid 建唯一索引，不用数据库时间或 TxID 字典序伪造全局最新。检测到分支时状态为 conflict，展示已知分支及固定版本入口，停止继续追加；合并/选支能力留待另行设计。

“最新”必须附带覆盖依据与观测时点。覆盖不足时显示“最新已知版本/历史待补齐”，不声称全链唯一最新；修订发布入口保持不可用。该限制依赖 v0.1 尚未完成的公共历史/checkpoint 能力，属于本期真实修订验收的前置条件。

### 5.4 决策与验证状态

R01 设计决策已关闭，用户批准证据记录于统一任务清单。协议实现仍须验证根/前版字段、签名覆盖、同作者归属、缺失与分支处理；实现检查通过前 C09 不得标记完成。

## 6. 后端与 HTTP 契约

以下为拟新增/扩展契约，并非现有 API 已具备能力。JSON 继续使用现有 `{data, meta}` 或结构化错误形式；scope 来自部署配置，普通请求无权选择生产或模拟来源。

### 6.1 交易同步与协议分派

`POST /api/v1/transactions/sync` 保持四字段请求和 `Idempotency-Key: <txid>`：

```json
{
  "operationId": "UUID",
  "bapId": "当前操作的完整BAP标识",
  "txid": "64位小写十六进制",
  "rawTx": "完整原交易hex"
}
```

请求 BAP 仅用于核对，不作为作者证据。拒绝额外正文、作者 Profile、签名成功布尔值、根版本或来源模式字段。解析完整脚本后分派身份、头像和内容：本期 content 必须是 B Markdown + MAP type=post + AIP；头像按原有完整契约识别。匹配一个分支后验证失败直接失败，禁止依次捕获错误并降级解释成其他协议。

处理顺序：请求形状/长度 → 交易解析和 TxID → 幂等冲突 → 协议/输出数量及金额 → AIP 完整载荷 → BAP 历史归属 → 网络原交易比对 → 修订关系 → 保存同步记录及可重建投影。身份/头像已有路径和 refreshObservation 重放路径均需覆盖新分派，避免首次成功、恢复时走错解析器。

同 operationId 换 TxID，或同 TxID 提交不同 rawTx/BAP，返回 409。相同原交易重试返回原结果并重新尝试待完成的观测/投影。返回 201 表示新同步记录，200 表示幂等已有记录，202 表示网络或身份/关系核验仍待完成；HTTP 状态本身不等同于发布或确认。错误 400 为输入，422 为交易/签名/协议不符，503 为依赖不可用。同步记录已落盘但投影未生成时返回 pending，重试可以补建；不依赖进程内成功标记。

### 6.2 只读 API

| 接口 | 参数与返回 | 空、缺失与失败 |
| --- | --- | --- |
| `GET /api/v1/contents?authorBapId=&cursor=&limit=` | 指定作者；limit 默认 20、1–50；返回版本摘要列表、nextCursor、coverage | 查询成功可为空；服务失败 503；覆盖不足保留 known-results/incomplete 语义 |
| `GET /api/v1/contents/{txid}` | 固定版本的原文、摘要、作者归属、版本关系、Proof；无需钱包 | 非法 ID 400；确实无当前可用记录 404 并附覆盖信息；待核验 202；验证失败 422；依赖不可用 503 |
| `GET /api/v1/contents/{txid}/versions?cursor=&limit=` | 从给定版本解析根，返回已验证版本/分支及 coverage；不接受草稿 UUID | 缺前版可返回已知数据和 incomplete；不能以空列表冒充首版 |
| `GET /api/v1/operations/{operationId}` | 新通用只读别名，复用现有同步记录；返回 kind、txid、阶段、来源及公开证据 | 404 只表示本服务无此记录，不能据此重新广播 |
| `GET /api/v1/transactions/{txid}` | 复用原有网络/原交易观测接口 | 保留现有来源与错误语义，不由客户端填写确认数 |

现有 `/api/v1/identity-operations/{id}` 保留兼容；通用操作响应仅包含已交给后端的公开交易结果，不返回本地草稿、钱包恢复引用、助记词或未签名 Review。公共 GET 无钱包认证要求；它不能成为后端接受私有写入的理由。

内容成功 DTO 的核心结构如下；值为类型示意，具体约束引用本期认知第 6 节：

```text
data: {
  txid, authorBapId, markdown, contentDigest, mediaType, encoding,
  title, summary,
  authorDisplay: {profile, source, observedAt},
  firstObservedAt,
  revision: {rootTxid, previousTxid, revisionNo, status, latestKnownTxid, branches},
  proof: {signatureStatus, signer, networkAccepted, confirmations, blockTime, observation}
}
meta: {scope, source, observedAt, coverage}
```

authorDisplay 是当前查询的 Profile，不宣称被正文交易签名；内容作者归属始终为 BAP ID。展示优先使用已核实区块时间并标注含义，未确认时使用实际首次观测时间及对应标签；无依据则显示时间未知。模拟结果使用模拟来源标签，无真实浏览器假链接。

签名失败不生成已验证作者的内容列表项。固定 TxID 查询若有公共原交易但验签失败，422 错误附最小公开 Proof 状态及原因，页面显示“验证失败”，保留 TxID 和查询入口；不展示有效徽标。归属未核实时 202 显示“未验证”，可呈现安全解码的公开正文，但 authorBapId 不填成已验证值。不支持的 MIME 有明确 unsupported 状态，本期不借此加载媒体。

列表按服务首次观测时间与 TxID 组成稳定游标，游标绑定作者及来源范围；此顺序仅为列表排序，不作为修订顺序。版本路径按已验证引用展示，确认信息独立更新，不能让确认数变化导致漏页。游标无效返回 400；所有读结果提供实际来源时点。

### 6.3 持久化、索引与公共回读

在现有来源隔离机制下增加内容集合、版本关系集合；用 `network+scope+txid` 唯一定位，每个本期内容记录保存 vout、原文字节摘要、解析器版本及验证依据。索引覆盖 authorBapId+firstObservedAt+txid、rootTxid、previousTxid；不对前版或 revisionNo 建全局唯一约束。

同步记录是可重放入口：先保存 rawTx，再以幂等 upsert 生成投影。任何中断均可重跑；重新验签不能只看旧数据库 valid 标记。清空可重建投影后，通过保留原交易或公共交易来源重建，并比较作者、正文摘要和关系。

固定 TxID 查询在本地未命中时可调用既有受控主网原交易来源解析；作者列表及“最新”需要索引覆盖，不能通过枚举钱包历史代替。外部来源限流/超时按真实错误返回，不能加载 seed fixtures 补位。请求大小限制沿用现有网关和 rawTx 边界；100 KiB 正文加交易开销需实测钱包/服务能接受，费用只以真实钱包结果为准。
