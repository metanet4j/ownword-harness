# Ownword 产品设计 v0.3.0

> Identity Artifact / Inscription Number / Identity Signature / Binding

## 0. 文档定位

本文定义 v0.3.0 Identity Artifact 高保真原型的功能范围、页面、交互、状态、BDD 验收和制作映射。本次先交付设计文档；页面制作、真实钱包接入和 metanet4j API 实现分别进入后续任务。

[核心认知](../../核心认知.md)是术语、实体、关系和链上规则的唯一事实来源。本文引用这些规则并规定界面如何表达，不另建协议、数据库或生产 API 契约。任务状态见[功能清单](../../../feature_list.json)。

本版延续既有身份与内容体验，使用 React Spectrum S2 和“穹顶与地平线”视觉。钱包授权、身份签名、交易、编号、所有权与 Binding 均用可控样例；选取图片、预览、表单、导航和复制实际可操作。模拟结果不作为真实上链或密码学验证证据。

## 1. 版本目标

用户能够创建或选择自己持有的 Artifact，以 Inscription Number 作为可记忆数字 ID，让他人找到当前关联的 BAP Identity。用户能判断数字 ID 是否已分配、是否稳定、当前关联谁、是否仍可使用，并在转移或关联失效后恢复可用状态。

体验以数字 ID 为主，视觉资产作为承载。成功创建、编号分配、编号稳定、设为 Current 是不同结果，各自给出反馈，不用一张成功页代替整个过程。没有 Artifact 时，身份查找和内容发布仍可使用。

## 4. 页面与交互

### 4.1 信息架构与进入条件

| 页面或视图 | 入口和首要信息 | 操作与返回 |
| --- | --- | --- |
| 我的身份 | 当前 Artifact 摘要、数字 ID、编号状态；保留醒目的 BAP ID | 查看 Artifact、管理 Artifact；无资产时创建或跳过 |
| 我的 Artifact | 当前身份、Current 摘要、资产列表；全部／可用／历史或不可用筛选 | 创建、选择钱包资产、打开详情；返回我的身份 |
| 创建 Artifact | 内容选择、名称、完整预览和当前身份 | 检查创建、保存草稿、返回工作台 |
| 操作确认与结果 | 操作身份、对象、影响、授权与处理阶段 | 返回修改、签名并执行；根据结果查询、重试或看详情 |
| Artifact 详情 | 数字 ID、稳定性、Associated Identity、视觉内容 | 复制、查看身份、展开 Proof；本人按资格设置 Current 或转移 |
| 选择 Artifact | 钱包持有列表、编号、可用性及禁用原因 | 选择并检查关联；取消回到入口 |
| 转移 Artifact | 当前资产、接收地址、关联影响 | 检查转移；返回详情 |
| 查找结果 | 输入数字 ID、匹配 Artifact、当前关联 BAP ID | 打开 Artifact 或公开身份，修改查询 |

公开详情和查找不要求连接钱包。创建与关联要求连接钱包、已发布且已完成设置的当前 Identity；未满足时复用现有连接和设置流程。转移还要求钱包控制当前输出。路由参数不能授予编辑权限或替换操作身份。

Artifact 详情使用 `#/artifact/<inscriptionId>` 作为原型固定入口，数字 ID 查询使用独立查找入口。分享详情不以可能变化的编号作为唯一定位键。刷新、后退、返回工作台保留合理的筛选与位置；未知链接显示未找到，不展示另一项资产。

### 4.2 视觉与组件

沿用既有 S2 绑定、品牌图案和身份卡。Artifact 页采用“资产预览＋数字 ID 与关联信息”布局；数字 ID 为主要记忆点，BAP ID 可读且可复制。资产列表不加入价格、购物车或营销等级，不呈现为 NFT 市场。

桌面详情和 Review 使用两栏，图片与信息各占一个主区域；窄屏按数字 ID、关联身份、图片、操作、Details 顺序排列。图片按原比例完整展示，列表可用固定预览框；Review 不裁掉会影响确认的内容。长 BAP ID、TxID、Origin 可换行或缩略，复制始终取原值。

复用 S2 的 Button、ActionButton、ActionMenu、Tabs、Dialog、InlineAlert、StatusLight、Disclosure、TextField、FileTrigger、CardView 与 Skeleton，以及现有标识复制、身份摘要和模拟钱包组件。新增 ArtifactSummary、ArtifactCard、NumberStatus、BindingSummary、ArtifactProof 等领域组合组件；不建立第二套按钮、输入框、颜色或状态体系。

默认展示一套沿用现有风格的设计。状态变化只做简短淡入，数字 ID 不用滚动计数动画；尊重减少动态效果。弹窗提供焦点约束，关闭后回到触发点；查询和状态更新用非打断式提示，不抢焦点。320px 宽度下主要操作可达，页面不横向溢出。

### 4.3 创建内容与草稿

创建页提供“内置图案”和“上传图片”两种内容来源。内置图案沿用 Ownword 品牌；上传接受单张 PNG/JPEG。名称必填，初始建议为当前 Profile 名称加“Artifact”，用户可修改；Review 固定所选图片与名称。

本版表单约束：名称去除首尾空白后为 1–100 个 Unicode 码点；图片上限为 2 MiB（2,097,152 字节），同时检查格式和解码结果。以上是原型体验范围，不代表 1Sat 协议限制。拒绝 SVG、HTML、动画和远程 URL，不压缩或裁剪后悄悄替换用户确认的图片；无效新文件不覆盖先前选择。

图片中不自动写入尚未分配的编号。编号显示在资产之外的界面区域；确认前使用明确待确认文案，不以样例 `#165` 假装将获得该号码。默认关联的目标是当前 BAP ID，不能在输入框中任意填写另一个身份。

草稿、图片和演示操作记录使用浏览器本地持久化，按 BAP ID 隔离；图片可使用 IndexedDB Blob。显示保存成功或失败，未落盘不能声称已保存。取消授权或明确失败后保留原草稿；离开未保存内容时可继续编辑、保存并离开或明确放弃，保存失败留在当前页。刷新恢复最后保存成功的草稿，不恢复钱包授权。

### 4.4 Review、签名、创建与默认关联

Review 显示当前身份及完整可复制 BAP ID、内容预览、名称、编号待确认说明，以及创建后默认尝试设为 Current 的影响。有既有 Current 时，明确指出成功关联后它将成为历史关联。主按钮为“签名并创建 / Sign & Create Artifact”，次按钮为“返回修改”。

Review 固定内容、操作身份和关联目标。用户改动内容或目标后，旧快照与旧授权失效。费用区域仅说明模拟不产生费用，真实费用由后续钱包确认提供，不虚构报价。

| 阶段 | 页面反馈 | 退出或恢复 |
| --- | --- | --- |
| 等待授权 | 模拟钱包显示本次操作和签名身份 | 拒绝或关闭为已取消，回到草稿 |
| 身份签名与校验 | 显示正在签名，继而显示归属校验 | 缺失、无效或身份不匹配时停在失败，不进入广播 |
| 创建处理中 | 显示交易处理；阻止重复操作 | 明确拒绝可重试；结果未知只能先查询 |
| Artifact 已创建 | 显示创建成功，编号状态独立展示 | 进入默认关联步骤或查看资产 |
| 默认关联处理中 | 单独说明正在设为 Current | 如需另一笔交易，再次展示该笔的身份签名与钱包授权 |
| 关联成功 | Current 更新，旧 Current 成为历史关联 | 查看当前身份或详情 |
| 关联取消、失败或待核实 | 明确“Artifact 已创建，尚未设为 Current” | 在该资产上重试关联或查询；不再次创建 |

原型用“创建交易”和“关联交易”两个可控样例表达部分成功及逐笔签名。生产是否合并交易、绑定采用何种链上表达，以后续实现契约为准；不能据原型推定一定两笔，也不能合并页面结果掩盖部分成功。

已提交但响应丢失时保留操作记录和原身份，显示“结果待核实”。查询样例返回已接收、仍未知或明确未接收；只有明确未接收才开放重新执行。刷新后，已提交操作恢复为待核实，未提交的授权失效。事务结果保存失败时保留恢复信息，不显示完成后又允许重复创建。

账户变化后，未提交操作终止，旧账户的数据保留在其作用域；已经提交的交易不能标为撤回。旧操作回调不进入新身份页面，不自动继续默认关联。返回原身份后先查询或重新 Review。

### 4.5 编号与稳定状态

NumberStatus 是工作台、身份摘要、详情和查询结果的唯一编号状态组件；判定遵循核心认知第 9.4 节。详情提供确认数、最近更新时间和“刷新状态”。

| 样例 | 界面表达 |
| --- | --- |
| 未入块、编号为空 | “编号待确认 / Inscription Number pending confirmation”，不展示可复制假编号 |
| 已确认但 Indexer 尚未回填编号 | “编号解析中 / Resolving inscription number”，确认事实与解析进度分别呈现 |
| 编号已分配、5 个确认 | 显示实际 `#165`，标注“尚未稳定 · 5/6 个确认” |
| 达到默认阈值 | 显示实际 `#165` 与“稳定 / Stable”；详情可查看实际确认数 |
| 已稳定后发生重组 | 显示“编号重新核实中”，先前编号仅作历史信息，不继续作为当前可用数字 ID 复制 |
| 重新解析后编号或确认数改变 | 显示最新编号与状态；有变化时说明原编号和新编号，并提示核对 |
| 查询不可用 | 保留带时间的上次结果，显式标注“待核实”；不伪造确认数递增 |

新交易接收成功不自动分配编号，等待计时不自动增加确认数。编号稳定不改变签名和 Binding 的验证结果；反过来，Binding 已生效也不让编号提前稳定。

转移交易使用自己的确认提示；不把其 0 个确认覆盖原铭文的确认数。直接打开 Artifact 固定链接始终核对同一 Inscription ID；重新输入旧数字则执行当前编号映射，不静默跳回过去关联的身份。

### 4.6 详情与 Proof

详情首屏显示数字 ID 与状态、Associated Identity 名称及 BAP ID、Binding 用户状态、资产预览。没有有效关联时显示“当前没有关联身份”，仍允许查看 Artifact；已有历史关联放在展开区域，不冒充当前 Identity。

详情按以下层次展开：

1. **资产内容**：铭文图片、原始内容类型和创建时名称；显示失败可重试，不影响标识读取。
2. **当前信息**：当前 MAP 展示元数据、当前 owner 和当前 Binding 分别显示，各自注明来源或验证状态。MAP 名称变化不修改铭文图片。
3. **Proof**：Inscription ID、Ordinal Number、Origin、Current Outpoint；创建、关联与转移各自的交易记录；操作 BAP ID、签名地址、身份签名验证结果、链上确认及数据来源。

creator、signer、owner、Associated Identity 使用独立标签。只有有对应证据时才显示具体身份，不能根据同一个地址填满所有字段。签名只提供模拟有效、未验证和无效三态，不显示现实身份认证标识。

长标识显示可以缩略；Copy 复制完整原值。数字 ID 的显示前缀 `#` 不进入复制值，复制结果为十进制字符串。复制失败给出重试和可选全文。演示 TxID 不链接真实区块浏览器；复制详情链接可在同一预览地址重开。

### 4.7 多 Artifact 与 Current 切换

选择器区分“钱包持有”与“关联历史”。钱包样例可包含本人创建及他人创建后转入的 Artifact；创建者不同本身不导致禁用。资格由当前 Origin、控制权与 Binding 校验结果决定；无法核实时显示原因和重试，不能归类为不存在。

选择另一项后进入 Review，显示旧 Current、新 Artifact、操作身份与公开结果。默认不按编号是否达到稳定阈值筛除候选：已分配但尚未稳定的编号明确标注；编号尚未分配也可关联，身份页显示待确认。

只有新关联成功后才提交 Current 切换；取消或明确失败保留原来仍有效的 Current。重复选择当前项不触发授权。同一操作期间新发现所有权变化或其他会话已改变关联时，旧 Review 失效，刷新后重新确认，不静默覆盖。历史关联保留，但不作为数字 ID 的当前查找结果。

### 4.8 转移与无效关联恢复

Transfer 只对当前钱包可控制的输出开放。页面输入接收地址，按所选网络进行地址校验；Review 展示完整地址、资产和操作 BAP ID。不能把 BAP ID 或 Inscription Number 直接当成接收地址。原型使用固定收款地址样例和可控错误，不调用真实钱包。

进入 Review 前获取最新输出，签名前再次核查。输出已变化但仍可控制时，提示重新检查；已不受当前钱包控制、Origin 失效或查询失败时停止操作并给出原因。每笔转移也执行身份签名；只有资金输入签名的样例不能进入成功。

结果分别显示交易是否接收、当前 ownership 和 Binding 是否已核实。待核实时禁用再次转移和设置 Current，不能预先宣布接收者已拥有或原关联必定失效。收到新的有效事实后再更新；确认转给他人且不满足原关联条件时，移除当前有效关联，保留历史。

无效关联横幅按实际原因区分“控制权已变化”“Origin 不再有效”“关联不满足唯一性”；临时服务错误使用“暂时无法核实”，不混为永久失效。提供“选择其他 Artifact”和“移除关联”。移除前 Review 明确只改变关联，不销毁 NFT、不删除 Identity，也不转移资产；完成后身份页恢复无 Current 状态。

转移号码不转移 BAP Identity、历史内容或关系。接收者的身份必须通过独立的新关联确认，不能从接收地址自动推导。

### 4.9 数字 ID 精确查找

沿用现有全局查找入口，接受核心认知指定的两种数字输入形式。去除首尾空格后，原型接受 `0` 或非零开头的十进制数字串，并允许一个前置 `#`；负数、小数、科学计数法、分隔符和多个 `#` 提示修正。前导零输入提示使用规范数字形式，不按名称处理。全程按字符串处理，不转换为 JavaScript Number。

按数字定位 Artifact，再核查 Origin 与 Current Binding，最后展示关联 BAP ID。分阶段反馈“正在查找资产”“正在核实关联”；用户修改查询时旧请求结果不得覆盖新查询。

| 返回情况 | 展示与下一步 |
| --- | --- |
| 找到且有有效关联 | Artifact 摘要、编号状态、关联 BAP ID，可打开公开身份 |
| 找到但无有效关联 | 展示 Artifact 与“当前没有关联身份”，不能以 creator 或 owner 代替 |
| 编号尚未稳定 | 展示实际匹配结果并提示确认进度，不伪装为稳定 |
| 重组或解析待核实 | 明确暂不能确认编号映射，允许重试，不提供未经核实的身份跳转 |
| 确定未找到 | 说明未找到该数字 ID，保留输入；与服务错误分开 |
| 服务不可用 | 说明查找暂不可用，保留输入并重试，不显示未找到 |

## 5. 原型数据与模拟边界

沿用可展开的场景面板，集中标注“模拟钱包与链上数据”。提供固定身份 A/B 和以下确定性场景：无资产、多资产、编号为空、编号解析中、5 个确认、6 个确认、稳定后重组、编号变化、无关联、控制权变化、Origin 失效、签名取消、签名归属不匹配、广播拒绝、结果待核实、关联失败及存储失败。编号和确认数只由场景数据驱动，不随机分配或按时间推测链上结果。

样例库存可公开查看，私有草稿按身份隔离；本机创建的演示资产只在当前浏览器 origin 存在。跨浏览器或清空本地数据后显示“未找到此演示资产”，不声称可以从链上恢复。场景面板重置需要确认并说明将清除哪些本地演示数据，不改变旧版本原型存储。

同一演示存储只允许一个页面执行写操作；其他页面可以公开阅读，接手前重新读取最新记录。所有请求和操作带原身份、对象与操作标识，防止双击、旧回调及账户切换产生重复资产或错绑。

## 6. BDD 验收

场景编号用于原型实现和证据映射。这里列出应达到的行为，不代表本次已完成浏览器验证。

| 场景 | Given（前置） | When（动作） | Then（结果） |
| --- | --- | --- | --- |
| A01-A | 身份有多个 Artifact | 打开工作台和当前身份 | Current 与其他项可区分，数字 ID 与 BAP ID 分别可见 |
| A01-B | 无资产或服务错误 | 打开工作台 | 分别显示创建入口或重试；无资产仍可进入内容与身份查找 |
| A01-C | 访客打开详情或创建入口 | 阅读或尝试创建 | 详情只读；创建引导连接和设置，不产生授权 |
| A02-A | 选择有效图片并输入名称 | 保存、刷新、检查创建 | 同一身份恢复图片与名称，Review 使用最新完整内容 |
| A02-B | 已有草稿 | 选择损坏或超限文件，或保存失败后离开 | 原内容不丢失；错误明确，未保存不宣称已保存 |
| A03-A | Review 有效 | 授权创建及默认关联 | 逐笔显示身份签名；创建和关联分别成功；编号不预先分配 |
| A03-B | 钱包取消、签名无效或归属不匹配 | 继续创建 | 分别显示取消或失败，保留草稿，不广播 |
| A03-C | Artifact 已创建但默认关联失败 | 重试关联 | 使用同一 Artifact，只重试关联，不重复创建 |
| A03-D | 广播响应丢失或已提交后刷新 | 查询操作结果 | 待核实期间禁止重复提交；明确未接收后才可重新 Review |
| A03-E | Review 后修改内容或账户变化 | 尝试继续旧操作 | 旧授权失效；已提交结果留在原身份，不由新身份续办 |
| A04-A | creator、signer、owner、Binding 各不相同 | 查看详情与 Proof、复制标识 | 独立表达四者；复制值完整，样例验证不冒充真实验证 |
| A04-B | 没有有效 Binding 或内容加载失败 | 打开详情 | 显示对应提示；仍可查看已知标识，不推导关联身份 |
| A05-A | 编号已解析且有 5 个确认 | 场景推进到 6 个确认 | 同一编号从尚未稳定变为稳定，身份签名和 Binding 状态不随之改变 |
| A05-B | 未入块或已有确认但编号未解析 | 打开编号区域 | 分别显示待确认或解析中，无假编号；首次解析已达阈值可直接稳定 |
| A05-C | 编号已稳定 | 触发重组并重新解析到较低确认数或新编号 | 先待核实，再按新事实降级或更新；Inscription ID 不变 |
| A05-D | 查询失败，或当前转移交易未确认 | 刷新详情 | 不用缓存宣称当前稳定，不用转移确认数覆盖铭文确认数 |
| A06-A | 钱包持有另一有效 Artifact | 检查并签名设置 Current | 新关联生效后切换，旧关联进入历史；数字查询只有一个当前结果 |
| A06-B | 已是 Current、资格未知或并发关联变化 | 尝试设置 | 分别不重复授权、要求核实或重新 Review；失败不抹掉仍有效的原 Current |
| A07-A | 当前输出可用、接收地址有效 | Review 并签名转移 | 交易结果与关联重验分开；新事实确认失效后旧 Current 不再有效 |
| A07-B | 地址无效、输出过期或只有花费签名 | 尝试转移 | 阻止执行，给出修正或刷新入口，不能显示成功 |
| A07-C | 转移结果未知后切换账户 | 查询或返回旧身份 | 不重复转移、不称已撤回，不自动绑定接收者身份 |
| A08-A | 关联因所有权或 Origin 失效 | 选择其他资产或确认移除关联 | 恢复有效 Current 或无 Current；资产和 Identity 均未被删除 |
| A08-B | 仅服务临时不可用 | 打开身份页 | 显示待核实和重试，不冒充永久失效 |
| A09-A | 存在有效关联样例 | 分别查找 `165` 与 `#165` | 得到相同 Artifact 与 BAP ID，复制编号为完整数字串 |
| A09-B | 资产存在但没有有效关联 | 输入编号 | 只返回资产和无关联说明，不用创建者或 owner 填充身份 |
| A09-C | 未找到、服务故障、重组或输入无效 | 查询 | 各自有明确反馈；错误不显示为空结果，待核实时无错误身份跳转 |
| A09-D | 输入超过安全整数范围的数字串或快速更换查询 | 查询与复制 | 精度不丢失，旧响应不覆盖新查询 |
| X01 | 任一 Review 已打开 | 切换语言或主题 | 图片、名称、标识、确认数、身份与授权快照不变 |
| X02 | 320px 页面或仅键盘操作 | 完成主流程并关闭弹窗 | 页面无横向溢出，焦点可见、可返回，状态不只靠颜色表达 |
| X03 | 第二标签页或存储失败 | 发起写操作或尝试恢复 | 不并发重复写入，失败反馈真实，恢复后先读取最新记录 |
| X04 | 操作产生多笔交易，或查看轮换前签名 | 检查 Proof 样例 | 每笔都有明确操作 BAP ID；历史签名按当时密钥验证，不能只验证当前密钥 |
