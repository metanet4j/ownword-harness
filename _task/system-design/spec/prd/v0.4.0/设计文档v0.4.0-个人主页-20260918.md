# Ownword 产品设计 v0.4.0：Identity 个人主页

> 高保真原型设计文档；需求核对日期：2026-10-12。

## 0. 文档定位

本文定义 Identity 公开个人主页的页面、内容展示、关注与好友交互、状态、视觉方案及原型验收。当前交付为设计文档，原型制作依据本文另行登记任务。

[核心认知](../../核心认知.md)是产品事实的唯一来源；设计方法遵循[OwnWord 设计与设计系统](../../../../../standard/OwnWord设计与设计系统.md)。本文规定这些事实如何呈现在本版本，不另建产品定义、链上 Schema、生产 API 或数据库契约。事项状态见[任务清单](../../../feature_list.json)。

本版以公开作品为主体，顶部集中呈现身份介绍、标识、关系人数和操作。沿用 Spectrum S2，使用真实可读的内容样例组织页面；钱包、关系交易、索引与 Proof 在拟制作原型中使用确定性模拟数据。模拟结果不能作为真实上链或密码学验证证据。

## 1. 版本目标与需求依据

访客进入主页后能够回答：这是谁、发布了什么、如何阅读或播放、如何关注或申请好友，以及他关注谁、谁关注他。

用户已确认的范围落在核心认知第 6.2、7.8、9.5、10.7 节：好友需要申请并由对方接受，遵循 BitcoinSchema Friend；图片、视频和音频可以是独立内容条目，博客中也可以包含媒体；关注和粉丝列表向所有访客公开。

“访问上下文”只决定当前访客能执行哪些操作，不改变公开内容的可见性。页面同时保存主页所属 Identity 和当前操作 Identity，避免看着他人的主页却误用主页身份发起操作。

### 3.1 访问上下文

| 当前上下文 | 公开读取 | 关系操作的呈现 |
| --- | --- | --- |
| Wallet 未连接 | 主页、内容和公开关系列表均可访问 | 点击“关注”或“添加好友”后进入连接流程，连接完成重新核实身份与关系并进入 Review，不自动提交 |
| Wallet 已连接，Identity 尚未完成设置 | 同上 | 提示完成 Identity 设置；保留主页目标，完成后重新核实 |
| 当前操作 Identity 等于主页 Identity | 同上 | 隐藏关注自己和添加自己；可通过已有入口进入“我的身份” |
| 已具备操作条件的其他 Identity | 同上 | 按当前关注和好友状态显示操作 |
| 关系读取失败或尚未完成 | 同上 | 保留已知结果及核实时点；无法确定是否会重复提交时只提供重新查询 |

上述判断不使用传统平台账号权限，也不根据路由中的 BAP ID、Profile 名称、数字 ID 或钱包连接本身推断签名授权。

## 4. 页面、组件与交互

### 4.1 信息架构与导航

以下为拟制作原型的公开路由约定，正式 URL 由后续实现确认。标识进入路由时正确编码，解析、比较和复制均使用完整原值。

| 页面或视图 | 原型入口 | 首要信息与返回 |
| --- | --- | --- |
| Identity 个人主页 | `#/identity/<bapId>` | 身份介绍与公开内容；数字 ID 查找成功后也进入此稳定入口 |
| 博客或媒体详情 | `#/content/<txid>` | 内容主体、作者和发布时间；返回原主页并恢复筛选及位置 |
| 关注列表 | `#/identity/<bapId>/following` | 当前主页 Identity 关注的对象；返回其主页 |
| 粉丝列表 | `#/identity/<bapId>/followers` | 关注当前主页 Identity 的对象；返回其主页 |
| 身份详情 | 主页标识区域的“身份详情” | 完整身份标识、关联与签名说明；关闭回到触发点 |
| 关系 Review 与结果 | 主页或关系列表的操作按钮 | 操作方、目标方、动作及处理结果；关闭保留原页面 |

公开详情使用发布交易定位，不能用本地 UUID 或可能变化的数字 ID 作为唯一分享标识。历史版本链接保持指向所选版本；返回主页时恢复当前位置，不将用户重新带到列表顶部。

顶部沿用既有模块入口、语言和外观控件。Wallet 连接状态作为紧凑的会话信息，不占据公开内容的主视觉位置。公开主页提供清晰的页面标题和来源返回入口；浏览器后退、直接访问与刷新均有可解释结果。

### 4.2 主页构图与视觉方案

阅读顺序是身份介绍 → 关系入口 → 内容筛选 → 内容流。桌面内容容器最大宽度建议 1120px，水平居中；页边距在 S2 间距尺度内选择 24–32px。顶部身份区域自然排列，不设置固定大高度：头像、名称、简介和标识成组，关注与好友操作位于同一组右侧；关注和粉丝人数紧邻身份信息，作为列表入口。

内容区采用按时间排列的单列内容流，内部按媒介安排文本和预览；需要并排时只在一条内容内部使用缩略图与正文布局。每条内容具有清晰标题或内容说明、类型、发布时间与入口，不把全部内容机械排列成同规格方形卡片。媒体预览由作品本身提供视觉重点，博客依靠标题、摘要和排版表达。

手机将身份信息、操作和关系入口依次排成单列，内容随容器缩放。博客可用缩略图在窄屏下移到正文上方；媒体保留自身比例。主要操作不依赖悬浮，不使用固定底栏遮住阅读或播放控件。

| 视觉角色 | 来源与本版使用 |
| --- | --- |
| 页面与分组表面 | `--s2d-surface-base`、`--s2d-surface-layer-1`；通过间距和少量分隔线表达分组 |
| 主次文字 | `--s2d-content-neutral`、`--s2d-content-subdued`；正文对比度满足核心认知要求 |
| 操作与状态 | `--s2d-action-accent` 用于主操作与链接；notice、negative、positive 仅表达实际状态 |
| 字体 | 绑定 S2 的正文与标题角色；BAP ID 等原始标识使用 `--s2d-font-mono`，中文使用可读回退字体 |
| 图片与图标 | 使用内容资源及 S2 源图标；无头像时采用中性的头像回退，不随机生成外貌 |
| 动效 | 按 S2 交互反馈执行；媒体由用户启动，尊重 `prefers-reduced-motion` |

本版不以穹顶大图、渐变背景、口号或装饰性统计面板占据首屏；已有小型品牌元素按其导航用途保留。作品封面、正文图片和声音信息均需有内容依据，空状态不能通过编造作品、时长、粉丝人数或证明徽章填充。

方案自评：顶部介绍回答“谁”，内容流回答“发布了什么”；同一作品的预览与说明靠近，身份和操作归为一组；标识保持可读且不压过内容；分隔与强调均有信息作用。上述是设计方案评审，实际视觉效果需在原型制作后按设计指南第 8.1 节查看截图并复核。

### 4.3 身份介绍与详情

展示 Profile 的头像、名称和简介；字段缺失时分别回退，不把未完成展示资料解释为 Identity 不存在。名称缺失可用缩略 BAP ID 作为临时标题，标识区域仍显示完整可访问值；简介缺失时收紧空间，不填模板自我介绍。组织 Identity 使用已定义的组织类型。

BAP ID 位于首屏，有复制和展开完整值的入口。有效 Current Artifact 有数字 ID 时紧邻展示编号与状态，并可进入既有 Artifact 详情。无 Artifact 时不放大空白资产卡，也不向普通访客显示资产设置操作。编号或 Binding 无法核实时不宣称是当前有效数字 ID，可在身份详情保留上次已知信息及核实时点。

身份详情分层呈现 Profile、身份发布信息、可选关联信息与 Proof。使用“身份签名有效 / Signature valid”等准确文案；未验证与验证失败各自说明，不把签名结果解释成现实人物认证。身份详情不展示私钥或要求导入密钥。

### 4.4 公开内容流

默认筛选“全部 / All”，其次为“博客 / Blog”“图片 / Images”“视频 / Video”“音频 / Audio”。采用 S2 Tabs，窄屏可横向浏览标签，选中状态和键盘焦点明确；筛选状态可随返回恢复。没有选中类型的作品时显示该类型的空状态，仍可切回全部。

默认按各内容当前公开版本的发布时间倒序排列，同一时间使用稳定标识保证顺序；同一作品的 Revision 在聚合流中展示当前版本，历史版本从详情进入。没有可靠版本关系的独立 Post 不强行合并。只有公开发布时间未知时才显示“发布时间待核实”，不能编造日期。

| 内容类型 | 列表表现 | 打开后的主要任务 |
| --- | --- | --- |
| 博客 | 标题、正文生成的短摘要、发布时间；有真实封面才展示 | 阅读正文、内嵌媒体和版本 |
| 图片 | 预览、原始标题或说明、发布时间；可查看完整画面 | 查看图片、说明与来源 |
| 视频 | 静态封面或中性回退、标题、实际可用的时长 | 用户点击后播放，查看说明 |
| 音频 | 标题或说明、实际可用的时长；有真实封面才展示 | 用户点击后播放和控制进度 |

媒体筛选依据 MIME 与可用资源信息，界面分类不写入新的协议类型。标题缺失时用“图片 / 视频 / 音频”加简短的原始标识区分，不生成不存在的创作描述。列表使用“加载更多”控制后续读取，保留已加载内容；后续页失败只重试该页，不清空首批结果。

主页无作品时显示“尚未发表公开内容”；本人可进入已有“我的内容”，访客仍可访问关系列表与身份信息。内容加载失败、确实为空和身份未找到分别表达。身份、内容和关系分别加载，某一模块失败不遮蔽已成功加载的其他模块。

### 4.5 博客与媒体详情

博客沿用 [v0.2.0 阅读设计](../v0.2.0/设计文档v0.2.0-20260917-210556.md)的 Markdown 语义、作者归属、版本和 Proof，阅读正文建议限制在 680–760px 宽度。作者名称与 BAP ID 进入作者主页；标题、发布时间和版本摘要紧邻正文。历史版本明确标注，提供进入当前版本的操作，不覆盖历史正文。

媒体详情复用相同的作者与来源区域，以图片或播放器作为主体。图片默认完整查看，可由用户放大并恢复；视频和音频使用可访问的播放、暂停、进度和音量控制，时长由实际资源读取。列表和详情默认不自动播放；离开媒体详情停止播放，不在后台继续发声。播放器加载和播放失败有明确反馈，资源不可用时保留标题、作者和已知来源。

Markdown 内的媒体仍属于该博客的阅读内容，可跳转到原媒体来源；不能仅因嵌入他人的媒体就改变博客作者或媒体作者。内容作者归属、载荷读取与媒体播放是独立结果，成功播放不证明签名有效，资源失败也不自动判定内容不存在。

读取不可信 Markdown 与媒体时使用安全渲染：脚本、事件属性和危险 URL 不能执行，未知或不支持格式给出提示；不直接执行任意 HTML 或 SVG 内容。博客内图像提供来源已有的替代文本；视频字幕、音频文字稿仅在源内容提供时展示，不伪造转录。

### 4.6 关注与取消关注

| 已核实状态 | 操作与反馈 |
| --- | --- |
| 未关注 | “关注 / Follow”进入 Review |
| 已关注 | “已关注 / Following”保持稳定，明确的“取消关注 / Unfollow”入口进入 Review |
| 操作处理中 | 显示正在执行的具体动作，阻止同一方向重复提交 |
| 关系未知或提交结果待核实 | 显示核实提示并提供查询，不把未知状态当作未关注 |

Review 和恢复规则统一见第 4.9 节。模拟交易被网络接收且派生关系可核实后，更新相应按钮与受影响的列表和人数；入块状态单独展示。取消授权或明确失败不提前增减人数。索引尚未追上时说明正在同步，不能把本地乐观数字标为已核实。

取消关注只影响当前操作 Identity 到目标 Identity 的方向，对方是否关注自己及好友状态保持各自含义。关注不要求发送好友申请，也不因成为好友而自动关注。

### 4.7 好友申请与接受

按钮表达采用核心认知第 9.5 节的业务状态；当前操作身份变化后重新派生。

| 状态 | 主页或列表操作 |
| --- | --- |
| 无好友申请 | “添加好友 / Add friend”进入申请 Review |
| 已发送申请 | “等待接受 / Request sent”，可查看申请详情，不能重复申请 |
| 收到对方申请 | “接受申请 / Accept request”进入接受 Review；可稍后处理，离开不改变记录 |
| 已是好友 | “已是好友 / Friends”，可查看关系详情 |
| 状态未知 | “好友状态待核实”，查询后再决定可执行操作 |

好友申请使用 `friend` 记录表达当前 Identity 对目标 Identity 的意愿；接受由对方以其自己的 Identity 授权相反方向的 `friend` 记录。双方记录有效后显示已是好友。该归并遵循核心认知第 6.2 节的产品解释，官方文档本身没有单独的申请和接受类型，生产适配须按第 12 节验证。

原型用 Identity A、B 双方场景表达完整过程：A 申请 B → A 看到等待接受 → 切换为 B 访问 A 的主页 → B 接受 → 双方看到已是好友。切换身份使用演示面板或已有 Wallet 场景，不允许直接修改路由来获得另一身份的权限。Review 明确申请或接受将公开哪些关系与签名信息，通信公钥在详情中解释，私钥始终留在 Wallet。

好友与关注并排显示各自状态，不用一个按钮同时执行两种动作。若接受前已经出现双方有效记录，重新核实后直接显示已有结果；签名前再检查目标与关系，不为同一关系补发重复交易。

### 4.8 关注与粉丝列表

主页用“关注 N / Following N”“粉丝 N / Followers N”两个紧凑入口进入公开列表。人数来自已核实的有效关系汇总，不能将当前已加载行数当作总人数。人数尚未取得时仍有列表入口，显示加载或待核实提示，不用零填充。

列表顶部显示其所属 Identity 和列表方向，使用 S2 Tabs 在关注与粉丝之间切换。每行展示头像、名称、必要的简介或 BAP ID 摘要；身份区域可进入该 Identity 的主页。只有当前操作 Identity 具备条件且关系已核实，才在行内显示对应关系操作；这些操作始终以当前操作 Identity 为操作方，不替主页所有者管理其关系。

按稳定查询结果分页，同一 BAP ID 去重。确实为空时给出“尚未关注其他 Identity”或“暂无粉丝”；首屏失败提供重试，分页失败保留已加载行。目标资料解析失败时保留完整 BAP ID 与访问入口，不丢弃这条已核实关系。关系读取与 Profile 读取的状态分开。

列表中的身份入口、关系动作和复制入口分别可操作，避免整行点击吞掉按钮动作。浏览器返回恢复原列表方向、已加载内容与位置；总人数、行项目和操作状态如来自不同查询时点，显示同步状态或重新查询，不能声称完全一致。

### 4.9 Review、钱包授权与异常恢复

申请、接受、关注和取消关注复用同一确认结构。Review 显示动作、操作方和目标方的名称及完整可复制 BAP ID、关系变化及公开影响；名称仅帮助识别。主按钮分别为“签名并关注 / Sign & follow”“签名并取消关注 / Sign & unfollow”“签名并申请 / Sign & request”“签名并接受 / Sign & accept”。

进入 Review 固定动作和身份快照，继续执行前重新核实资格和关系；变化时提示重新检查。钱包确认沿用核心认知第 6.3、6.4 节，原型明确模拟，不在页面虚构费用、通信密钥派生或真实验证结果。

| 阶段或异常 | 反馈与恢复 |
| --- | --- |
| 未连接或 Identity 未就绪 | 复用现有连接与设置流程，保留目标，完成后重新核实；用户仍主动确认操作 |
| 等待 Wallet 授权 | 显示本次动作和操作身份；关闭或拒绝为已取消，关系保持原已知结果 |
| 签名校验失败 | 明确归属缺失、无效或不匹配；不进入广播，修复后重新 Review |
| 交易处理中 | 给出当前阶段，阻止重复提交；离开后保留原身份下的查询记录 |
| 网络已接收，关系已核实 | 展示具体业务结果，确认状态单独呈现 |
| 网络已接收，索引未同步 | 显示正在同步关系，继续查询；不再次提交，也不把人数显示为已核实新值 |
| 明确未接收或构造失败 | 保留原关系，说明失败原因；用户重新 Review 后重试 |
| 已提交但响应丢失 | 显示结果待核实，只查询原操作；明确未接收后才可重新执行 |
| 切换或断开操作 Identity | 未提交 Review 与授权失效；已提交记录仍归原 Identity 查询，不能以新身份继续旧动作 |
| 结果保存失败 | 保留本轮交易与恢复标识，提示保存问题；不能以记录丢失为由开放重复提交 |

Review 对话框打开后焦点进入标题或首个合理控件，Tab 保持在弹层内，Escape 在允许关闭的阶段可关闭，关闭后焦点回到有效触发点。交易正在处理时关闭只影响页面显示，不声称取消已经提交的交易。

## 5. 原型数据与模拟边界

拟制作原型使用固定的 A、B、C 三个 Identity。至少包含：完整 Profile、有数字 ID、无 Artifact、资料缺失；有博客和独立图片、视频、音频的主页及空主页；当前和历史博客版本；不同方向的 Follow；无申请、申请发出、申请收到、双方好友和未知关系。样例标识可完整复制，全部演示数据在可展开的“演示数据”入口说明。

博客样例应有可读正文，媒体使用实际可加载的本地资源并记录来源和使用依据；时长从文件取得，图片替代文本与标题依据样例内容编写。不能用不工作的播放按钮代替媒体体验。无可用媒体时明确缺少资源，不能将占位缩略图作为播放验收。

演示面板控制取消授权、签名归属不匹配、网络拒绝、索引延迟、结果未知、关系读取失败、分页失败、媒体不可用和状态保存失败。面板只用于切换确定性场景，不随机制造链上状态或将计时器作为真实确认依据。

钱包、签名、关系记录、作者归属验证、索引及链上确认由模拟数据驱动；导航、复制、筛选、详情展开、键盘及本地媒体播放应实际工作。关系操作和恢复记录按操作 BAP ID 隔离；公开固定样例独立于 Wallet 会话。刷新恢复已保存的演示业务记录，不恢复钱包授权，未核实操作先查询。

本地模拟只在当前浏览器 origin 中成立，不能宣称跨设备传播或从链上恢复。默认不向普通访问流程反复插入协议实现说明；公开影响放在 Review，模拟范围和数据来源集中在演示入口与 Proof 详情。

## 6. BDD 验收

以下是原型应满足的场景，本次文档交付不代表已执行浏览器验收。每项必须在原型制作映射和证据中使用同一编号。

| 编号 | Given（前置） | When（动作） | Then（结果） |
| --- | --- | --- | --- |
| P01-A | 未连接 Wallet，公开 Identity 存在 | 直接打开主页 | 身份、公开内容和关系列表入口可访问，无强制连接 |
| P01-B | BAP ID 无对应公开 Identity 或格式无效 | 打开主页 | 分别显示未找到或输入问题，不展示其他 Identity 的数据 |
| P01-C | 身份成功，内容或关系读取失败 | 加载主页 | 已成功模块保留，失败模块独立重试，不伪装为空 |
| P02-A | Identity 没有 Artifact，Profile 部分缺失 | 查看首屏 | BAP ID 可识别且可完整复制，缺失字段准确回退，主页可用 |
| P02-B | 有有效 Current Artifact 与已解析编号 | 查看标识与详情 | 展示编号和独立状态，BAP ID 仍明确；无法核实时不宣称有效 |
| P02-C | 身份签名尚未验证或校验失败 | 查看身份 Proof | 各自显示实际结果，不显示现实人物认证或虚假通过 |
| P03-A | 有博客及独立图片、视频、音频，另有 Draft | 打开全部内容 | 只显示该 Identity 的公开内容，按确定顺序排列，Draft 隐藏 |
| P03-B | 有图片但没有音频 | 切换图片与音频筛选 | 图片是独立条目，音频筛选为空且可返回全部，返回后筛选可恢复 |
| P03-C | 同一博客有当前与历史 Revision | 查看主页内容流 | 展示当前版本一次，历史版本保留可访问入口，不强行合并无版本关系的 Post |
| P04-A | 博客包含正文和内嵌媒体 | 从主页打开博客 | 正文可阅读，作者进入其主页，内嵌媒体不改变作者归属 |
| P04-B | 有历史版本和当前版本 | 打开历史版本链接 | 显示所选历史正文和标记，可进入当前版本，原链接不被覆盖 |
| P04-C | Markdown 含脚本、危险 URL 或资源错误 | 阅读正文 | 危险内容不执行，资源局部报错，正文及已知来源仍可阅读 |
| P05-A | 本地图片、视频和音频资源有效 | 打开详情并使用控件 | 图片可完整查看和放大，视频与音频实际播放及暂停，离开停止播放 |
| P05-B | 媒体格式不支持或资源不可用 | 打开详情 | 分别给出格式或读取提示，保留作者及来源，不显示假时长 |
| P05-C | 媒体能播放但作者签名未核实 | 查看详情及 Proof | 播放状态与签名状态独立，不能因播放成功显示签名有效 |
| P06-A | 当前 A 未关注 B，关系已核实 | A 确认、授权并关注 B | 操作归 A、目标为 B；关系核实后按钮、出入向列表和人数一致更新 |
| P06-B | A 与 B 为好友且互相关注 | A 取消关注 B | 只取消 A→B 的 Follow，B→A 与 Friend 分别保持原状态 |
| P06-C | 交易已接收但索引延迟 | 查看关注结果 | 显示同步中并可查询，不重复提交，不把乐观人数标为已核实 |
| P07-A | A 与 B 无好友申请 | A 发出申请并核实单方记录 | A 显示等待接受，B 场景可看到收到申请，双方尚非好友 |
| P07-B | A 申请 B，B 具备操作资格 | B 访问 A 并接受申请 | 使用 B 的身份授权相反方向记录，双方有效后显示已是好友 |
| P07-C | 只有单方申请或双方 Follow | 查询好友状态 | 不显示已是好友，不自动关注，不以双向关注代替 Friend |
| P07-D | 已发送申请或双方关系已成立 | 再次尝试申请或接受 | 根据重新核实结果显示已有状态，不重复提交关系交易 |
| P08-A | B 有有效入向和出向 Follow | 未连接 Wallet 打开两种列表 | 关注显示出向对象，粉丝显示入向对象，身份入口可跳转 |
| P08-B | 总人数已核实但列表只有首批，后续页有重复对象 | 加载更多 | 总人数不取首批行数，列表按 BAP ID 去重并保持稳定顺序 |
| P08-C | 列表查询、后续页或 Profile 解析失败 | 浏览列表 | 不以错误显示零人数；保留已有行或目标 BAP ID，并提供相应恢复 |
| P09-A | 未连接 Wallet，访客点击关系按钮 | 连接或取消连接 | 公开读取始终可用；连接成功后重新核实并 Review，不自动签名提交 |
| P09-B | 已进入 Review，授权取消或签名不匹配 | 执行关系操作 | 取消与失败分别反馈，签名不匹配不广播，原已知关系不提前变更 |
| P09-C | 操作已提交但结果未知 | 返回或刷新后再次进入 | 按原身份查询，结果不明时不能重复提交；确认未接收才可重新 Review |
| P09-D | 看他人主页且关系操作处于未提交或已提交阶段 | 切换操作 Identity | 主页对象不被改写；未提交授权失效，已提交记录归原身份，关系按新身份重查 |
| P10-A | 已选择语言、主题和内容筛选 | 进入详情、返回并刷新 | 偏好按既有规则恢复，筛选和返回位置合理，用户内容与标识不被翻译或修改 |
| P10-B | 键盘或窄屏访客浏览主页与 Review | 操作标签、列表、媒体和弹层 | 焦点可见且不丢失，主要动作可达，弹层和完整标识不造成页面横向溢出 |
| P10-C | 当前 Identity 等于主页 Identity | 查看主页并从公开关系列表操作他人 | 不出现关注自己或添加自己；行内操作始终归当前 Identity，不替列表所属 Identity 执行 |

## 8. 实施依赖与验证边界

### 8.1 协议事实与生产验证

BitcoinSchema 官方 [Social Actions](https://bitcoinschema.org/docs/schemas/social-actions) 定义 Follow、Unfollow、Friend，Friend 包含目标 `bapID`、`publicKey` 和 AIP；[Content Publishing](https://bitcoinschema.org/docs/schemas/content) 定义可承载文本、图片和二进制载荷的 Post。2026-10-12 已通过官方页面核对。

官网没有单独定义申请、接受、拒绝、撤销和解除的完整生命周期。第 4.7 节的申请/接受是落实已确认产品规则的表达，不能宣称为官方已经规定的状态机。生产实施须关闭核心认知第 12 节的关系适配和媒体读取问题：通信公钥派生、身份签名与密钥历史、双方记录归并、重复与事件顺序、重组、MIME/编码/载荷及资源来源。原型模拟可先制作，生产集成不得据其推断已验证。
