# Ownword v0.2.0 内容原型实施计划

本计划提交评审，尚未启动环境搭建或原型实现。用户已确定基于当前版本继续制作文字内容高保真原型，Markdown 编辑器参考 xLog。

v0.2.0 仅处理文字内容，采用现有 Markdown Post 模型，涵盖编辑、草稿、发布、阅读和修订。内容模型依据 [核心认知](spec/核心认知.md) 第 6.1、7.4、10.3 节；本轮范围与其一致，无需新增领域类型。

## 1. 交付目标与依据

用户能够从自己的身份进入内容工作台，编辑或导入 Markdown，恢复草稿，核对身份与正文，模拟签名发布，阅读公开版本，再创建修订版本。所有可见操作必须产生相应状态变化。

本计划只定义版本范围、实施顺序和验收，不覆盖产品事实。发布、取消、账户切换和修订规则分别引用核心认知第 6.3、9.3、10.1、10.3 节。

| 数据 | 使用本地样例和浏览器草稿存储，按原型版本、BAP ID、草稿 ID 分开保存；已发布样例单独保存，供刷新后继续演练 |
| 外部服务 | 原型阶段钱包授权、广播、索引与签名结果延续现有场景模拟方式；不需要部署数据库、钱包后端或区块链节点 |
| 验证与日志 | 沿用模型断言及宿主 `agent-browser`；日志、截图和验证记录归入原型 `evidence/` |

草稿存储仅承担本机原型演练，不作为生产数据库设计。保存失败时保留内存正文，显示失败原因和重试、导出入口，不显示“已保存”。账户切换取消原账户的发布操作，旧草稿保留在原身份下，不绑定给新身份。

新增模块按职责拆分：内容状态、草稿存储、Markdown 编辑与渲染、工作台与阅读页面。钱包会话、S2 按钮与弹窗、标识复制、主题和语言继续复用现有实现。

实施前建立 v0.2.0 PRD，记录实际版本和权威路径，并同步任务提交版本约定。当前计划不是已批准的 v0.2.0 PRD，不能把 v0.1 文档改名后当作新版本依据。

## 3. xLog 编辑体验的采用范围

首版采用 Markdown 源码编辑。桌面默认编辑与预览双栏，可收起预览；手机切换编辑、预览。提供可关闭的同步滚动、专注写作、格式工具栏和快捷键说明。外层布局、工具栏、按钮与正文视觉使用 Ownword 的 S2 设计系统。

首版工具包括标题层级、粗体、斜体、删除线、引用、有序与无序列表、任务列表、链接、行内代码、代码块、表格和分隔线。支持撤销、重做、查找，以及中文输入。渲染范围为基础 Markdown 与选定 GFM 扩展，编辑、预览、确认、阅读保持一致。

以下能力排在后续版本：图片嵌入与上传、附件、音视频嵌入、公式、Mermaid、AI 写作、多人协作和自定义 HTML。导入文档包含图片、音视频或其他未支持语法时保留源文本并提示，不渲染非文字内容，也不能静默删除源文本。

正文使用 Markdown 字符串作为唯一编辑源。建议从首个一级标题派生列表标题；若设计独立标题输入框，它应编辑同一行 Markdown，不再维护另一份协议标题。最终标题必填性和长度在版本 PRD 中确定，不把 xLog 的标题规则当成 Ownword 既定约束。

技术选型参考：[CodeMirror Markdown 支持](https://github.com/codemirror/lang-markdown)、[GFM 扩展](https://github.com/remarkjs/remark-gfm)、[HTML 清理](https://github.com/rehypejs/rehype-sanitize)、[esbuild 本地构建](https://esbuild.github.io/getting-started/)。

## 4. 功能清单

| 编号 | 功能 | v0.2.0 交付内容 |
| --- | --- | --- |
| C01 | 内容入口与工作台 | 从“我的身份”进入“我的内容”；草稿、已发布筛选，新建入口、摘要、时间、空状态和加载失败 |
| C02 | Markdown 编辑器 | 源码编辑、工具栏、快捷键、撤销重做、查找、字数与 UTF-8 字节数提示；桌面分栏、手机切换 |
| C03 | 预览与正文排版 | 共用渲染器；标题、段落、引用、列表、代码和表格排版；长链接换行、代码与表格局部横向滚动 |
| C04 | 草稿管理 | 自动保存、保存中/已保存/失败状态、刷新恢复、返回继续编辑、删除草稿确认、账户隔离和未保存离开保护 |
| C05 | Markdown 导入导出 | 导入 UTF-8 `.md`、格式或编码错误提示；导入前处理已有未保存内容；导出原始 Markdown |
| C06 | 发布确认 | 正文预览、当前作者与完整可复制 BAP ID、公开发布影响；返回编辑保留内容，正文变更后重新确认 |
| C07 | 发布结果 | 模拟授权、处理中、成功、取消、失败与重试；防重复提交、账户切换中断、发布结果与链上确认分开呈现 |
| C08 | 内容详情与公开阅读 | 正文、作者身份入口、发布时间、版本和内容标识；本人可创建修订，其他浏览者只读；复制链接、导出 Markdown |
| C09 | 修订与版本历史 | 从已发布内容创建新草稿；发布新版本后可查看当前与旧版本，旧正文不被覆盖；无改动不进入发布 |
| C10 | Proof 与交易详情 | 可展开查看作者 BAP ID、签名状态、TxID 与确认信息；标识完整复制，结果是原型样例时与现有模拟说明一致 |

建议按六组页面组织：内容工作台、编辑器、发布确认、发布结果、内容详情、版本历史。Proof 可在详情页展开，避免增加重复页面。公开阅读入口使用可刷新的 URL；原型数据只在本机持久化，复制链接不等同于互联网发布服务。

本版功能范围不含问答、评论、点赞、转发、关注、悬赏、标签体系和推荐流。

## 5. 关键场景与验收

| 场景 | 应验证的结果 |
| --- | --- |
| 新建、输入、刷新 | 草稿恢复到同一身份，正文不丢失；显示真实保存状态 |
| 工具栏与预览 | 选区格式操作和撤销正确；预览、Review、公开阅读输出一致 |
| Markdown 导入导出 | UTF-8 中文、换行和代码内容保持；编码错误不替换当前草稿 |
| 发布成功 | 核对当前身份后授权；成功进入详情，可同时显示确认中 |
| 取消与失败 | 不丢失正文，用户取消不标为系统失败；重试不能导致重复发布 |
| 切换账户或断开 | 取消进行中的敏感操作；异步返回不能污染新身份或发布旧草稿 |
| 修订 | 新版本具有独立内容记录与交易；旧链接和旧正文仍可访问 |
| 主题与语言 | 编辑中的 Markdown 和标识不被改写，选区和光标尽量保持 |
| 边界内容 | 空正文、长文、长链接、宽表格、代码块和不支持语法有明确行为 |
| 渲染安全 | 脚本、事件属性和危险链接不执行；编辑源不因预览清理被改写 |

正文长度、导入文件大小、标题约束及发布费用尚无 v0.2.0 权威定义。实施时先形成可评审规则；原型性能测试使用明确标注的样例上限，不将其描述为链上协议限制。

每个实施阶段默认验证一个正常场景与相关边界，查看受影响桌面和手机截图，记录浏览器错误。涉及内容保存、授权和修订的状态分支保留最小可运行断言。无需每轮重跑旧身份原型全部组合；变更触及钱包会话时再补测对应关联路径。

## 6. 实施顺序

| 阶段 | 产出 | 完成门槛 |
| --- | --- | --- |
| P0 范围与环境 | 按已确认的文字范围形成 v0.2.0 PRD，建立 worktree、版本隔离存储与编辑依赖构建 | 新旧预览均可打开；S2 绑定、版本来源和依赖锁定可追溯 |
| P1 写作与草稿 | 内容工作台、xLog 式编辑器、统一预览、导入导出、自动保存 | 可以写、看、保存、刷新恢复；用户可先评审核心写作体验 |
| P2 发布与阅读 | 身份 Review、模拟授权、发布结果、详情和 Proof | 发布闭环、取消保留、失败重试与身份切换通过 |
| P3 修订与交付 | Revision、历史版本、内容边界与视觉打磨 | 旧版本可读，正常与边界证据齐备，提交用户复核 |

建议第一批先交付 P0 与 P1，写作体验确认后推进发布和修订。每个功能完成即提交，原型提交引用实际 v0.2.0 PRD；最终集成回 `dev`。
