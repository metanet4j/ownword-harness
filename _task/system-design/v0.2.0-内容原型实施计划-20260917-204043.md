# Ownword v0.2.0 内容原型实施计划

本计划提交评审，尚未启动环境搭建或原型实现。用户已确定基于当前版本继续制作文字内容高保真原型，Markdown 编辑器参考 xLog；身份签名与真实链上发布为本版必备能力。

v0.2.0 仅处理文字内容，采用现有 Markdown Post 模型，涵盖编辑、草稿、发布、阅读和修订。内容模型依据 [核心认知](spec/核心认知.md) 第 6.1、7.4、10.3 节；本轮范围与其一致，无需新增领域类型。

## 1. 交付目标与依据

用户能够从自己的身份进入内容工作台，编辑或导入 Markdown，恢复草稿，核对身份与正文，经钱包授权完成 BAP 身份签名并发布到 BSV 网络，阅读真实链上版本，再创建修订版本。发布验收必须提供真实交易与身份归属验证证据。

本计划只定义版本范围、实施顺序和验收，不覆盖产品事实。发布、取消、账户切换和修订规则分别引用核心认知第 6.3、9.3、10.1、10.3 节。

## 2. 环境构建方案

| 项目 | 建议方案 |
| --- | --- |
| Git 基线 | 原型仓库从 `dev@8d924ae` 新建 `prototype/v0.2.0-content`；通过 worktree 保留当前版本并行查看 |
| 原型目录 | `designs/own-word-prototype-v0.2.0/`，与原型仓库共享 Git 历史，不复制成另一个独立仓库 |
| 预览 | 继续使用服务整个 `designs/` 的 4311 端口，新地址为 `http://127.0.0.1:4311/own-word-prototype-v0.2.0/`；该地址目前尚未创建 |
| 运行方式 | 沿用 React 18.3.1、Babel 和本地 S2 bundle；新内容页拆为独立 JSX 文件 |

| Markdown 渲染 | `unified + remark-parse + remark-gfm + remark-rehype + rehype-sanitize + rehype-stringify`；编辑预览、发布确认和公开阅读共用一条渲染流程 |
| 依赖管理 | 增加 `package.json`、锁文件及 esbuild 脚本，打包编辑器、渲染器和经验证的钱包适配依赖；静态依赖本地加载，真实发布和查询需要网络 |
| 本机工具 | 已检查：Node `v24.14.0`、npm `11.18.0`；具体依赖版本在首次安装验证后锁定，不直接照搬 xLog 的旧依赖清单 |
| 数据 | 草稿按版本、网络、BAP ID、草稿 ID 隔离保存；发布操作记录保存网络、请求标识和已知 TxID，支持刷新后恢复查询。已发布正文来自链上交易或可追溯索引，本地仅作缓存 |
| 钱包与身份 | 接入真实 Yours Wallet 与 BAP 身份解析，取得当前可签名身份；现有示例身份不能用于真实发布。未发布身份需走真实身份准备流程 |
| 链上服务 | 配置与钱包网络一致的广播、交易查询和 BAP 解析服务；优先使用可用现成服务，自建节点不是默认前提。若鉴权或跨域阻止浏览器直连，再增加最小服务适配层 |
| 验证与日志 | UI 使用模型断言及宿主 `agent-browser`；真实发布另保留钱包结果、广播接收、TxID、原始交易和签名验证证据。日志不记录密钥与助记词 |

草稿存储仅承担本机原型演练，不作为生产数据库设计。保存失败时保留内存正文，显示失败原因和重试、导出入口，不显示“已保存”。账户切换取消原账户的发布操作，旧草稿保留在原身份下，不绑定给新身份。

新增模块按职责拆分：内容状态、草稿存储、Markdown 编辑与渲染、工作台与阅读页面。钱包和链上能力通过核心认知第 5.2 节的领域接口接入；复用身份页面、S2、标识复制与偏好逻辑，替换发布路径依赖的模拟会话和身份解析。确定性演练可保留在测试入口，数据与真实环境隔离，不作为链上发布验收证据。

P0 先验证一条最小链路：真实钱包连接、BAP ID 解析、指定正文的身份签名、Post 交易构造、广播和按 TxID 读回。网络、费用、可公开的样例正文与钱包授权在实际发布前确认。本轮仅修改计划，不发送交易。

实施前建立 v0.2.0 PRD，记录实际版本和权威路径，并同步任务提交版本约定。当前计划不是已批准的 v0.2.0 PRD，不能把 v0.1 文档改名后当作新版本依据。

## 3. xLog 编辑体验的采用范围

首版采用 Markdown 源码编辑。桌面默认编辑与预览双栏，可收起预览；手机切换编辑、预览。提供可关闭的同步滚动、专注写作、格式工具栏和快捷键说明。外层布局、工具栏、按钮与正文视觉使用 Ownword 的 S2 设计系统。

首版工具包括标题层级、粗体、斜体、删除线、引用、有序与无序列表、任务列表、链接、行内代码、代码块、表格和分隔线。支持撤销、重做、查找，以及中文输入。渲染范围为基础 Markdown 与选定 GFM 扩展，编辑、预览、确认、阅读保持一致。

以下能力排在后续版本：图片嵌入与上传、附件、音视频嵌入、公式、Mermaid、AI 写作、多人协作和自定义 HTML。导入文档包含图片、音视频或其他未支持语法时保留源文本并提示，不渲染非文字内容，也不能静默删除源文本。

正文使用 Markdown 字符串作为唯一编辑源。建议从首个一级标题派生列表标题；若设计独立标题输入框，它应编辑同一行 Markdown，不再维护另一份协议标题。最终标题必填性和长度在版本 PRD 中确定，不把 xLog 的标题规则当成 Ownword 既定约束。

技术选型参考：[CodeMirror Markdown 支持](https://github.com/codemirror/lang-markdown)、[GFM 扩展](https://github.com/remarkjs/remark-gfm)、[HTML 清理](https://github.com/rehypejs/rehype-sanitize)、[esbuild 本地构建](https://esbuild.github.io/getting-started/)。

## 4. 功能清单

| 编号 | 功能 | v0.2.0 交付内容 |
| --- | --- | --- |
| C01 | 内容入口与工作台 | 从“我的身份”进入“我的内容”；草稿、已发布筛选，新建入口、摘要、时间、空状态和加载失败 |
| C02 | Markdown 编辑器 | 源码编辑、工具栏、快捷键、撤销重做、查找、字数与 UTF-8 字节数提示；桌面分栏、手机切换 |
| C03 | 预览与正文排版 | 共用渲染器；标题、段落、引用、列表、代码和表格排版；长链接换行、代码与表格局部横向滚动 |
| C04 | 草稿管理 | 自动保存、保存中/已保存/失败状态、刷新恢复、返回继续编辑、删除草稿确认、账户隔离和未保存离开保护 |
| C05 | Markdown 导入导出 | 导入 UTF-8 `.md`、格式或编码错误提示；导入前处理已有未保存内容；导出原始 Markdown |
| C06 | 发布确认 | 核对正文快照、真实作者与完整可复制 BAP ID、网络和公开发布影响；展示可获取的费用信息，实际付款由钱包确认；正文或身份变化后重新 Review |
| C07 | 身份签名与链上发布 | 真实钱包授权、BAP 归属的内容签名、Post 编码、交易广播和状态查询；展示处理中、成功、取消、失败与结果待核实，防重复提交并处理账户切换 |
| C08 | 内容详情与公开阅读 | 按真实 TxID 查询正文，展示作者、时间、版本和内容标识；本人可创建修订，其他浏览者只读；复制链接、导出链上原始 Markdown |
| C09 | 修订与版本历史 | 从已发布内容创建新草稿；发布新版本后可查看当前与旧版本，旧正文不被覆盖；无改动不进入发布 |
| C10 | Proof 与交易详情 | 验证正文对应的 AIP 签名及签名地址与作者 BAP ID 的归属，展示真实 TxID、查询来源和确认信息；未验证、验证失败与签名有效分别呈现，标识完整复制 |

建议按六组页面组织：内容工作台、编辑器、发布确认、发布结果、内容详情、版本历史。Proof 可在详情页展开，避免增加重复页面。公开阅读 URL 携带可恢复查询的网络与 TxID，不依赖作者本机草稿；原型未部署公网时，本机预览地址仍只供本地访问。

发布链路按核心认知第 6.1、6.3、9.3 节实现，Post 编码与 AIP 格式参考 [BitcoinSchema 官方定义](https://github.com/BitcoinSchema/schema/blob/master/docs/social_schema.md#post)。内容签名与交易输入签名分别验证：仅付款交易签名成功，不能证明内容属于当前 BAP Identity。

签名针对 Review 确认的原始 Markdown 字节及协议规定的签名范围，不能签预览 HTML，也不能在签名后改写正文。具体 AIP 签名封装、密钥路径和身份归属验证须通过实际钱包输出核实；通用 `createSignature` 或 `inscribe.signWithBAP` 的存在，不等于已证明它能直接满足此 Post 流程。[钱包官方 API](https://github.com/yours-org/yours-wallet/blob/main/docs/provider-api.md)

本版功能范围不含问答、评论、点赞、转发、关注、悬赏、标签体系和推荐流。

## 5. 关键场景与验收

| 场景 | 应验证的结果 |
| --- | --- |
| 新建、输入、刷新 | 草稿恢复到同一身份，正文不丢失；显示真实保存状态 |
| 工具栏与预览 | 选区格式操作和撤销正确；预览、Review、公开阅读输出一致 |
| Markdown 导入导出 | UTF-8 中文、换行和代码内容保持；编码错误不替换当前草稿 |
| 身份签名 | 正文与签名范围一致，签名校验通过且归属当前 BAP ID；更改正文后旧签名校验失败，错误身份不得显示为签名有效 |
| 发布成功 | 取得真实 TxID 和网络接收证据；在清除本地内容缓存后仍可按 TxID 读取同一 Markdown。进入详情时业务发布结果与挖矿确认分别展示 |
| 取消与失败 | 授权前取消保留草稿且不发布；签名失败、余额不足、广播拒绝分别可恢复；已获得 TxID 的重试先查询原交易，避免重复支付和发布 |
| 结果未知 | 网络超时或响应丢失时保留操作标识与已有交易数据，进入待核实；先查原交易结果，不直接创建新交易重发 |
| 切换账户或断开 | 终止未提交的旧账户授权，不用新身份继续；若交易已提交，不声称已撤回，保留原身份下的查询记录并隔离后续结果 |
| 修订 | 新版本重新签名并生成真实新交易；链上版本关联可解析，旧链接和旧正文仍可访问 |
| 主题与语言 | 编辑中的 Markdown 和标识不被改写，选区和光标尽量保持 |
| 边界内容 | 空正文、长文、长链接、宽表格、代码块和不支持语法有明确行为 |
| 渲染安全 | 脚本、事件属性和危险链接不执行；编辑源不因预览清理被改写 |

正文长度、导入文件大小、标题约束及发布费用尚无 v0.2.0 权威定义。实施时先形成可评审规则；原型性能测试使用明确标注的样例上限，不将其描述为链上协议限制。

UI 原型每阶段默认验证一个正常场景与相关边界，查看受影响桌面和手机截图，记录浏览器错误。真实签名和发布采用集成验收：覆盖身份归属、签名字节、广播接收、结果未知后的恢复、账户隔离与修订读回。运行前明确网络、查询端点、日志位置及钱包授权方式，集成与端到端测试使用宿主环境。模拟断言仅用于可控错误路径，不替代真实链上证据。

## 6. 实施顺序

| 阶段 | 产出 | 完成门槛 |
| --- | --- | --- |
| P0 范围与环境 | 形成 v0.2.0 PRD，建立 worktree 与依赖构建，核实钱包/BAP/AIP/Post 和网络端点，验证最小签名发布链路 | 新旧预览均可打开；真实签名与 Post 交易可验证，钱包能力缺口及状态映射明确，不以模拟成功代替 |
| P1 写作与草稿 | 内容工作台、xLog 式编辑器、统一预览、导入导出、自动保存 | 可以写、看、保存、刷新恢复；用户可先评审核心写作体验 |
| P2 发布与阅读 | 将真实身份 Review、钱包签名、链上发布、详情和 Proof 接入完整 UI | 真实 TxID、签名归属、正文读回、取消保留、失败恢复与身份切换验证通过 |
| P3 修订与交付 | Revision、历史版本、内容边界与视觉打磨 | 旧版本可读，正常与边界证据齐备，提交用户复核 |

建议第一批交付 P0 的真实接入验证与 P1 的写作体验，再完成发布 UI 和修订。身份签名与链上发布属于 v0.2.0 必备范围，不递延到后续版本。每个功能完成即提交，原型提交引用实际 v0.2.0 PRD；最终集成回 `dev`。
