| ----------------- | ---------------------------------------- | -------------------------------------- |

# 2. 目标

设计一款以 **区块链 Identity 为中心** 的个人或组织身份、关系、内容平台。

用户可以：

1. 使用自己的 Wallet；
2. 创建并拥有自己的 BAP Identity；
3. 使用 Identity 签署自己的内容；
4. 将内容发布到 Bitcoin；
5. 建立 Identity 与 Identity 之间的关系；
6. 创建代表 Identity 的链上 Artifact；
7. 即使离开本平台，Identity、Content 和 Asset 仍然存在。

核心模型：

```text
Wallet
   ↓
Identity
   ↓
┌───────────────┬───────────────┬───────────────┐
│               │               │               │
Content    Relationship    Identity Artifact
│               │               │
└───────────────┴───────────────┘
                ↓
              Bitcoin
```

Wallet 是基础设施。

Identity 是产品中心。

产品需要解决三个核心问题：

```text
Who am I?
Identity

What did I say?
Words

Can it be proven?
Proof
```

核心理念：

> **Identity belongs to the user.**
> **Words are signed by the identity.**
> **Blockchain is the source of truth.**

平台负责：

- UI；
- 编辑；
- 预览；
- 索引；
- 查询；
- 搜索；
- 缓存；
- 数据解析；
- Proof 展示；
- 交易状态跟踪。

平台不拥有：

- 私钥；
- Seed Phrase；
- BAP ID；
- 已发布内容；
- Identity Artifact 所有权。

## 3.4 组件化

建议统一以下核心组件：

| 组件                   | 主要用途                                                    | 主要展示内容                                           | 典型使用位置                                      |
| ---------------------- | ----------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------- |
| `WalletConnect`        | 负责连接 Wallet 的入口和交互                                | Connect Wallet、Wallet 选择、连接中、重试              | Landing、Header、首次使用流程                     |
| `WalletStatus`         | 展示当前 Wallet 的连接状态                                  | Connected / Connecting / Failed、当前 Wallet、当前账户 | Header、Settings、异常提示                        |
| `IdentityReference`    | 用紧凑形式表示“某个 Identity”，相当于全站统一的身份引用组件 | Avatar、Name、BAP ID 缩写，可选签名/状态信息           | Post 作者、Publish Review、Relationship、交易详情 |
| `IdentityCard`         | 完整展示一个 Identity 的概要信息                            | Avatar、Name、BAP ID、Bio、Type、Artifact、操作按钮    | My Identity、Public Identity、Explore             |
| `BapIdDisplay`         | 专门展示 BAP ID，解决长字符串显示、复制、展开问题           | 缩略 BAP ID、完整值、Copy                              | Identity 页面、Proof、Transaction Detail          |
| `MarkdownEditor`       | Markdown 内容编辑器                                         | Markdown 原文、导入 `.md`、编辑、Draft 状态            | Write 页面、Create Revision                       |
| `MarkdownPreview`      | 将 Markdown 渲染成最终阅读效果                              | 标题、正文、链接、列表、代码等 Markdown 渲染结果       | Write Preview、Publish Review                     |
| `ContentCard`          | 用于列表中展示一条内容摘要                                  | Author、标题/摘要、时间、Content Status                | Identity Words、Explore、搜索结果                 |
| `ContentStatus`        | 统一展示内容当前业务状态                                    | Draft、Publishing、Published、Failed 等                | Editor、ContentCard、文章详情                     |
| `ContentProof`         | 展示一条内容为什么可以被验证                                | BAP ID、Signature、Protocol、TxID、链上状态            | Public Post、文章详情的 Proof 区域                |
| `ArtifactCard`         | 展示一个 Identity Artifact / BAP NFT                        | Artifact 图片、Origin、当前状态、是否 Current          | Identity Artifacts、Artifact 列表、选择 Artifact  |
| `ArtifactStatus`       | 表达 Artifact 与 Identity 当前的产品关系                    | Current、Not Used、Historical、Unavailable             | ArtifactCard、Artifact Detail                     |
| `TransactionStatus`    | 展示某个链上交易当前状态                                    | Broadcasting、Pending、Confirmed、Failed 等            | Publish Result、Artifact 创建、Transaction Detail |
| `TransactionReference` | 以统一方式引用一笔 Transaction                              | TxID 缩写、Copy、View Details / Explorer               | ContentProof、Artifact Detail、Identity Detail    |
| `SignatureBadge`       | 表达某个内容或行为的签名验证结果                            | Signed、Signature valid、Invalid / Unverified          | Post、ContentProof、Publish Result                |

### 更具体一点

这几个组件其实可以分成 5 组。

| 领域               | 组件                                                         | 解决的问题                                   |
| ------------------ | ------------------------------------------------------------ | -------------------------------------------- |
| Wallet             | `WalletConnect`、`WalletStatus`                              | “钱包怎么连接、现在连没连上？”               |
| Identity           | `IdentityReference`、`IdentityCard`、`BapIdDisplay`          | “这是谁？他的 BAP ID 是什么？”               |
| Content            | `MarkdownEditor`、`MarkdownPreview`、`ContentCard`、`ContentStatus`、`ContentProof` | “写了什么、现在什么状态、怎么证明是谁写的？” |
| Artifact           | `ArtifactCard`、`ArtifactStatus`                             | “这个身份资产是什么、是不是当前正在使用的？” |
| Blockchain / Proof | `TransactionStatus`、`TransactionReference`、`SignatureBadge` | “链上有没有成功、交易是什么、签名是否有效？” |

其中有几个组件尤其重要，建议产品原型阶段就定义清楚。

**`IdentityReference`** 是最值得统一的组件。它类似传统社交平台里的“用户头像 + 用户名”，但你这里不是 User，而是 Identity。例如：

```
[Avatar] Alice
         8F3a...91Bc
```

Publish Review、Post 作者、Follow 关系、交易详情全部使用同一个组件，这样用户会逐渐形成稳定认知：**Alice + BAP ID = 一个 Identity**。

**`ContentProof`** 是你这个产品区别于 Medium、Twitter 等传统内容平台的核心组件。例如：

```
Proof

Signed by
Alice
8F3a...91Bc

✓ Signature valid

Protocol
BitcoinSchema / Post

Transaction
ab31...89fe
```

普通用户默认可以折叠，真正需要验证时再展开。

**`SignatureBadge`** 则应该非常轻量，例如：

```
✓ Signed
```

或者：

```
✓ Signature valid
```

不要写成含义模糊的：

```
✓ Verified
```

因为它验证的是**密码学签名**，不是证明 Alice 是现实世界中的某个真实人物。

**`TransactionStatus` 和 `ContentStatus` 必须分开。**例如一篇文章可能已经：

```
ContentStatus = Published
```

但 Bitcoin 交易仍然：

```
TransactionStatus = Confirmation pending
```

两者如果做成一个组件，用户会很容易误认为“还没出块 = 文章没发布成功”。

所以最终建议组件关系类似：

```
ContentCard
├── IdentityReference
├── ContentStatus
└── SignatureBadge

ContentProof
├── IdentityReference
├── BapIdDisplay
├── SignatureBadge
├── TransactionReference
└── TransactionStatus
```

这样组件不是零散的，而是可以逐层组合起来

这样符合：

> Own your words.

用户可以改变观点，但不能覆盖过去的链上历史。

## 4.1.4 创建 Identity Artifact 

[^1sat 的序数ID]: 突出展示**1sat 的序数ID**



领域层：

```text
BapNFT
```

用户侧：

> **Identity Artifact**

不要把：

```text
Create BAP NFT
```

作为主要 UI 文案。

------

### 产品定义

Identity Artifact：

> 与 BAP Identity 建立关联的 1Sat Ordinal，用于身份的视觉化和资产化表达。

它可以表现为：

```text
Badge
Seal
Identity Card
Metal Plate
Artifact
```

但：

```text
Identity Artifact
≠
BAP Identity
```

Identity 可以完全不创建 Artifact。

------

### 入口

Identity Home：

```text
Identity Artifact

No artifact yet.

Create a visual artifact
for your identity.

[Create Artifact]
```

可以：

```text
Skip
```

不能阻止用户：

```text
Write
Publish
```

------

### 创建流程

```text
Create Artifact
      ↓
Choose Content
      ↓
Preview
      ↓
Review
      ↓
Create Artifact
      ↓
Wallet Confirmation
      ↓
Creating...
      ↓
Created
```

------

### 默认 Binding

用户刚创建一个 Identity Artifact 时，默认：

```text
Create Artifact
↓
Set as current Identity Artifact
```

成功：

```text
Identity Artifact created

✓ Set as your current artifact
```

不用再要求用户：

```text
Create
↓
Go somewhere else
↓
Bind
```

降低操作复杂度。

领域模型仍保留：

```text
Artifact
Binding
```

两个独立实体。

------

### 已有多个 Artifact

例如：

```text
Artifact A
Historical

Artifact B
Current

Artifact C
Not used
```

用户操作：

```text
[Set as Current]
```

统一产品文案：

```text
Current Identity Artifact
```

不要向普通用户展示：

```text
ACTIVE_BINDING
UNBOUND
INVALID_BINDING
```

------

### Binding 产品规则

这是**产品规则，不是 BAP/1Sat 协议规则**：

```text
一个 BAP ID
可以拥有多个 Artifact

但：

Current Artifact <= 1
```

即：

```text
BAP Identity
├── Artifact A    Historical
├── Artifact B    Current
└── Artifact C    Not used
```

------

### Artifact Transfer

1Sat Ordinal 可以被转移。

如果当前 Artifact 已不再满足所有权要求：

```text
Current Artifact
      ↓
Ownership changed
      ↓
Association invalid
```

用户看到：

```text
Identity Artifact unavailable

This artifact has changed ownership
and can no longer be used as your
current identity artifact.

[Choose Another Artifact]

[Remove Association]
```

必须满足：

```text
发生了什么
+
有什么影响
+
用户下一步怎么办
```

不能只显示：

```text
INVALID
```

------

### 协议依据

1Sat Ordinals 使用 1-satoshi output 承载 Inscription，并允许通过消费该 Output 转移 Ordinal。

参考：

```
BitcoinSchema/1sat-ordinals README
```

Yours Wallet 提供：

```text
getOrdinals
inscribe
transferOrdinals
```

参考：

```
yours-wallet/docs/provider-api.md
```

执行已有 Ordinal 的消费操作时，需要取得 Output/BEEF 等上下文。

参考：

```
yours-wallet/docs/gitbook/ai-onboarding.md
```

# 6. 关系

核心模型：

```text
                  Wallet
                    │
                  controls
                    │
                    ▼
               BAP Identity
                    │
       ┌────────────┼────────────┐
       │            │            │
       ▼            ▼            ▼
    Content    Relationship   Artifact
                    │
                    ▼
               BAP Identity
```

关系：

| 实体 A       | 关系             | 实体 B       | 数量     |
| ------------ | ---------------- | ------------ | -------- |
| BAP Identity | Profile          | BAP Profile  | 1 : 0..1 |
| BAP Identity | Publish          | Content      | 1 : N    |
| Content      | Revision         | Content      | 1 : N    |
| BAP Identity | Relationship     | BAP Identity | N : N    |
| BAP Identity | Artifact         | BapNFT       | 1 : N    |
| BAP Identity | Current Artifact | BapNFT       | 1 : 0..1 |

其中：

```text
Current Artifact <= 1
```

属于本产品业务规则。

# 15. 最终设计结论

平台中心模型保持：

```text
                   BAP Identity
                        │
          ┌─────────────┼─────────────┐
          │             │             │
          ▼             ▼             ▼
        Words      Relationship    Artifact
          │             │             │
          └─────────────┼─────────────┘
                        │
                        ▼
                     Bitcoin
```

Wallet：

```text
Wallet
  ↓
Identity
```

但不作为产品中心。

交互设计最终遵循：

```text
用户只理解自己的目标

Create Identity
Write
Publish
Create Artifact
```

而系统负责处理：

```text
BAP
B / MAP / AIP
Wallet Actions
Signatures
Transactions
BEEF
Ordinal
Network Status
```

通过渐进披露向高级用户展示这些协议细节。

产品需要始终保证三件事：

### 易用性

> 用户不需要先学习区块链协议才能使用产品。

### 一致性

> 相同行为使用相同文案、状态、组件和交互模式。

### 确定性

> 用户始终知道自己以哪个 Identity 操作、当前发生了什么、是否已经成功，以及失败后该做什么。

最终回到：

# Own your identity.

# Own your words.
