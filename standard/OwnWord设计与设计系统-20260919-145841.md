# OwnWord 设计与设计系统

适用于 OwnWord 界面与原型的设计、修改、评审，以及设计系统使用核对。以下工作区路径相对根目录，原型内路径相对对应原型目录。

- 设计和评审页面时，先明确用户任务、信息层级、内容关系和操作顺序，再组合组件。遵循秩序清晰、关系可感知、密度适当、表达精细四项原则；分别检查对齐与结构、格式塔关系、阅读节奏，以及图片、图标和品牌视觉的准确性。
- React Spectrum 2 是基础 UI 的权威来源。组件、颜色、字体、间距 Token、圆角、阴影、通用图标、交互状态和无障碍行为遵循项目绑定版本。OwnWord 的页面结构、信息架构、产品状态、内容关系及品牌表达依据核心认知和当前设计文档。
- 开始前读取原型的 `_d_meta.json`、绑定的 `_ds/<slug>/_ds_prompt.md` 和来源记录，确认组件包与 Token 版本；不把最新版或其他 Spectrum 版本直接作为依据。
- 官方实现优先核对本地上游源码 `reference/react-spectrum-main/react-spectrum-main/packages/@react-spectrum/s2/`，用 `package.json` 确认版本。资料不足时再查官方文档，并核对其与绑定版本的适用性。
- 区分官方源码与规范、本地导入的设计资料、页面实际加载的原型封装。`designs/react-spectrum-s2/` 和原型内的 `_ds/react-spectrum-s2/` 不因包含 S2 名称就等同于官方生产包；生成的 bundle、CSS 和消费副本不能替代官方实现。
- 核实页面实际加载的组件、Token、图标及 OwnWord CSS 覆盖。报告时明确哪些来自 S2，哪些是原型封装或 OwnWord 定制；调用同名组件不代表完整继承官方视觉、交互和无障碍行为。
- 判断是否符合 S2，必须给出绑定版本的依据与实际差异。不能仅凭组件名称宣称符合，也不能仅凭使用原生 HTML 元素、三角图标或自定义 CSS 宣称不符合；未核实项标为待核实。

## 与 baoyu-design 配合

继续遵循 [baoyu-design](../.agents/skills/baoyu-design/SKILL.md) 的设计系统导入、组件组合、预览和验证流程，并明确以下边界：

- 符合性以项目绑定版本的官方 S2 为准；导入 bundle 是原型实现载体。绑定文件或封装与官方实现存在差异时，记录差异及影响，不能以封装行为反过来定义 S2。修复应修改导入来源中的可维护源文件，再按技能流程编译、重新导入，不直接修改生成的 bundle 或消费副本。源文件不完整时，明确记录修复所缺的资料；完成 bundle 接入不代表已经符合 S2。
- OwnWord 基础 UI 使用绑定版本的 S2 Token，不适用技能中配色受限时用 OKLCH 自由扩色的通用建议。品牌表达按 OwnWord 的设计依据实现，不覆盖组件必要的交互状态和无障碍行为。
