## 实施

TS 采集器在原测试导入时安装，处理 Point、Curve、JacobianPoint 的循环依赖；固定上游源码及 Jest 编译配置保持原样。采集仅记录原测试直接调用的构造、静态工厂和实例入口，排除 SDK 内部运算与断言格式化调用。

Java 测试通过薄入口代理委派真实 Point、BigNumber 和 JacobianPoint 对象。每次调用检查实际参数与实际接收者，执行原 Java 运算，再由原测试判断真实返回值。输入表征保留参数类型、数组和对象内容；BigNumber 使用实际十六进制数值，Point 使用实际仿射坐标，JacobianPoint 使用真实 `toP()` 得到的仿射值。语料不包含 TS 断言输出。

原 Java 测试恢复以下源码行为：`fromX` 用例原本未使用的 `getX→toString` 调用、`toJSON` 后再序列化、加法和倍点求值顺序、标量 BigNumber 原类型、`encode()` 无参和 `encode(true, 'hex')` 参数，以及原 `toBe`、`toHaveLength`、`toThrow` 和正则 matcher。`_combineWnafPair` 接收原空 `wnd` / `naf` 数组上下文；`_collectWnafStep` 接收显式临时数组并在两个调用之后执行原断言。结构化结果由 Java 实际记录字段构成 Map，用于原深比较。生产代码、映射及通用语义规则未因本批改变。

## 重跑

标准 capture 使用 `point-additional-input-plan.json`、上述局部 catalog/mapping 和固定语料，侧执行器为 `capture-point-additional-side.py ts` 或 `capture-point-additional-side.py java clean test`。传入 `--catalog`、`--mapping`、`--report`、`--replay`，输出使用新目录，并由 `evidence-bundle.py capture` 包装。Java 在宿主环境执行，采集期间保持主仓源码稳定。

全量登记由主代理维护 `full-evidence-locals.json`。本文件局部验收不能替代最终统一来源版本的完整模块验收。
