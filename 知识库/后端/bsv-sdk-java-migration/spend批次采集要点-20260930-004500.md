## 二、标准流程（每条命令都已在本批验证过）

以下 `$L` 是局部名（`spend-locals.py` 里的 key），`$F` 是原文件相对路径，`$P` 是探针文件名，
`$OBS` 是该局部的 `ts_observations_env`，`$C` 是 Java 测试类名，`$D` 是计划目录。

```bash
cd /home/haodev/ownword/_task/backend-worktree/bsv-sdk-java-migration
D=.cache/evidence/$L-plan-20260930

# 1. 冻结前清单（探针按它过滤本局部用例）
python3 prepare-spend-local.py catalog --local $L --directory $D

# 2. 冻结前探针自采（产出 raw 轨迹；只跑 TS，不碰 Java）
./lock.sh ./bootstrap-spend-probe.sh $L "$PWD/$D" $F $P $OBS

# 3. 冻结（catalog/mapping/input-plan 三件套；样本号 = <入口>-<序号>）
python3 prepare-spend-local.py freeze --local $L \
    --raw $D/ts-calls.raw.jsonl --assertions $D/ts-assertions.raw.jsonl --directory $D

# 4. 聚焦编译/测试（先保证 Java 侧能跑；此步可选但强烈建议）
./lock.sh ./mvn.sh -f metanet4j-bsv-sdk/pom.xml clean test -Dtest=$C

# 5. 登记（full-evidence-locals.json 只允许通过本脚本改）
./lock.sh python3 register-local.py --name $L \
    --catalog $D/catalog.json --mapping $D/mapping.json \
    --input-plan $D/input-plan.json --capture capture-spend-local.py

# 6. 标准双侧重采（运行目录必须为空；输出 cases/inputsCompared/assertionsCompared）
./lock.sh python3 recapture-local.py --name $L --run .cache/evidence/$L-standard-20260930 --update

# 7. 篡改门禁（必须两个 true）
./lock.sh python3 local-evidence-gate.py tamper --name $L

# 8. 全量前置检查（该局部 planValid=true；planErrors 不得新增）
./lock.sh python3 full-evidence-preflight.py --output .cache/evidence/preflight-$L-20260930.json
```

## 三、探针写法（TS 侧）

```js
'use strict'
const path = require('node:path')
const recorder = require('./spend-probe-lib.cjs').create({
  output: process.env.MIGRATION_XXX_TS_OBSERVATIONS,   // 本局部的 observations 环境变量
  label: 'Spend xxx',
  testPath: expect.getState().testPath
})
beforeEach(() => { recorder.begin() })                 // 必须：绑定当前用例并重置序号

const modulePath = path.resolve(path.dirname(expect.getState().testPath), '../Spend.ts')
jest.doMock(modulePath, () => {
  const moduleObject = jest.requireActual(modulePath)
  return { ...moduleObject, __esModule: true, default: new Proxy(moduleObject.default, {
    construct (target, args, newTarget) {
      if (recorder.active) recorder.spend(args[0])     // 记录 Spend 构造参数
      return Reflect.construct(target, args, newTarget)
    }
  }) }
})
```

- `recorder.active` 只在“当前用例属于本局部冻结清单”时为真，因此同一原文件里属于别的 Java 类的
  用例（如 Spend.test.ts 的 455 个有效向量）会自动跳过，不会污染轨迹。
- 一个用例内可以记录多个入口：`recorder.observe(method, args, () => 原调用, 结果描述)`；
  纯构造入口用 `recorder.spend(params)`；抛错会被 `observe` 自动记成 `{kind:'throw',...}`。
- 只包原测试真正调用的公开入口，不要在探针里改行为；探针不得调用网络。
- 需要固定随机时，照 `capture-signature-inputs.cjs` 的做法 `jest.doMock` Random 模块，
  用固定 fixture 的同一批字节喂 `PrivateKey.fromRandom()`（Java 侧用同一批字节）。

## 四、Java 侧重放写法

```java
@ExtendWith(ParityRecordingExtension.class)
class XxxTest {
    private static final String CASE = "<冻结用例 id>";
    private XxxInputReplay replay;
    @BeforeEach void setUp() { replay = XxxInputReplay.forCase(CASE); }

    @Test void 原用例名() { ... replay.spend(params) ... }   // 既有断言原样保留
}
```

- `SpendObservation.forCase(<inputs_env 名>, caseId)`：环境变量缺失时返回未激活观察器，
  此时包装方法直接委托，**无输入时行为与现在完全一致**。
- 入口包装方法放在 `<类名>InputReplay.java`（包内可见），逐个转发到 `observation.observe/spend`。
- 描述投影必须与探针逐字段一致：脚本用 `SpendObservation.script(...)`、输入输出用
  `input/output(...)`、Spend 构造参数用 `spendParams(...)`、签名前置参数用 `signatureParams(...)`。
  数值两侧统一成十进制字符串（`jsNumber`），不要自己写 `Map.of("x", 1.0)`。
- 不得删除、放宽或改写既有断言；只把“构造/入口调用”换成 replay 包装。

## 五、已知坑

1. **探针过滤身份**：`recorder.begin()` 必须放在 `beforeEach`；探针不记录就等于没有样本，
   `freeze` 会报“固定 TS 原用例未全部触达公开入口”。
2. **`jest.doMock` 路径**：从 `expect.getState().testPath` 推导，`src/script/__tests/*` 用
   `../Spend.ts`；Transaction／TransactionSignature 等按原测试 import 的相对路径推导。
3. **至少一个样本/用例**：只 new 不调方法的用例用 Spend 构造入口；不构造 Spend 的用例
   （例如走 `Transaction.verify`、`Transaction.fromBinary/fromEF` 的用例）必须记录它真正调用的入口。
4. **数值类型**：两侧一律走 `jsNumber` 字符串化，禁止直接塞 JSON 数字（Integer/Long/Double 不相等）。
5. **`isRelaxed`**：TS 侧未传时投影为 `false`（Java 是原始 boolean，无法区分 undefined）。
6. **JSON 文件较大**：向量类局部样本可能上千条（normative-vectors），属正常；冻结与重采都按行处理。
7. **运行目录一次性**：`recapture-local.py --run` 目录必须为空，失败后换新目录名重试。
8. **并行纪律**：任何 Maven／采集走 `./lock.sh`；编译错误出现在别人文件（如 `BeefInputReplay.java`、
   `WalletClient*InputReplay.java`）就等 2 分钟重试，不要动别人的文件；不 `git commit`／`git push`；
   不改 `feature_list.json`／`progress.md`／`session-handoff.md`；不改生产源码，发现缺陷先报告。
9. **同用例冲突**：只做分配给你的文件/类；`full-evidence-preflight.py` 的 `planErrors` 必须保持为空
   （出现“同用例计划冲突”说明抢了别人的用例，立刻停止并报告）。
10. **随机熵用例**：原测试直接 `PrivateKey.fromRandom()` 时，TS 自采与标准采集必须是同一熵口径
   （`spend-seeded-entropy.cjs` 已在两条路径加载）；否则冻结样本与重采样本不同值，Java 侧无论怎么写
   都不可能同时通过自采与重采。当前 spend 批只有 `Spend.additional.test.ts` 受影响；`Spend.test.ts`
   等其余文件的自采轨迹与种子无关（已实测：加载种子前后逐行一致）。
