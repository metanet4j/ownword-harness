# 交易向量同输入采集

固定 TS 提交 `f999e0c1aad9a7afd0cbadaaf23841d049af9d5a` 的 `Transaction.test.ts` 全文件 Jest 为 720／720。本文只核对其中映射到 `TransactionCompleteVectorsTest` 的 659 个向量注册：500 个 sighash、93 个有效序列化、65 个无效序列化及 1 个大交易 txid。其余原用例仍由原测试文件执行，但不计入此局部输入计划。

## 发现与修复

第一轮从原 TS `Transaction.fromBinary`／`fromHex`、`TransactionSignature.format` 的实际调用捕获 1159 次输入；隔离 Java 同数采集也有 1159 次，原断言 1159／1159 相同。逐输入比较发现 249 个 sighash 向量的 `transactionVersion` 不同：TS 保留 32 位无符号数，例如 `2671911709`，Java 测试此前将 `tx.version` 强转 `int`，得到 `-1623055587`。两者写出的 4 字节相同，但传入 API 的数值不同。

Java 提交 `5bff6f1` 将 `TransactionSignature.Params.transactionVersion` 改为 `long`，向量测试直接传 `tx.version`，并在实际 SDK 调用前记录输入。该改动已合入主分支 `3d8af27`；`api-map.json` 对应字段签名同步为 `public long transactionVersion;`。隔离聚焦 `clean test` 的 659／659 向量通过，失败／错误／跳过均为 0；无过滤累计回归将在后续主分支整合后重跑。

## 提交版证据

`transaction-vector-evidence.py` 从冻结 `module-tests.json`／`test-map.json` 派生 659 例局部计划，固定 1159 个输入实例和 1159 个原断言实例。TS 运行原文件，Java 运行对应 JUnit 类；两端分别记录实际消费值、原断言、Jest／Surefire、命令、源码版本的前后摘要、运行身份及产物 SHA-256。原始资料和计划位于 `.cache/evidence/transaction-vector-final-20260927/`。

提交版局部比较 `parity.json` 为 `localParityPassed=true`、`formalAcceptance=false`：659／659 用例、1159／1159 次输入、1159／1159 条原断言逐项相同。TS 与 Java 使用不同 runId；Java 证据绑定隔离提交 `5bff6f1` 的源码摘要 `e00e32fd6adf9bf144f8683bea3d1108e74120cabc00b704bb811baaa1afd3cd`。输入和断言各制作一份篡改副本，连同 manifest 中的产物摘要一起重算，两次比较仍分别因实际值不同而拒绝；见 `tamper-results.json`。

可在任务目录复跑同一流程；集成测试须在宿主环境执行：

```bash
python3 transaction-vector-evidence.py prepare --plan .cache/evidence/transaction-vector-new/plan
python3 transaction-vector-evidence.py ts --plan .cache/evidence/transaction-vector-new/plan --output .cache/evidence/transaction-vector-new/ts --java-worktree /tmp/bsv-transaction-vector-input-20260927
python3 transaction-vector-evidence.py java --plan .cache/evidence/transaction-vector-new/plan --output .cache/evidence/transaction-vector-new/java --java-worktree /tmp/bsv-transaction-vector-input-20260927
python3 transaction-vector-evidence.py compare --plan .cache/evidence/transaction-vector-new/plan --ts .cache/evidence/transaction-vector-new/ts --java .cache/evidence/transaction-vector-new/java --java-worktree /tmp/bsv-transaction-vector-input-20260927 --output .cache/evidence/transaction-vector-new/parity.json
```

此证据只覆盖原文件中的 659 个向量用例，且 Java 来自独立工作树。完整 P0 仍须在最终 Java 版本上执行无过滤双侧采集与 `audit-tests.py check`；局部报告不能拼接成正式全量验收。
